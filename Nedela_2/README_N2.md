# AI Advent AI_9 — Инструментарий LLM: Агенты и их внутреннее устройство

Учебный репозиторий с практическими заданиями курса AI Advent.
Неделя 2 (для ознакомления с предыдущей частью проекта смотри [Nedela_1/README_N1.md](../Nedela_1/README_N1.md))

Неделя N2 знакомит с внутренним устройством LLM-агентов: четырьмя ключевыми компонентами (Context Management, Memory Management, Planning, Tool Orchestration), техниками управления контекстом и памятью, стратегиями планирования и оркестровки инструментов. Практическая цель — построить простой флоу работы агента со всеми описанными механизмами.

## Подготовка проекта

### 1. Клонирование

```bash

```

### 2. Виртуальное окружение

Создайте виртуальное окружение:

```bash

```

Активируйте его.

Linux:

```bash
source .venv/bin/activate
```

Windows:

```bash
.venv\Scripts\activate
```

### 3. Зависимости

```bash
pip install python-dotenv requests
```

### 4. API-ключ

Получите ключ в [RouterAI](https://routerai.ru).

Создайте в корне проекта файл `.env` на основе `.env.example`:

```env
API_KEY=ваш_ключ_от_routerai
```

Файл `.env` уже добавлен в `.gitignore`. Не публикуйте его и не передавайте другим людям.

## Что изучено

### День 6

- четыре компонента внутреннего устройства агентов: Context Management, Memory Management, Planning, Tool Orchestration;
- техники управления контекстом: History Compression, Sliding Window, Vector Embeddings, Context-Leveling, Topic Branches;
- типы памяти агентов: Session Memory, Compressed Memory, Vector Base Memory, Layered Memory, Rule-Based Memory, Self-Reflective Memory;
- эволюция ассистентов: Basic → Smart → Modern;
- этапы планирования при создании агента;
- этапы работы с инструментами: Tool Selection → Invocation → Results → Interpretation → Error Handling → State Update;
- уровни промптов: Simple, Pro, Prompt Pro Max;
- протоколы обмена: JSON и TUN (экономия 30–60% токенов);
- лайфхаки работы с агентами: сужение контекста, индексация проекта, stage-based execution, избегание суммаризации.

### День 7

- JSON-персистентность: полный снимок состояния (история, архив, саммари, режимы, счётчики) в машиночитаемом формате;
- автоматическое сохранение при выходе (включая Ctrl+C/Ctrl+D) и загрузка при старте;
- ручное управление: `/save`, `/load`; отсутствующий или повреждённый файл не роняет программу;
- почему JSON, а не Markdown: машиночитаемость без потерь против человекочитаемости (оба файла ведутся параллельно).

### День 8

- модель stateless: весь диалог отправляется заново каждым запросом — контекст платный каждый обмен;
- три счётчика токенов: текущий запрос / ответ модели / вся история (по `usage` API);
- локальная оценка токенов (эвристика + опциональный tiktoken) до отправки запроса;
- стоимость в рублях с раздельным тарифом (входящие/исходящие), прогноз расходов;
- CSV-журнал обменов; контроль лимита контекста до отправки (`--max-context-tokens`);
- служебные запросы (автосжатие) тоже стоят денег — честный учёт.

### День 9

- сжатие истории ломает рост запроса 1+2+…+N: саммари + окно вместо полной истории;
- автосжатие по порогу (`--compress-every`), ручное сжатие и переключение на лету (`/compress on|off`);
- `/compare`: качество и расход токенов/₽ до и после сжатия на одном контрольном вопросе;
- экономия токенов ≠ экономия рублей: суммаризация — платный запрос и сбрасывает prompt-cache.

### День 10

- набор стратегий управления контекстом + переключатель `--context` (всего 5 режимов);
- Sticky Facts: блок фактов «ключ: значение», автообновление после каждого сообщения служебным запросом, «сырое» окно без искажений;
- Branching: ветки диалога с checkpoint, хранение в `Branches/` (файл на ветку), переключение `/branch switch`, активная ветка видна в терминале;
- `/compare-strategies`: один сценарий («собираем ТЗ») на всех стратегиях, сравнение по 4 критериям — качество, стабильность, расход токенов, удобство;
- вывод: единственно верной стратегии нет — выбор зависит от задачи (длина диалога, важность ранних деталей, готовность платить за служебные запросы).

## Теоретическая база недели N2

### 1. Context Management (Управление контекстом)

- отсутствие памяти между сессиями;
- калибровка весов внутри сессии;
- TopP и TopC параметры;
- современные модели: ~1 млн токенов контекстного окна.

### 2. Memory Management (Управление памятью)

- от кратковременной сессионной памяти до иерархической self-reflective;
- векторные базы данных для масштабируемого хранения;
- правила нечёткой логики для детерминированного поведения.

### 3. Planning (Планирование)

- определение цели → декомпозиция на таски → выбор стратегии → перепланирование → подтверждение → реализация.

### 4. Tool Orchestration (Оркестровка инструментов)

- выбор, вызов, получение результатов, интерпретация, обработка ошибок, обновление состояния.

## Ограничения API

Доступное количество запросов и токенов зависит от тарифного плана. При превышении лимита токенов в минуту (HTTP 429) программы автоматически повторяют запрос после паузы (2 → 4 → 8 секунд, до 3 попыток). Ошибки API не прерывают цикл чата; непредвиденные ошибки пишутся в `den_*_error.log`.
