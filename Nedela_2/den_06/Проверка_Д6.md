# Сценарий ручной проверки — День 6 «Простой агент LLM: Context & Memory Management»

> Чек-лист для живой проверки проекта `Nedela_2/den_06` руками, без автотестов.
> Время прохождения: ~25–30 минут. Живые запросы к API — платные (≈1–2 ₽ на весь сценарий).
> Отметки: ☐ — не выполнено, ✅ — прошло, ❌ — не прошло (записать, что именно).

## Подготовка (3 минуты)

☐ **П.1** Открыть терминал в каталоге `Nedela_2/den_06`.

☐ **П.2** Убедиться, что ключ API на месте:
```bash
grep -q "API_KEY" ../../.env && echo "ключ есть" || echo "ключа НЕТ"
```
Ожидание: «ключ есть».

☐ **П.3** Убедиться, что в папке есть все варианты кода:
```bash
ls den_6_Kod*.py
```
Ожидание: 4 файла — `den_6_Kod.py` (3-in-1) и три отдельных варианта
(A_Sliding-Window, B_History-Compression, C_Context-Leveling).

## Часть 1. Вариант A — Sliding Window + Session Memory (5 минут)

☐ **1.1** Запустить объединённую версию:
```bash
./den_6_run.sh --context sliding-window --memory session --window 4
```

☐ **1.2** Проверить шапку: `контекст=sliding-window, память=session, окно=4`.

☐ **1.3** Отправить 6 сообщений по очереди (живой API):
```
Меня зовут Алексей
Мой любимый цвет — синий
Я живу в Казани
У меня два кота
Работаю программистом
Люблю кофе
```
Ожидание: после 5-го–6-го сообщения — `[Контекст] Сообщение вышло из окна…`
(старые реплики вытесняются, но НЕ теряются — остаются в логе).

☐ **1.4** Ввести `/history`.
Ожидание: все 6 сообщений; ранние помечены `[вытеснено]`, последние 4 — `[в окне]`.

☐ **1.5** Ввести `/window`.
Ожидание: состояние окна — 4 последних сообщения.

☐ **1.6** Спросить: `Как меня зовут?`
Ожидание: модель НЕ знает (имя вытеснено из окна) — демонстрация механики.

☐ **1.7** Ввести `/save`, затем `/exit`. Проверить, что лог `Den_6_log.md` создан и
содержит все обмены.

☐ **1.8** Запустить снова (1.1), ввести `/load_history`, затем `/history`.
Ожидание: история поднята из лога вручную (session-память не грузит лог сама).
Ввести `/clear`, затем `/exit`.

---

## Часть 2. Вариант B — History Compression + Compressed Memory (5 минут)

☐ **2.1** Запустить:
```bash
./den_6_run.sh --context compression --memory compressed --keep 2
```

☐ **2.2** Отправить 6 сообщений из Части 1.
Ожидание: после накопления сообщений вне окна — `[Сжатие] N сообщений свёрнуты в
саммари…`; старое НЕ выбрасывается, а консолидируется в саммари.

☐ **2.3** Ввести `/summary`.
Ожидание: текст саммари с ранними фактами (имя, цвет, город).

☐ **2.4** Ввести `/history`.
Ожидание: пометки трёх видов — `[в окне]`, `[вне окна]`, `[в саммари]`.

☐ **2.5** Спросить: `Как меня зовут и какой у меня любимый цвет?`
Ожидание: модель ЗНАЕТ — ранние факты живут в саммари (отличие от Части 1).

☐ **2.6** Ввести `/exit`, запустить снова (2.1).
Ожидание: `[Память] … саммари загружено` — сжатое знание пережило перезапуск
(Compressed Memory). Спросить `Как меня зовут?` — модель помнит. `/exit`.

## Часть 3. Вариант C — Context-Leveling + Layered Memory (5 минут)

☐ **3.1** Запустить:
```bash
./den_6_run.sh --context leveling --memory layered --keep 2
```

☐ **3.2** Отправить сообщения с маркерами приоритета:
```
Запомни: меня зовут Алексей
Я люблю кофе
Важно: дедлайн проекта — 1 октября
```
Ожидание: сообщение с «запомни»/«важно» получает слой `high` (автоопределение).

☐ **3.3** Ввести `/layers`.
Ожидание: статистика по слоям (high/mid/low).

☐ **3.4** Ввести `/history`.
Ожидание: у каждого сообщения пометка слоя.

☐ **3.5** Сменить приоритет вручную: `/layer 2 high`, затем `/layers`.
Ожидание: сообщение №2 теперь `high`.

☐ **3.6** Ввести `/exit`, запустить снова с `--load high`:
```bash
./den_6_run.sh --context leveling --memory layered --keep 2 --load high
```
Ожидание: из лога подняты только high-сообщения (имя и дедлайн — да, кофе — нет).
Ввести `/clear`, `/exit`.
