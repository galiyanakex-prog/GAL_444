ПРОМТ: День 6, Вариант B — History Compression + Compressed Memory (класс Agent)

  Роль

  Ты — опытный Python-разработчик и преподаватель. Пишешь учебный код для студента, который уже прошёл День 1 (чат-бот на RouterAI) и День 6
  вариант A (Sliding Window), и понимает: формат сообщений system/user/assistant, retry при 429, сохранение истории в файл.

  Задача

  Напиши один файл den_06/den_6_Kod_B_History-Compression.py — CLI-чат-бот с LLM, который демонстрирует технику History Compression (сжатие
  истории в саммари) и тип памяти Compressed Memory. Логика агента должна быть инкапсулирована в класс Agent — прямое требование задания Дня 6:
  «Агент должен быть отдельной сущностью (класс), а не просто один вызов API».

  Контекст проекта

   - API: RouterAI, OpenAI-compatible, endpoint https://routerai.ru/api/v1/chat/completions, модель stepfun/step-3.5-flash.
   - Ключ читается из .env (переменная API_KEY) через python-dotenv. Нет ключа — понятная ошибка и остановка.
   - Стиль кода — как в den_01/Den_1_Kod.py: комментарий почти к каждой строке на русском, простые конструкции, всё в одном файле.
   - Зависимости: только requests и python-dotenv.
   - Разделение ответственности: история, саммари, сжатие и запросы к API — внутри класса Agent; CLI-цикл (ввод, команды, вывод) — снаружи и
     работает с агентом только через его методы.

  Ключевая идея (объясни её в шапке файла комментарием)

  Вместо того чтобы выбрасывать старые сообщения (как в Sliding Window), мы сжимаем их в саммари отдельным вызовом LLM. Саммари всегда едет в
  запросе первым сообщением после system. Так контекст остаётся коротким, но агент «помнит» суть всего диалога. Цена — потеря деталей и лишние
  токены на сжатие.

  Класс Agent (обязателен, интерфейс из задания Дня 6)

  1 class Agent:
  2     def __init__(self, system_prompt: str, keep: int = 6):
  3         """system_prompt — роль агента; keep — размер окна последних сообщений."""

 13         или None, если сжимать нечего/не удалось."""

  - Запрос к API с retry при 429 — внутренний метод агента (_ask_llm); снаружи не вызывается.
  - Саммари хранится внутри агента; для команд /summary и /history добавь методы get_summary() и get_history().
  - Загрузка саммари при старте — метод агента (например, load_summary(filepath)).

  Функциональные требования

  1. History Compression (главная техника)

   - Полная история диалога хранится внутри агента в списке full_history (без system).
   - В запросе к API агент отправляет: [system] + [саммари, если есть] + [последние K сообщений].
   - K по умолчанию 6, задаётся флагом --keep 6 (модуль argparse) и передаётся в Agent(keep=...).
   - Триггер сжатия: когда вне окна накапливается ≥ 8 сообщений (константа COMPRESS_THRESHOLD = 8), агент сжимает историю:
     1. Берутся все сообщения вне окна (старые).
    2. Формируется отдельный запрос к LLM с промптом-сжатием:

   1 compress_messages = [
   2    {"role": "system", "content": "Ты сжимаешь диалоги. Сделай краткое саммари ключевых фактов, решений и договорённостей. Только
     саммари, без приветствий и комментариев."},
   3     {"role": "user", "content": f"Предыдущее саммари:\n{old_summary или '(нет)'}\n\nСообщения диалога:\n{transcript}\n\nОбъедини всё в
     единое обновлённое саммари."},
   4 ]

    3. Ответ сохраняется как новое summary (старое саммари консолидируется — включается в промпт, а не теряется).
     4. Сжатые сообщения удаляются из full_history (они теперь внутри саммари).
   - После сжатия выведи уведомление:

   1 [Сжатие] 8 сообщений свёрнуты в саммари (длина саммари: 214 символов)

   - Сжатие выполняется сразу после ответа агента, до следующего ввода пользователя (пользователь видит уведомление до того, как продолжит
     диалог).
   - Если запрос на сжатие упал с ошибкой — не теряй сообщения: покажи [Сжатие] Не удалось, сообщения сохранены, попробуем в следующий раз и
     оставь всё как было.

  2. Compressed Memory с сохранением

   - Саммари сохраняется в файл Den_6_summary_B_History-Compression.md (перезапись целиком при каждом обновлении, UTF-8):

   1 # Саммари диалога — History Compression
   2 Обновлено: 2026-09-09 14:35:12
   3
   4 <текст саммари>
   5 ```

   - Полный лог переписки — в Den_6_log_B_History-Compression.md, формат как в варианте A (дозапись после каждого обмена, дата, роль,
     текст). Дополнительно фиксируй события сжатия:
  > 🔧 [14:35:12] Сжатие: 8 сообщений → саммари (214 символов)

   - При старте: если файл саммари существует, **загрузи его** в агента (load_summary) и сообщи [Память] Загружено саммари прошлой сессии
     (N символов) — это и есть Compressed Memory: сжатое знание переживает перезапуск, полная переписка — нет.

  3. CLI-команды

  | Команда | Действие |
  |---|---|
  | /summary | Показать текущее саммари (через get_summary(); или «Саммари пока пусто») |
  | /history | Показать полную историю с пометками: [в окне], [в саммари] |
  | /compress | Принудительно вызвать agent.compress() (даже если порог не достигнут) |
  | /clear | agent.clear_context() — сбросить саммари и окно (лог-файл сохраняется) |
  | /exit | Сохранить саммари и лог, выйти |

  4. Обработка ошибок API

   - Retry при HTTP 429: до 3 попыток, задержка 2 → 4 → 8 сек, с сообщением [API] Лимит запросов, повтор через N сек....
   - Таймаут 30 сек; прочие HTTP-ошибки и отсутствие choices — понятное сообщение, цикл продолжается.
   - Ошибки запроса сжатия обрабатываются **отдельно** от ошибок основного диалога (см. п. 1).

  ## Структура кода (обязательна)

  1. Импорты: os, sys, argparse, datetime, requests, dotenv
  2. load_dotenv() + проверка API_KEY
  3. Парсинг --keep через argparse
  4. Константы: URL, MODEL, LOG_FILE, SUMMARY_FILE, COMPRESS_THRESHOLD, KEEP
  5. class Agent:
     - __init__(system_prompt, keep) — system prompt, окно, полная история, пустое саммари
     - _ask_llm(messages) -> str — запрос с retry при 429 (внутренний метод)
     - _build_messages() -> list — [system] + [саммари] + окно
     - send_message(user_message) -> str — запрос → ответ → история → проверка порога сжатия
     - compress() — сжатие внеоконных сообщений в саммари (консолидация)
     - load_summary(filepath) / save_summary(filepath)
     - save_history(filepath) / load_history(filepath)
     - clear_context()
     - get_context_summary() / get_summary() / get_history()
  6. Функции append_log(role, text) и log_compression(n, length) — CLI-уровень
  7. Главный цикл: создать Agent → загрузить саммари → ввод → команды (через методы агента) → agent.send_message → ответ → лог

  System prompt: "Ты полезный ассистент. Отвечай кратко на русском языке."

  ## Критерии приёмки

  1. После 14 обменов (6 в окне + 8 вне) сжатие срабатывает автоматически, уведомление видно, /history помечает старые сообщения [в саммари].
  2. После сжатия агент **помнит факты из свёрнутых сообщений** (проверка: сказать имя до сжатия, спросить после — агент отвечает верно).
  3. Перезапуск программы: саммари загружается из файла, агент помнит контекст прошлой сессии.
  4. /compress работает принудительно; ошибка сжатия не теряет сообщения.
  5. Логика агента инкапсулирована в класс Agent: CLI-цикл не лезет к истории, саммари и API напрямую, только через методы.
  6. Лог содержит события сжатия; каждая значимая строка кода прокомментирована на русском.

  ## Чего делать НЕ нужно

  - Не используй наследование, ABC, logging — один простой класс Agent с явными методами; типизация в сигнатурах методов допустима (как в
    задании).
  - Не выноси логику сжатия/саммари в функции вне класса — всё состояние агента живёт в его атрибутах и методах.
  - Не реализуй sliding window с удалением без сжатия (это вариант A) — здесь старое всегда сворачивается в саммари.
  - Не подключай векторные БД и слои контекста (вариант C и следующие дни).
  - Не отправляй саммари как сообщение user — только как system-сообщение после основного system prompt.
  - Не храни ключ API в коде.
