ПРОМТ: День 6, Вариант C — Context-Leveling + Layered Memory

  Роль

  Ты — опытный Python-разработчик и преподаватель. Пишешь учебный код для студента, который уже прошёл День 1 (чат-бот на RouterAI), День 6
  вариант A (Sliding Window) и вариант B (History Compression), и понимает: формат сообщений system/user/assistant, retry при 429, сохранение
  истории и саммари в файлы.

  Задача

  Напиши один файл den_06/Den_6_Kod_C_Context-Leveling.py — CLI-чат-бот с LM, который демонстрирует технику Context-Leveling (разделение
  контекста на слои) и тип памяти Layered Memory (сообщения раскладываются по слоям приоритета).

  Контекст проекта

   - API: RouterAI, OpenAI-compatible, endpoint https://routerai.ru/api/v1/chat/completions, модель stepfun/step-3.5-flash.
   - Ключ читается из .env (переменная API_KEY) через python-dotenv. Нет ключа — понятная ошибка и остановка.
   - Стиль кода — как в den_01/Den_1_Kod.py: комментарий почти каждой строке на русском, простые конструкции, всё в одном файле.
   - Зависимости: только requests и python-dotenv.

  Ключевая идея (объясни её в шапке файла комментарием)

  Не весь контекст одинаково важен. Мы делим его на слои:

   - Стратегический слой — system prompt + общие инструкции. Не меняется, едет в каждом запросе первым.
   - Оперативный слой — текущий диалог. Растёт, старое сжимается в самари (как в варианте B).

  А память (сохраняемые сообщения) дополнительно раскладывается по приоритетам: ключевые факты и решения — высокий слой, текущие задачи —
  средний, обычная переписка — низкий. При формировании запроса слои собираются в порядке важности, а при загрузке памяти можно выбрать, какие
  слои подгружать.

  Функциональные требования

  1. Context-Leveling: два слоя контекста (главная техника)

   - Стратегический слой (не меняется в ходе сессии):
    - system prompt: "Ты полезный ассистент. Отвечай кратко на русском языке.";
     - блок общих инструкций, добавляемый вторым system-сообщением: "Правила работы: сохраняй ключевые факты о пользователе. Если пользователь
       просит что-то запомнить — подтверди это.".
   - Оперативный слой:
     - самари старых сообщений (если есть) — третьим system-собщением: "Саммари более раннего диалога:\n<текст>";
     - последние K сообщений диалога.
   - K по умолчанию 6, флаг --keep 6 (argparse).
   - Порог сжатия оперативного слоя: ≥ 8 сообщений вне окна (константа COMPRESS_THRESHOLD = 8) — сжатие в саммари через отдельный вызов LLM, как в
      варианте B (консолидация со старым самари, уведомление [Сжатие] ...).
   - Итоговый запрос всегда собирается функцией build_messages() в строгом порядке: стратегия → инструкции → самари → окно. Никогда не отправляй
     сообщения в другом порядке.

  2. Layered Memory: приоритеты сообщений (главная техника)

  Каждое сообщение пользователя при добавлении получает приоритет слоя. Определяется автоматически по ключевым словам + вручную командой:


  ┌─────────────┬──────────────────────────────────────────────────────────────────────────────────────────────┬─────────────────────────┐
  │ Слой        │ Как определяется                                                                             │ Примеры                 │
  ├─────────────┼──────────────────────────────────────────────────────────────────────────────────────────────┼─────────────────────────┤
  │ Высокий ... │ Содержит маркеры: «запомни», «важно», «меня зовут», «мой», «всегда», «никогда» — или поль... │ «Запомни: меня зовут... │
  │ Средний ... │ Содержит маркеры задач: «нужно», «сделать», «план», «давай», «задача»                        │ «Нужно дописать README» │
  │ Низкий (... │ Всё остальное                                                                                │ «Привет», «Как дела?»   │
  └─────────────┴──────────────────────────────────────────────────────────────────────────────────────────────┴─────────────────────────┘


   - Ответы агента наследуют приоритет сообщения, на которое они отвечают.
   - Полная история хранится как список словарей: {"role", "content", "layer", "timestamp"}.

  3. Сохранение и загрузка (Layered Memory с файлами)

   - История сохраняется в Den_6_log_C_Context-Leveling.md — дозапись после каждого обмена, с пометкой слоя:

   1 ## 2026-09-09 14:40:01
   2 **Вы** [high]: Запомни: меня зовут Алексей
   3 **Агент** [high]: Хорошо, Алексей, запомнил!

   - Отдельный файл самари Den_6_summary_C_Context-Leveling.md — как в варианте B (перезапись, загрузка при старте).
   - Загрузка слоёв при старте (это ключевое отличие от вариантов A/B): флаг --load выбирает, какие слои подгружать из лога в оперативный слой:

    1 python Den_6_Kod_C_Context-Leveling.py --load high       # только ключевые факты
    2 python Den_6_Kod_C_Context-Leveling.py --load high,mid    # факты + задачи
    3 python Den_6_Kod_Context-Leveling.py --load all         # всё (по умолчанию)
    4 python Den_6_Kod_C_Context-Leveling.py --load none        # чистая сессия
    5 ``
    6
    7 - При загрузке выведи статистику: `[Память] Загружено: high=3, mid=2, low=0 (слой low пропущен)`.

    9 ### 4. CLI-команды
   10
   11 | Команда | Действие |
   12 |---|
   13 | `/layers` | Статистика по слоям: сколько сообщений в каждом, какие в окне |
   14 | `/history` | Полная история с пометками слоя: `[high]`, `[mid]`, `[low]`, `[в окне]`, `[в саммари]` |
   15 | `/layer <номер> <high|mid|low>` | Сменить приоритет последнего сообщения пользователя (например `/layer 1 high`) |
   16 | `/summary` | Показать текущее самари |
   17 | `/compress` | Принудительное сжатие оперативного слоя |
   18 | `/clear` | Сбросить саммари и окно (лог сохраняется) |
   19 | `/exit` | Сохранить лог и саммари, выйти |
   20
   21 ### 5. Обработка ошибок API
   22
   23 - Retry при HTTP 429: до 3 попыток, задержка 2 → 4 → 8 сек, сообщение `[API] Лимит запросов, повтор через N сек...`.
   24 - Таймаут 30 сек; прочие HTTP-ошибки и отсутствие `choices` — понятное сообщение, цикл продолжается.
   25 - Ошибка сжатия не теряет сообщения (как в варианте B).

   27 ## Структура кода (обязательна)
  1. Импорты: os, sys, argparse, datetime, requests, dotenv
  2. load_dotenv() + проверка API_KEY
  3. Парсинг флагов: --keep, --load
  4. Константы: URL, MODEL, LOG_FILE, SUMMARY_FILE, COMPRESS_THRESHOLD, KEEP
  5. Словари LAYER_MARKERS (маркеры слоёв) и LAYER_LABELS (подписи для вывода)
  6. Функция detect_layer(text) -> str — автопределение слоя по маркерам
  7. Функция ask_llm(messages) -> str — запрос с retry при 429
  8. Функция compress_history(old_messages, summary) -> str — самари через LLM
  9. Функция build_messages(history, summary) -> list — слои в строгом порядке:
  [стратегия] + [инструкции] + [саммари] + [окно]
  10. Функции append_log(msg), load_summary(), save_summary(), load_layers(path, layers)
  11. Главный цикл: ввод → команды → определение слоя → запрос → ответ → лог → порог сжатия

    2 ## Критерии приёмки
    3
    4 1. «Запомни: ...» автоматически получает слой `high` (видно в `/layers` и `/history`).

    8 5. Порядок сообщений в запросе строго: стратегия → инструкции → саммари → окно (проверяется чтением кода `build_messages`).
