ПРОМТ: День 6, Вариант C — Context-Leveling + Layered Memory (класс Agent)

  Роль

  Ты — опытный Python-разработчик и преподаватель. Пишешь учебный код для студента, который уже прошёл День 1 (чат-бот на RouterAI), День 6
  вариант A (Sliding Window) и вариант B (History Compression), и понимает: формат сообщений system/user/assistant, retry при 429, сохранение
  истории и саммари в файлы.

  Задача

  Напиши один файл den_06/den_6_Kod_C_Context-Leveling.py — CLI-чат-бот с LLM, который демонстрирует технику Context-Leveling (разделение
  контекста на слои) и тип памяти Layered Memory (сообщения раскладываются по слоям приоритета). Логика агента должна быть инкапсулирована в
  класс Agent — прямое требование задания Дня 6: «Агент должен быть отдельной сущностью (класс), а не просто один вызов API».

  Контекст проекта

   - API: RouterAI, OpenAI-compatible, endpoint https://routerai.ru/api/v1/chat/completions, модель stepfun/step-3.5-flash.
   - Ключ читается из .env (переменная API_KEY) через python-dotenv. Нет ключа — понятная ошибка и остановка.
   - Стиль кода — как в den_01/Den_1_Kod.py: комментарий почти к каждой строке на русском, простые конструкции, всё в одном файле.
   - Зависимости: только requests и python-dotenv.
   - Разделение ответственности: слои, саммари, сжатие и запросы к API — внутри класса Agent; CLI-цикл (ввод, команды, вывод) — снаружи и
     работает с агентом только через его методы.

  Ключевая идея (объясни её в шапке файла комментарием)

  Не весь контекст одинаково важен. Мы делим его на слои:

   - Стратегический слой — system prompt + общие инструкции. Не меняется, едет в каждом запросе первым.
   - Оперативный слой — текущий диалог. Растёт, старое сжимается в саммари (как в варианте B).

  А память (сохраняемые сообщения) дополнительно раскладывается по приоритетам: ключевые факты и решения — высокий слой, текущие задачи —
  средний, обычная переписка — низкий. При формировании запроса слои собираются в порядке важности, а при загрузке памяти можно выбрать, какие
  слои подгружать.

  Функциональные требования

  1. Context-Leveling: два слоя контекста (главная техника)

   - Стратегический слой (не меняется в ходе сессии, хранится в агенте):
    - system prompt: "Ты полезный ассистент. Отвечай кратко на русском языке.";
     - блок общих инструкций, добавляемый вторым system-сообщением: "Правила работы: сохраняй ключевые факты о пользователе. Если пользователь
       просит что-то запомнить — подтверди это.".
   - Оперативный слой:
     - саммари старых сообщений (если есть) — третьим system-сообщением: "Саммари более раннего диалога:\n<текст>";
     - последние K сообщений диалога.
   - K по умолчанию 6, флаг --keep 6 (argparse).
   - Порог сжатия оперативного слоя: ≥ 8 сообщений вне окна (константа COMPRESS_THRESHOLD = 8) — сжатие в саммари через отдельный вызов LLM, как в
      варианте B (консолидация со старым саммари, уведомление [Сжатие] ...).
   - Итоговый запрос всегда собирается методом агента _build_messages() в строгом порядке: стратегия → инструкции → саммари → окно. Никогда не
     отправляй сообщения в другом порядке.

  2. Layered Memory: приоритеты сообщений (главная техника)

  Каждое сообщение пользователя при добавлении получает приоритет слоя. Определяется автоматически по ключевым словам + вручную командой:

  | Слой | Как определяется | Примеры |
  |---|---|---|
  | Высокий (high) | Содержит маркеры: «запомни», «важно», «меня зовут», «мой», «всегда», «никогда» | «Запомни: меня зовут Алексей» |
  | Средний (mid) | Содержит маркеры задач: «нужно», «сделать», «план», «давай», «задача» | «Нужно дописать README» |
  | Низкий (low) | Всё остальное | «Привет», «Как дела?» |

   - Ответы агента наследуют приоритет сообщения, на которое они отвечают.
   - Полная история хранится внутри агента как список словарей: {"role", "content", "layer", "timestamp"}.

  3. Сохранение и загрузка (Layered Memory с файлами)

   - История сохраняется в Den_6_log_C_Context-Leveling.md — дозапись после каждого обмена, с пометкой слоя:

   1 ## 2026-09-09 14:40:01
   2 **Вы** [high]: Запомни: меня зовут Алексей
   3 **Агент** [high]: Хорошо, Алексей, запомнил!

   - Отдельный файл саммари Den_6_summary_C_Context-Leveling.md — как в варианте B (перезапись, загрузка при старте).
   - Загрузка слоёв при старте (это ключевое отличие от вариантов A/B): флаг --load выбирает, какие слои подгружать из лога в оперативный слой
     (метод load_history(filepath, layers)):

    1 python den_6_Kod_C_Context-Leveling.py --load high       # только ключевые факты
    2 python den_6_Kod_C_Context-Leveling.py --load high,mid    # факты + задачи
    3 python den_6_Kod_C_Context-Leveling.py --load all         # всё (по умолчанию)
    4 python den_6_Kod_C_Context-Leveling.py --load none        # чистая сессия
    5 ```

   - При загрузке выведи статистику: [Память] Загружено: high=3, mid=2, low=0 (слой low пропущен).

  4. CLI-команды

  | Команда | Действие |
  |---|---|
  | /layers | Статистика по слоям (через get_layers_stats()): сколько сообщений в каждом, какие в окне |
  | /history | Полная история с пометками слоя: [high], [mid], [low], [в окне], [в саммари] |
  | /layer <номер> <high\|mid\|low> | agent.set_layer(...) — сменить приоритет сообщения |
  | /summary | Показать текущее саммари (get_summary()) |
  | /compress | Принудительное сжатие оперативного слоя (agent.compress()) |
  | /clear | agent.clear_context() — сбросить саммари и окно (лог сохраняется) |
  | /exit | Сохранить лог и саммари, выйти |

  5. Обработка ошибок API

   - Retry при HTTP 429: до 3 попыток, задержка 2 → 4 → 8 сек, сообщение [API] Лимит запросов, повтор через N сек....
   - Таймаут 30 сек; прочие HTTP-ошибки и отсутствие choices — понятное сообщение, цикл продолжается.
   - Ошибка сжатия не теряет сообщения (как в варианте B).

  ## Структура кода (обязательна)

  1. Импорты: os, sys, argparse, datetime, requests, dotenv
  2. load_dotenv() + проверка API_KEY
  3. Парсинг флагов: --keep, --load
  4. Константы: URL, MODEL, LOG_FILE, SUMMARY_FILE, COMPRESS_THRESHOLD, KEEP
  5. Словари LAYER_MARKERS (маркеры слоёв) и LAYER_LABELS (подписи для вывода)
  6. Функция detect_layer(text) -> str — автоопределение слоя по маркерам
  7. class Agent:
     - __init__(system_prompt, keep, load_layers) — стратегический слой, окно, история, саммари
     - _ask_llm(messages) -> str — запрос с retry при 429 (внутренний метод)
     - _build_messages() -> list — слои в строгом порядке: [стратегия] + [инструкции] + [саммари] + [окно]
     - send_message(user_message) -> str — слой → запрос → ответ → история → порог сжатия
     - compress() — сжатие оперативного слоя
     - set_layer(index, layer) -> bool
     - load_history(filepath, layers) -> dict / save_history(filepath)
     - load_summary(filepath) / save_summary(filepath)
     - clear_context()
     - get_context_summary() / get_layers_stats() / get_summary() / get_history()
  8. Функции append_log(msg) — CLI-уровень
  9. Главный цикл: создать Agent → загрузить слои и саммари → ввод → команды (через методы агента) → agent.send_message → ответ → лог

  Вы: /exit
  [Память] Лог сохранён: Den_6_log_C_Context-Leveling.md

  ## Критерии приёмки

  1. «Запомни: ...» автоматически получает слой high (видно в /layers и /history).
  2. После 14 обменов срабатывает сжатие оперативного слоя; стратегический слой при этом **не изменяется** (проверить /history и текст саммари).
  3. Перезапуск с --load high загружает только ключевые факты: агент помнит имя, но не помнит светскую беседу; статистика загрузки выводится.
  4. /layer 1 mid меняет приоритет и отражается в логе.
  5. Порядок сообщений в запросе строго: стратегия → инструкции → саммари → окно (проверяется чтением кода _build_messages).
  6. Логика агента инкапсулирована в класс Agent: CLI-цикл не лезет к истории, слоям, саммари и API напрямую, только через методы.
  7. Каждая значимая строка кода прокомментирована на русском.

  ## Чего делать НЕ нужно

  - Не используй наследование, ABC, logging — один простой класс Agent с явными методами; типизация в сигнатурах методов допустима (как в
    задании).
  - Не выноси логику слоёв/сжатия в функции вне класса — всё состояние агента живёт в его атрибутах и методах (detect_layer может остаться
    функцией уровня модуля).
  - Не дублируй варианты A/B: здесь сжатие — лишь обслуживание оперативного слоя, а **главная демонстрация — слои** (автоопределение
    приоритета, выборочная загрузка, порядок в запросе).
  - Не подключай векторные БД и tool calls — это следующие дни.
  - Не отправляй саммари и инструкции как user/assistant — только system.
  - Не храни ключ API в коде.
