ПРОМТ: День 6, Вариант A — Sliding Window + Session Memory (класс Agent)

  Роль

  Ты — опытный Python-разработчик и преподаватель. Пишешь учебный код для студента, который уже прошёл День 1 (простой чат-бот с RouterAI) и
  знает: requests, .env, цикл while True, формат сообщений system/user/assistant.

  Задача

  Напиши один файл den_06/den_6_Kod_A_Sliding-Window.py — TUI-чат-бот с LLM, который демонстрирует технику Sliding Window (скользящее окно
  контекста) и тип памяти Session Memory с сохранением в файл. Логика агента должна быть инкапсулирована в класс Agent — это прямое требование
  задания Дня 6: «Агент должен быть отдельной сущностью (класс), а не просто один вызов API».

  Контекст проекта

   - API: RouterAI, OpenAI-compatible, endpoint https://routerai.ru/api/v1/chat/completions, модель stepfun/step-3.5-flash.
   - Ключ читается из .env (переменная API_KEY) через python-dotenv. Если ключа нет — понятная ошибка и остановка.
   - Стиль кода: комментарий почти к каждой строке, объясняющий «что и зачем», без сокращений и хитрых конструкций.
   - Всё в одном файле; зависимости — только requests и python-dotenv.
   - Разделение ответственности: история, окно и запросы к API — внутри класса Agent; TUI-цикл (ввод, команды, вывод) — снаружи и работает с
     агентом только через его методы.

  Класс Agent (обязателен, интерфейс из задания Дня 6)

  - Запрос к API с retry при 429 — внутренний метод агента (например, _ask_llm); снаружи не вызывается.
  - Полная история хранится внутри агента; для команды /history добавь метод (например, get_history()), возвращающий список сообщений с
    позициями относительно окна.

  Функциональные требования

  1. Sliding Window (главная техника)

   - Агент держит в контекстном окне только последние N сообщений диалога (без учёта system-сообщения).
   - N по умолчанию 10, задаётся флагом командной строки: python den_6_Kod_A_Sliding-Window.py --window 5 (модуль argparse) и передаётся в
     Agent(window=...).
   - Перед каждым запросом к API агент формирует messages так: [system] + последние N сообщений.
   - Вытесненные сообщения не теряются: полная история хранится внутри агента и сохраняется в файл (см. п. 2).
   - Когда окно сдвигается (старое сообщение вытесняется), выведи пользователю ненавязчивое уведомление, например: [Контекст] Сообщение вышло из
     окна (в памяти осталось 10 последних) — не чаще одного раза за сдвиг.

  2. Session Memory с сохранением

   - Полная история диалога сохраняется в файл Den_6_log_A_Sliding-Window.md в формате Markdown:

    1 # Лог диалога — Sliding Window (N=10)
    2
    3 ## 2026-09-09 14:30:05
    4 **Вы:** Привет
    5 **Агент:** Привет! Чем помочь?
    6 ```

   - Запись в файл — **после каждого обмена** (дозапись, режим "a", кодировка UTF-8); сохранение выполняет метод save_history() агента (или
     TUI вызывает его с путём). Агент хранит счётчик уже записанных сообщений, поэтому повторные вызовы save_history() (в т.ч. команда /save)
     дозаписывают только новые сообщения — без дублей.
   - При старте, если лог-файл существует, **не загружай** его в контекст автоматически (это Session Memory — она начинается с чистого листа),
     но сообщи пользователю: [Память] Найден прошлый лог: <имя файла> (в контекст не загружается — сессия новая, /load_history — загрузить).
   - Ручная загрузка по команде /load_history: агент вызывает load_history(LOG_FILE), парсит Markdown-лог (строки `## <дата>`, `**Вы:**`,
     `**Агент:**`) и восстанавливает сообщения в полную историю агента; в окно попадают последние N загруженных сообщений. Ответ:
     [Память] Загружено сообщений: M (в окне — K последних). Если файла нет — [Память] Файл не найден: <имя файла>, цикл продолжается (не падать).

  3. TUI-команды

  | Команда | Действие |
  |---|---|
  | /history | Показать **полную** историю (включая вытесненные из окна), с пометкой [в окне] / [вытеснено] |
  | /window | Показать текущий размер окна и сколько сообщений в нём (через get_context_summary()) |
  | /save | Вручную сохранить историю в лог-файл — agent.save_history(LOG_FILE) (дозапись только новых сообщений), ответ: [Память] Лог сохранён: <имя файла> |
  | /load_history | Вручную загрузить историю из лог-файла в контекст — agent.load_history(LOG_FILE) (см. п. 2) |
  | /clear | Очистить контекст окна — agent.clear_context() (полная история и файл сохраняются) |
  | /exit | Сохранить лог (agent.save_history(...)) и выйти |

  Обычный текст — сообщение агенту (agent.send_message(...)). Пустой ввод — игнорировать.

  4. Обработка ошибок API

   - Retry при HTTP 429: до 3 попыток, задержка 2 → 4 → 8 секунд (экспоненциальная), с сообщением [API] Лимит запросов, повтор через N сек....
   - При других HTTP-ошибках и таймауте (30 сек) — понятное сообщение и продолжение цикла (не падать).
   - Если в ответе нет choices — сообщение об ошибке формата, продолжить цикл.

  ## Структура кода (обязательна)

  1. Импорты: os, sys, json, argparse, datetime, requests, dotenv
  2. load_dotenv() + проверка API_KEY
  3. Парсинг --window через argparse
  4. Константы: URL, MODEL, LOG_FILE, RETRY_...
  5. class Agent:
     - __init__(system_prompt, window) — system prompt, окно, полная история
     - _ask_llm(messages) -> str — запрос с retry при 429 (внутренний метод)
     - send_message(user_message) -> str — окно → запрос → ответ → обновление истории
     - save_history(filepath) / load_history(filepath) — save: дозапись только новых сообщений (счётчик записанных); load: парсинг Markdown-лога и восстановление полной истории + последних N в окно
     - clear_context()
     - get_context_summary() -> str
     - get_history() -> list — для команды /history
  6. Функция append_log(role, text) — дозапись в Markdown-лог (TUI-уровень)
  7. Функция show_history(full, window) — вывод с пометками
  8. Главный цикл: создать Agent → ввод → команды (/history, /window, /save, /load_history, /clear, /exit — только через методы агента) → agent.send_message → ответ → лог

  System prompt: "Ты полезный ассистент. Отвечай кратко на русском языке."

  ## Критерии приёмки

  1. python den_6_Kod_A_Sliding-Window.py запускается и ведёт диалог.
  2. Логика агента инкапсулирована в класс Agent: TUI-цикл не лезет к истории и API напрямую, только через методы.
  3. --window 3 — после 4-го обмена появляется уведомление о вытеснении, а /history показывает [вытеснено] у старых сообщений.
  4. Лог-файл пополняется после каждого сообщения и корректно открывается как Markdown.
  5. При 429 бот не падает, а повторяет запрос.
  6. /save дозаписывает в лог только новые сообщения (без дублей уже сохранённых).
  7. /load_history поднимает сообщения из лога в полную историю, в окне оказываются последние N; /history показывает их с пометками; при отсутствии файла — сообщение об ошибке без падения.
  8. Каждая значимая строка кода имеет комментарий на русском.

  ## Чего делать НЕ нужно

  - Не используй наследование, ABC, датаклассы, logging — один простой класс Agent с явными методами; типизация в сигнатурах методов допустима
    (как в задании).
  - Не выноси логику окна/истории в функции вне класса — всё, что «знает» агент, должно жить в его атрибутах и методах.
  - Не подключай векторные БД, саммаризацию, tool calls — это варианты B/C и следующие дни.
  - Не загружай старый лог в контекст автоматически при старте — только по команде пользователя /load_history.
  - Не храни ключ API в коде.
