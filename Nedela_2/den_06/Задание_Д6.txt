## Теоретическая база

Согласно материалам недели N2, агент состоит из четырёх ключевых компонентов:

1. **Context Management** — управление контекстом диалога
2. **Memory Management** — управление долговременной и кратковременной памятью
3. **Planning** — планирование целей и разбиение на задачи
4. **Tool Orchestration** — оркестровка инструментов

В День 6 фокусируемся на первых двух компонентах: **Context Management** и **Memory Management**.

### Context Management — что нужно знать

- **Отсутствие памяти между сессиями.** Каждая новая сессия стартует с чистого листа (System Prompt). Иллюзия «памяти» создаётся подгрузкой сохранённых данных из файлов.
- **System Prompt** — самый устойчивый к перебалансировке, но даже его можно изменить последующими промтами.
- **Техники управления контекстом:**
  - **History Compression** — сжатие контекстного окна в саммари через нейросеть;
  - **Sliding Window** — сдвиг окна: старые сообщения удаляются, новые добавляются;
  - **Vector Embeddings** — представление диалога в виде векторов, извлечение по запросу;
  - **Context-Leveling (Слои)** — разделение на стратегический, оперативный и task-specific слои.

### Memory Management — что нужно знать

- **Session Memory** — кратковременная память в рамках сессии (простая, быстрая, но исчезает после завершения).
- **Compressed Memory** — сжатие сообщений в саммари перед сохранением (мало токенов, но потеря деталей).
- **Vector Base Memory** — факты → эмбеддинги → векторная БД (масштабируемо, но требует токенов на эмбеддинги).
- **Layered Memory** — контекст разбивается на слои по приоритету.

## Задание

Реализуйте **простого агента** с базовыми механизмами управления контекстом и памятью.

### Требования к агенту

Агент должен быть **отдельной сущностью** (класс), а не просто один вызов API. Логика запроса и ответа должна быть инкапсулирована.

#### 1. Базовая функциональность (обязательно)

- Агент принимает запрос пользователя;
- Отправляет его в LLM через API (RouterAI);
- Получает и выводит ответ;
- Хранит **историю текущего диалога** (Session Memory) в памяти;
- Имеет **System Prompt**, задающий роль агента.

#### 2. Управление контекстом (выберите минимум 1 технику)

Реализуйте одну из техник управления контекстом:

**Вариант A — Sliding Window:**
- Храните только последние N сообщений (например, 10) в контекстном окне;
- При превышении лимита старые сообщения удаляются;
- Настройте N через параметр или аргумент командной строки.

**Вариант B — History Compression:**
- Когда контекстное окно заполняется, сжимайте историю в саммари через отдельный вызов LLM;
- Саммари добавляется в начало нового запроса;
- Показывайте пользователю уведомление о сжатии.

**Вариант C — Context-Leveling (Слои):**
- Разделите контекст на два слоя:
  - **Стратегический** — System Prompt + общие инструкции (не меняется);
  - **Оперативный** — текущий диалог (растёт и сжимается);
- В запросе к API отправляйте оба слоя.

#### 3. Управление памятью (выберите минимум 1 тип)

Реализуйте один из типов памяти:

**Вариант A — Session Memory с сохранением:**
- Сохраняйте историю диалога в файл (JSON или Markdown);
- При перезапуске агента загружайте сохранённую историю;
- Формат сохранения: дата, роль, текст сообщения.

**Вариант B — Compressed Memory:**
- Раз в N сообщений сжимайте историю в краткое саммари;
- Саммари сохраняйте как отдельное сообщение в истории;
- По запросу пользователя показывайте саммари.

**Вариант C — Layered Memory:**
- Разделите сохранённые сообщения на слои по приоритету:
  - **Высокий** — ключевые решения и факты;
  - **Средний** — текущие задачи;
  - **Низкий** — общая переписка;
- При загрузке памяти определяйте, какие слои загружать.

### Интерфейс

Минимальный CLI-интерфейс:

```
Агент: Привет! Я ваш помощник. Чем могу помочь?
Вы: > Расскажи про управление контекстом LLM
Агент: Управление контекстом — это...
Вы: > А как работает память?
Агент: Память агентов бывает разных типов...
Вы: > /save — сохранить историю
Вы: > /clear — очистить контекст
Вы: > /history — показать историю
Вы: > /exit — выйти
```
