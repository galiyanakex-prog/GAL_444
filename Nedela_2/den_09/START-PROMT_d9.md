# START-PROMT_d9 — стартовый промт проекта `den_09` «Управление контекстом: сжатие истории»

## 1. Суть дня
К концу дня агент должен **сжимать историю диалога**: хранить последние N сообщений «как
есть», остальное сворачивать в summary (примерно каждые 10 сообщений), хранить summary
отдельно и подставлять его в запрос вместо полной истории — и **сравнивать качество
ответов и расход токенов до/после сжатия**. Формат результата — код (Python).

## 4. Главная инструкция
Работай **строго по `agents_memory_9/.plan_9`**, подшаг за подшагом, в порядке нумерации
(Блок 0 → 1 → 2 → 3 → 4 → 5 → 6). Отклонения от плана — только с явного согласия
пользователя. Один подшаг = один цикл работы, не склеивать.

## 5. Правила контекста
При новой сессии, потере контекста или непонятном смысле перечитать по порядку:
`agents_memory_9/.plan_9` → `agents_memory_9/.agents_memory_9` (последние отчёты) →
`agents_memory_9/.mem_9` (последние записи) → `meta_promt/ПРОМТ_den9_.txt`.
Первый невыполненный подшаг определять по `.mem_9`, а не по памяти.

## 6. Правила журналов
- После **каждого** подшага: запись в `.mem_9` (формат: Файл / Было / Стало / Проверка /
  Статус / Дата; для ознакомления — «Соответствует ли заданию» + «Предложения») и краткий
  отчёт в `.agents_memory_9` (3–5 строк + номер записи + следующий шаг).
- Журналы дописывать файловым инструментом (replace), не shell-heredoc: `$(...)` в командах
  блокируется политикой CLI.
- Предложенные, но не применённые правки остаются в `.mem_9` со статусом
  `⚠️ требует проверки` и закрываются в Блоке 5.

## 7. Критерии приёмки дня
1. `den_9_Kod.py` компилируется; в дне есть `README_d9.md`, `den_9_run.sh`,
   `den_9_run.desktop` (все непустые, `.sh`/`.desktop` исполняемые).
2. Последние N сообщений хранятся «как есть» (оперативное окно, `--keep`).
3. Остальная история сворачивается в summary автоматически по порогу `--compress-every`
   (по умолчанию 10 — «каждые 10 сообщений» из задания).
4. Summary хранится отдельно (файл `*.summary.md` + поле агента) и подставляется в запрос
   вместо полной истории (system-сообщение перед окном) — «под капотом», не копипастом (Ч1).
5. Повторное сжатие консолидирует саммари: старое саммари + новые сообщения (Ч3); старые
   сообщения не удаляются безвозвратно, а уходят в архив (Ч4).
6. Есть команда `/compare`: сравнение качества ответов и расхода токенов до/после сжатия;
   показывает экономию и без учёта суммаризации, и с её учётом + оговорка о prompt-cache
   (Ч8); живой API — только после явного «y», без него — локальная оценка.
7. Качество саммари управляемо: язык саммари = язык переписки (Ч6), лимит длины
   `--summary-word-limit` (Ч7), температура сжатия `--compress-temperature` (Ч6).
8. Сжатие переключается на лету (`/compress on|off`) — «момент включения/отключения хорошо
   виден» (Ч5).
9. Уроки Дней 6–8 перенесены: `errors='replace'` для stdin, `try: import readline`,
   токен-учёт и CSV из Дня 8 работают.
10. Тесты проходят без живого ключа (`API_KEY=test-key`, заглушка `requests`).
