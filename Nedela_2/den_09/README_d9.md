# День 9 — Управление контекстом: сжатие истории

> **Неделя 2** — «Инструментарий LLM: Агенты и их внутреннее устройство».
> День 9 — развитие агента Дня 8: токены не просто считаются — их становится МЕНЬШЕ.

## Суть проекта

Реализован CLI-чат-бот с LLM (RouterAI, модель `stepfun/step-3.5-flash`), который **хранит последние N сообщений «как есть», автоматически сворачивает всё старшее в саммари (по умолчанию каждые 10 сообщений), подставляет саммари в запрос «под капотом» вместо полной старой истории и умеет сравнивать качество и расход токенов до/после сжатия**.

База — `den_8_Kod.py` (День 8): токен-учёт (usage, CSV, `/tokens` `/cost` `/scenario`), контроль лимита контекста, JSON-снимок v2. Ядро сжатия (консолидация саммари, архив) в доноре уже было — День 9 делает его управляемым и измеримым.

Ключевая идея дня: **модель stateless, и запрос растёт как 1+2+…+N — сжатие истории ломает этот рост: в запрос едет короткое саммари + оперативное окно, а не вся история**. Но (вывод чата курса) экономия токенов ≠ экономия рублей: сама суммаризация — платный запрос, и она сбрасывает prompt-cache.

## Что нового относительно Дня 8

- **Порог автосжатия `--compress-every`** (требование задания «например каждые 10 сообщений»): когда вне окна накопилось ≥ N сообщений, все старые сворачиваются в саммари одним служебным запросом. В Дне 8 порог был жёсткой константой (8) — теперь настраивается флагом (по умолчанию 10) и переживает перезапуск (хранится в снимке);
- **Саммари хранится отдельно** (требование задания): поле `self.summary` + файл `Den_9_log.summary.md`; в запрос подставляется вторым system-сообщением «Саммари более раннего диалога: …» — «под капотом», без копипаста в текст пользователя. Сжатые сообщения не удаляются, а уходят в архив (`self.archived`) — доступны в `/history` и для сравнения «до»;
- **`/compare` — ядро дня**: один контрольный вопрос про начало диалога задаётся в двух вариантах запроса — «ДО» (вся история + архив) и «ПОСЛЕ» (саммари + окно). Печатает оба ответа (качество), локальную оценку токенов и **экономику двумя строками** (Ч8): «БЕЗ учёта суммаризации» и «С учётом суммаризации» (минус стоимость всех служебных запросов сжатия за сессию, накопитель `summary_usage`) + оговорку: сжатие меняет префикс запроса → **prompt-cache сбрасывается**, реальная экономия может быть ниже расчётной. Живое сравнение (2 запроса к API, оба ответа и фактические usage) — только после явного `y/N`;
- **`/compress on|off` — сжатие на лету** (Ч5): переключает стратегию контекста между `history_compression` (вкл) и `sliding_window` (выкл) без потери истории — меняется способ сборки запроса, а не данные; печатает «было → стало» и размер следующего запроса в токенах;
- **Язык саммари = язык переписки** (Ч6): эвристика `_detect_language` (кириллица/латиница) — саммари пишется на языке диалога, а не на языке промпта;
- **`--summary-word-limit`** (Ч7): лимит длины саммари в словах (по умолчанию 120; в чате курса тестировали 50) формулируется в промпте сжатия — ограничивает текст, а не обрезает ответ;
- **`--compress-temperature`** (Ч6): температура служебного запроса сжатия (по умолчанию 0.2 — фактичнее, чем творческий режим). Передаётся **только** в запрос сжатия; основной запрос идёт на дефолте API, чтобы сравнение в `/compare` не съезжало;
- **Снимок v3**: в JSON добавлены настройки сжатия (`compress_every`, `summary_word_limit`, `compress_temperature`) и накопитель `summary_usage`. Снимки Дня 8 (v2) и Дня 7 (v1) загружаются без падения — недостающие поля берутся по умолчанию; явные флаги запуска не затираются снимком (приоритет: флаг > снимок > константа);
- **Токен-учёт Дня 8 сохранён полностью**: `/tokens`, `/cost`, `/scenario`, CSV-журнал, контроль лимита `--max-context-tokens`.

## Команды

| Команда | Действие |
|---|---|
| `/compare` | качество и расход до/после сжатия: два ответа + экономия токенов/₽ двумя строками (compressed/layered) |
| `/compress on\|off` | включить/выключить сжатие на лету (все режимы) |
| `/compress` | принудительное сжатие истории в саммари (compressed/layered) |
| `/summary` | текущее саммари (compressed/layered) |
| `/tokens` | три счётчика: текущий запрос / ответ / вся история + локальная оценка |
| `/cost` | стоимость последнего обмена, всей сессии, прогноз на 100 обменов |
| `/scenario` | сравнение трёх сценариев расхода (живой API только после y/N) |
| `/history` | полная история с пометками `[в окне]`/`[вне окна]`/`[в саммари]`/`[слой]` |
| `/window` | состояние контекстного окна (sliding-window) |
| `/layers` | статистика по слоям (layered) |
| `/layer <№> <high\|mid\|low>` | сменить приоритет сообщения (layered) |
| `/save` / `/load` | сохранить / загрузить контекст в JSON |
| `/clear` | очистить контекст сессии в памяти (JSON на диске не трогается) |
| `/help` | список команд с пометкой доступности в текущем режиме |
| `/exit` | сохранить контекст и выйти |

## Запуск

```bash
# Через скрипт (из любого каталога)
./den_9_run.sh

# Основной режим дня: сжатие истории (порог 10 — из задания)
./den_9_run.sh --context compression --memory compressed

# Дешёвый тест автосжатия: порог 3, окно 2 — сжатие видно почти сразу
./den_9_run.sh --context compression --memory compressed --window 2 --compress-every 3

# Короткое саммари (как в чате курса) и «сухая» температура сжатия
./den_9_run.sh --context compression --summary-word-limit 50 --compress-temperature 0.1

# Режим «до» — без сжатия (для сравнения с /compare)
./den_9_run.sh --context sliding-window --memory session
```

Флаги Дней 6–8: `--context sliding-window|compression|leveling`, `--memory session|compressed|layered`, `--window`, `--keep`, `--load`, `--log`, `--context-file`, `--fresh` (начать новую сессию, игнорируя прошлый JSON-снимок), `--max-context-tokens`, `--max-tokens`, `--token-log`, `--price-in`, `--price-out`.

Новые флаги Дня 9: `--compress-every` (порог автосжатия, по умолчанию 10), `--summary-word-limit` (лимит слов саммари, по умолчанию 120), `--compress-temperature` (температура запроса сжатия, по умолчанию 0.2).

## Механика сжатия

```
полная история:  [m1 m2 m3 m4 m5 m6 m7 m8]  окно = 2, порог = 3
                        └── вне окна накопилось ≥ 3 → сжатие ──┐
                                                                ▼
запрос «после»:  system + «Саммари: …» + [m7 m8]      архив: [m1..m6]
запрос «до»:     system + [m1 m2 m3 m4 m5 m6 m7 m8] + вопрос   ← длиннее
```

- окно едет в запрос дословно — оперативный контекст не искажён;
- старая часть представлена саммари (консолидируется при каждом сжатии: старое саммари + новые сообщения);
- архив хранит исходные тексты — ничего не теряется безвозвратно, `/history` показывает всё.

## Тарификация и экономика (Step-3.5-Flash_params.md)

| Параметр | Значение |
|---|---|
| Модель | `stepfun/step-3.5-flash` |
| Контекстное окно | 262 144 токена (262K) |
| Входящие токены | 11 ₽ за 1M |
| Исходящие токены | 33 ₽ за 1M (втрое дороже входящих) |

**Почему экономия токенов ≠ экономия рублей** (Ч8, вывод чата курса):

1. сама суммаризация — отдельный платный запрос, причём исходящие (сам текст саммари) втрое дороже входящих;
2. сжатие меняет начало запроса → **prompt-cache провайдера сбрасывается**, а кэшированный префикс может быть выгоднее ~в 2 раза.

Поэтому `/compare` печатает экономию двумя строками — без учёта суммаризации и с её учётом. На коротких сессиях вторая строка бывает отрицательной: сжатие ещё не окупилось. Пример (заглушка API, порог 3):

```
[Сравнение] Локальная оценка запроса (без API):
  ДО  (вся история): ~168 токенов
  ПОСЛЕ (саммари+окно): ~138 токенов
  Экономия на одном запросе: ~30 токенов
  Экономика БЕЗ учёта суммаризации: ~0.000330 ₽ на запросе
  Экономика С учётом суммаризации (само сжатие стоило ~0.001760 ₽ за сессию): ~-0.001430 ₽
  Примечание: сжатие меняет начало запроса, поэтому prompt-кэш провайдера
  сбрасывается — реальная экономия может быть ниже расчётной.
```

## Общее с Днями 6–8

- API: RouterAI (OpenAI-совместимый), ключ в `.env` (переменная `API_KEY`);
- Retry при HTTP 429: до 3 попыток, задержка 2 → 4 → 8 сек; таймаут запроса 30 сек;
- Ошибки API не прерывают цикл; непредвиденные ошибки пишутся в `den_9_error.log` с ожиданием Enter;
- Уроки устойчивости: `sys.stdin.reconfigure(encoding='utf-8', errors='replace')` + `sys.stdout.reconfigure(errors='replace')`, `try: import readline`, пути через `BASE_DIR`;
- Стиль: учебный однофайловый скрипт, комментарий почти к каждой строке; зависимости — только `requests`, `python-dotenv` и стандартная библиотека.

## Результат

- Агент, который экономит токены: окно «как есть» + саммари вместо старой части диалога (три требования задания);
- Порог автосжатия настраивается (`--compress-every`, по умолчанию 10) и переживает перезапуск (снимок v3);
- `/compare` показывает качество и расход до/после, экономику двумя строками и оговорку про prompt-cache;
- `/compress on|off` переключает сжатие на лету без потери истории;
- Саммари — на языке переписки, с лимитом слов и отдельной температурой сжатия;
- Снимки v1/v2 загружаются без падения; токен-учёт Дня 8 сохранён полностью.
