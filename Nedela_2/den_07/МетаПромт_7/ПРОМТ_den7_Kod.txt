Ключевая идея (объясни её в шапке файла комментарием)

В Дне 6 память между запусками имели только compressed/layered-режимы (и то — только саммари/слои из Markdown-лога), а session-память умирала вместе с процессом. День 7 добавляет универсальную персистентность: полное состояние агента (история, архив, саммари, слои, режимы) снимается в JSON-файл и восстанавливается при следующем запуске. JSON выбран потому, что это машиночитаемый формат без потерь: Markdown-лог удобен человеку, но при парсинге теряет timestamps и структуру. Теперь «агент не выключался» — это не метафора: после перезапуска он продолжает диалог с того же места, со всей историей и саммари.

Функциональные требования

1. save_context_json(filepath) — полный снимок состояния в JSON:

{
  "version": 1,
  "saved_at": "2026-09-12 15:00:00",
  "context_strategy": "sliding_window",
  "memory_type": "session",
  "window": 10,
  "full_history": [ {"role": "user", "content": "...", "timestamp": "..."}, ... ],
  "archived": [ ... ],
  "summary": "...",
  "evicted_total": 0
}

   - Для layered-памяти каждая запись full_history/archived дополнительно содержит "layer".
   - Запись через json.dump(..., ensure_ascii=False, indent=2), кодировка UTF-8.
   - Перед записью — атомарность не требуется, но файл должен оставаться валидным при штатном сохранении.

2. load_context_json(filepath):
   - Файла нет → вернуть None (вызывающий код напечатает [Память] Прошлый контекст не найден, начинаю новую сессию) — не падать.
   - Файл повреждён (json.JSONDecodeError) или структура неожиданная (KeyError/TypeError) → сообщение [Память] Файл контекста повреждён, начинаю новую сессию, вернуть None — не падать.
   - Файл валиден → восстановить context_strategy, memory_type, window, full_history, archived, summary, evicted_total; вернуть статистику (число сообщений, длина саммари).
   - Сообщения без поля "layer" (снимок session/compressed) корректно загружаются в layered-режим: слой определить через detect_layer().

3. Автозагрузка при старте (главный цикл, до приветствия):
   - Если CONTEXT_FILE существует → agent.load_context_json(CONTEXT_FILE) и сообщение:
     [Память] Контекст восстановлен: N сообщений (саммари: M символов)
   - Если нет → [Память] Прошлый контекст не найден, начинаю новую сессию
   - Автозагрузка выполняется для ВСЕХ режимов (--context/--memory) — в этом смысл дня.

4. Автосохранение:
   - При /exit → agent.save_context_json(CONTEXT_FILE) + сообщение [Память] Контекст сохранён: <файл>.
   - При выходе по Ctrl+C / Ctrl+D (EOFError/KeyboardInterrupt) → сохранить так же (finally-логика или сохранение в обработчиках).

5. CLI-флаги (argparse) — все флаги Дня 6 сохраняются (--context, --memory, --window, --keep, --load, --log) и добавляется:

| Флаг | Значения | По умолчанию |
|---|---|---|
| --context-file | путь к JSON-файлу контекста | den_7_context.json |

   - Относительный путь фиксируется за каталогом скрипта (BASE_DIR), абсолютный — как есть.

6. Новые команды CLI:

| Команда | Действие |
|---|---|
| /save | ручное сохранение контекста в JSON: [Память] Контекст сохранён: <файл> |
| /load | ручная загрузка контекста из JSON (после /clear или для отката): [Память] Контекст восстановлен: ... |

   - Остальные команды Дня 6 без изменений: /history, /window, /summary, /compress, /layers, /layer, /clear, /exit.
   - /clear очищает контекст сессии В ПАМЯТИ; JSON-файл на диске не удаляется (долговременная память управляется явно через /load и /exit).

7. Приведение текстов к Дню 7:
   - Шапка-комментарий файла: «День 7 — den_7_Kod.py (сохранение контекста в JSON)» + ключевая идея дня.
   - Вывод: 🤖 Чат-бот — День 7 (контекст=..., память=..., окно=...).

   - Журнал ошибок: den_7_error.log.
   - Заголовок саммари: «# Саммари диалога — День 7».
   - Все остальные упоминания «День 6» в текстах и сообщениях заменить на «День 7».

8. Без изменений оставить (каркас Дня 6):
