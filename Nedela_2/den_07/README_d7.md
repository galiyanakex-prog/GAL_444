# День 7 — Сохранение контекста (JSON-персистентность агента)

> **Неделя 2** — «Инструментарий LLM: Агенты и их внутреннее устройство».
> День 7 — развитие агента Дня 6: контекст переживает перезапуск.

## Суть проекта

Реализован CLI-чат-бот с LLM (RouterAI, модель `stepfun/step-3.5-flash`), который **сохраняет полное состояние контекста в JSON-файл и восстанавливает его при перезапуске** — диалог продолжается так, как будто агент не выключался.

База — `den_6_Kod.py` (День 6): класс `Agent`, три стратегии контекста (`--context`) и три типа памяти (`--memory`). День 7 добавляет универсальную JSON-персистентность поверх всех режимов.

## Что нового относительно Дня 6

- **Хранение истории в JSON** (требование задания): метод `Agent.save_context_json()` пишет полный снимок состояния — версию формата, дату, режимы, окно, полную историю (с `role`/`content`/`timestamp` и `layer` для layered), архив свёрнутых сообщений, саммари и счётчик вытеснений;
- **Загрузка истории при перезапуске**: метод `Agent.load_context_json()` восстанавливает состояние; отсутствующий или повреждённый файл не роняет программу — печатается понятное сообщение и сессия начинается с чистого листа;
- **Автоматизация**: контекст загружается при старте (для всех режимов) и сохраняется при `/exit`, Ctrl+C и Ctrl+D — «агент не выключался» без ручных действий;
- **Ручное управление**: `/save` — сохранить контекст сейчас, `/load` — загрузить из файла (например, после `/clear`);
- **Почему JSON, а не Markdown-лог**: JSON — машиночитаемый формат без потерь (timestamps, слои, саммари), Markdown-лог остаётся человекочитаемой копией диалога. Оба файла ведутся параллельно.

## Команды

| Команда | Действие |
|---|---|
| `/history` | полная история с пометками `[в окне]`/`[вытеснено]`/`[в саммари]`/`[слой]` |
| `/window` | состояние контекстного окна (sliding-window) |
| `/summary` | текущее саммари (compressed/layered) |
| `/compress` | принудительное сжатие истории в саммари (compressed/layered) |
| `/layers` | статистика по слоям (layered) |
| `/layer <№> <high\|mid\|low>` | сменить приоритет сообщения (layered) |
| `/save` | сохранить контекст в JSON сейчас |
| `/load` | загрузить контекст из JSON |
| `/clear` | очистить контекст сессии в памяти (JSON на диске не трогается) |
| `/exit` | сохранить контекст и выйти |

## Запуск

```bash
# Через скрипт (из любого каталога)
./den_7_run.sh

# С флагами (как в Дне 6)
./den_7_run.sh --context leveling --memory layered --keep 6

# Или напрямую (с активированным .venv недели)
python den_7_Kod.py --context sliding-window --memory session
```

Флаги: `--context sliding-window|compression|leveling`, `--memory session|compressed|layered`, `--window` (для sliding-window, по умолчанию 10), `--keep` (для compression/leveling, по умолчанию 6), `--load` (слои для layered), `--log` (имя Markdown-лога, по умолчанию `Den_7_log.md`), `--context-file` (имя JSON-файла контекста, по умолчанию `den_7_context.json`).

## Общее с Днём 6

- API: RouterAI (OpenAI-совместимый), ключ в `.env` (переменная `API_KEY`);
- Retry при HTTP 429: до 3 попыток, задержка 2 → 4 → 8 сек; таймаут запроса 30 сек;
- Ошибки API не прерывают цикл; непредвиденные ошибки пишутся в `den_7_error.log` с ожиданием Enter;
- Стиль: учебный однофайловый скрипт, комментарий почти к каждой строке; логика агента инкапсулирована в класс `Agent`; зависимости — только `requests`, `python-dotenv` и стандартный `json`.

## Результат

- Агент, который сохраняет и восстанавливает контекст между запусками (требование задания Дня 7);
- Полное состояние (история, саммари, слои, режимы) переживает перезапуск во всех трёх режимах памяти;
- Устойчивость к отсутствию и повреждению JSON-файла;
- Markdown-лог и JSON-снимок ведутся параллельно: для человека и для агента.
