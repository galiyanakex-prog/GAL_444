### Улучшение 1. Вернуть фильтр неизвестных slash-команд (KNOWN_COMMANDS)

- **Баг:** ввод `/layerr`, `/help` или любой другой неизвестной команды уходит в LLM
  как обычное сообщение — лишние вызовы API, мусор в истории и логе.
- **Описание бага:** в Дне 7 удалён список `KNOWN_COMMANDS` и проверка `startswith("/")`,
  которые были в Дне 6. Опечатки и незарегистрированные команды обрабатываются как текст.
- **Решение бага:** добавить константу `KNOWN_COMMANDS` (с `/save`, `/load` вместо
  `/load_history`) и в начале цикла проверять `startswith("/")`: неизвестная команда
  выводится со списком доступных и НЕ отправляется агенту.
- **Что выполнено:** ☑ / **Что не выполнено:** ☐
  — добавлены `KNOWN_COMMANDS` (кортеж из 11 команд) и проверка
  `user_input.startswith("/")` первой проверкой в цикле; неизвестная команда печатает
  список доступных и `continue`, до LLM не доходит.

### Улучшение 5. Валидировать режимы из JSON-снимка (Б8)

- **Баг:** мусорное значение `context_strategy`/`memory_type` в снимке приводит к
  `ValueError` в `_build_messages` при первом сообщении.
- **Описание бага:** `load_context_json` доверяет снимку без проверки известных значений.
- **Решение бага:** проверять `context_strategy` по списку известных стратегий и
  `memory_type` по списку известных типов; при несоответствии — чистая сессия с сообщением.
- **Что выполнено:** ☑ / **Что не выполнено:** ☐
  — добавлены `KNOWN_STRATEGIES` и `KNOWN_MEMORY_TYPES`; в `load_context_json`
  проверяются и `context_strategy`, и `memory_type`, и корректность `window`
  (целое ≥ 1); при несовместимости печатается причина и возвращается `None`
  (чистая сессия), файл не удаляется.

### Улучшение 6. Проверять версию снимка (Б9)

- **Баг:** `version` пишется, но при загрузке не читается — версионирование фиктивно.
- **Описание бага:** старый/несовместимый снимок молча загружается как текущий.
- **Решение бага:** при `version != CONTEXT_VERSION` печатать предупреждение и начинать
  чистую сессию (как для структурных ошибок).
- **Что выполнено:** ☑ / **Что не выполнено:** ☐
  — в начале `load_context_json` проверяется `snapshot.get("version")`; при
  несовпадении с `CONTEXT_VERSION` печатается предупреждение и возвращается `None`.

### Улучшение 7. Предупреждать о расхождении снимка с флагами CLI (Б3)

- **Баг:** снимок молча перезаписывает режимы/окно из флагов CLI без предупреждения.
- **Описание бага:** `load_context_json` затирает `context_strategy`/`memory_type`/`window`
  значениями из файла, игнорируя явные флаги запуска.
- **Решение бага:** сравнивать значения снимка с флагами CLI; при расхождении печатать
  `[Конфиг]`-предупреждение о том, что конфигурация берётся из снимка.
- **Что выполнено:** ☑ / **Что не выполнено:** ☐
  — `load_context_json` принимает `cli_strategy`/`cli_memory`/`cli_window`; флаг
  `--context` приводится к внутреннему имени (`sliding-window` → `sliding_window`);
  при расхождении выводятся `[Конфиг]`-предупреждения «беру из снимка».

### Улучшение 8. Устранить двойной источник истины для layered (Б4)

- **Баг:** при старте layered JSON восстанавливает полную историю, но следом
  `load_history(LOG_FILE)` затирает её парсингом Markdown (архив теряется, `--load`
  фильтрует лог, а не снимок).
- **Описание бага:** `agent.load_history(LOG_FILE)` вызывается безусловно после
  `load_context_json` для всех режимов.
- **Решение бага:** фильтровать слои прямо в `load_context_json` по `self.load_layers`
  и не вызывать `load_history` для layered при успешном JSON-восстановлении.
- **Что выполнено:** ☑ / **Что не выполнено:** ☐
  — в `load_context_json` для layered слои фильтруются по `--load` (`chosen`), архив
  сохраняется; в главном цикле `agent.load_history(LOG_FILE)` вызывается только при
  `agent.memory_type != "layered"` — Markdown-лог больше не затирает JSON-снимок.

### Улучшение 13. Убрать/задействовать мёртвый Agent.save_history()

- **Баг:** метод `save_history` не вызывается нигде — мёртвый код, который вводит в заблуждение.
- **Описание бага:** в Дне 7 `/save` сохраняет JSON, а `save_history` остался от Дня 6 и
  не используется.
- **Решение бага:** задействовать метод вместо удаления — вернуть append-режим
  `save_history()` + `saved_count`/`mark_saved()` из Дня 6 и вызывать его при `/exit`;
  так Markdown-лог дозаписывается без дублей и без потери строк `append_log`.
- **Что выполнено:** ☑ / **Что не выполнено:** ☐
  — `save_history()` переведён с «w» (полная перезапись) на «a» (дозапись только
  `self.full_history[self.saved_count:]`); добавлены `saved_count` в `__init__`,
  `mark_saved()` и вызов `agent.mark_saved()` после `append_log`; в `/exit` теперь
  вызывается `agent.save_history(LOG_FILE)`; после JSON-восстановления
  `saved_count = len(full_history)` (снимок и лог ведутся параллельно, дублей нет).

### Улучшение 14. Не дублировать приветствие в истории при восстановлении

- **Баг:** каждый запуск дописывает приветствие в лог, и при восстановлении из JSON
  приветствие может дублироваться как реплика агента.
- **Описание бага:** приветствие пишется в лог на каждом старте и не входит в `full_history`,
  но при загрузке лога в layered-режиме (до фикса №8) попадало в историю.
- **Решение бага:** после фикса №8 источником истины для layered становится JSON,
  приветствие из лога в контекст не тянется; в `load_context_json` доп. защиты от дублей
  приветствия не требуется (приветствие не сохраняется в снимок).
- **Что выполнено:** ☑ / **Что не выполнено:** ☐
  — приветствие (`GREETING`) по-прежнему пишется только в Markdown-лог, а не в
  `full_history`/JSON-снимок; для layered `load_history` больше не вызывается, поэтому
  приветствие в контекст не попадает; дублирование при восстановлении устранено.

---

### Улучшение 15. Не обнулять архив при несовместимом снимке (безопасность восстановления)

- **Баг:** при структурной ошибке снимка агент сбрасывает состояние, но `archived`
  и `full_history` обнуляются без учёта того, что Markdown-лог ещё можно поднять.
- **Описание бага:** в `load_context_json` ветка ошибки сбрасывает только состояние агента,
  но поведение при частично валидном снимке не определено.
- **Решение бага:** при несовместимом снимке логировать причину и продолжать чистую
  сессию (как сейчас), НО не удалять Markdown-лог и не вызывать load_history поверх
  чистого JSON-восстановления (согласовано с №8).
- **Что выполнено:** ☑ / **Что не выполнено:** ☐
  — все ветки отказа (`JSONDecodeError`, неверная версия, неизвестные режимы, битая
  структура) печатают причину и возвращают `None`; файл снимка и Markdown-лог не
  удаляются; для layered `load_history` после JSON не вызывается (см. №8).

**Итоговый вывод.** Все 15 «чистых улучшений» применены к `den_7_Kod.py`,
`python -m py_compile` проходит без ошибок, хвост главного `while True`-цикла не
обрезан. В коде устранены регрессии Дня 7 относительно Дня 6 (фильтр неизвестных

и не затирает файлы: печатается причина и сессия начинается с чистого листа.

**Сверка с `README_d7.md`.** Поведение кода соответствует описанию: JSON-снимок
