     saved_at, режимы, окно, full_history, archived, summary, evicted_total;

     откатывает состояние);

     сессия, не падение;

  3. Баги

  Б1 (высокий, подтверждён стаб-тестом). Неизвестные /-команды и опечатки уходят в LLM
   как обычные сообщения: ввод /layerr и /help дал 2 живых вызова API с текстом
  команды в messages. В den_6 это было закрыто фильтром `KNOWN_COMMANDS` (п. 1.9
  Проверки_Д6). Потеря: деньги, мусор в истории, UX.

  Б2 (высокий). Рассинхрон нумерации /layer: cmd_layer ищет сообщение в
  agent.get_history() (архив + активные), а set_layer меняет слой только в
  full_history. Как только появляются архивные сообщения (после сжатия), /layer N high
   меняет одно сообщение, а показывает другое. В den_6 был фикс через
  `get_user_message()` — не перенесён.

  Б3 (средний, подтверждён тестом). load_context_json молча перезаписывает режимы из
  снимка поверх флагов CLI: запуск с --context compression --memory compressed при
  session-снимке → агент работает в session/sliding_window, флаги игнорируются без
  единого предупреждения (после `/exit` снимок остался `memory_type=session`).

  Б4 (средний). Конфликт двух источников для layered: при старте JSON востанавливает
  полную историю, но следом load_history(LOG_FILE) перезаписывает её парсингом
  Markdown-лога (только выбранные слои, timestamp=now, архив теряется из контекста).
  Идея «JSON — источник истины» Дня 7 для layered фактически не работает: --load high
  живёт за счёт Markdown, а не JSON.

  Б5 (низкий). input("Нажмите Enter...") в except Exception (строка 166) не защищён от
   EOFError — при EOF в этом месте трейсбек на экран. В den_6 был try/except EOFError 
  → break.

  Б6 (низкий). Создание лог-файла при старте без try/except OSError — сбой
  прав/каталога валит программу до первого ввода (в den_6 — `log_error` и
  продолжение).

  Б7 (низкий). Нет sys.stdout.reconfigure(errors='replace') — при экзотической
  кодировке терминала print кириллицы/эмодзи может упасть UnicodeEncodeError (в den_6
  было).

  Б8 (низкий). load_context_json не валидирует context_strategy из снимка: мусорное
  значение приведёт к ValueError в _build_messages при первом же сообщении (поймается
  общим except, но пользователь получит цикл «ошибка → Enter»).
