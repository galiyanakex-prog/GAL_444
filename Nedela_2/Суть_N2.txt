## 1. Четыре компонента внутреннего устройства агентов

Агент состоит из четырёх ключевых subsystem-ов:

1. **Context Management** — управление контекстом диалога
2. **Memory Management** — управление долговременной и кратковременной памятью
3. **Planning** — планирование целей и разбиение на задачи
4. **Tool Orchestration** — оркестрация инструментов (MCP, API, shell-команды)

---

## 2. Context Management

### 2.1. Фундаментальные особенности нейросетей

- **Отсутствие памяти между сессиями.** Каждая новая сессия стартует с чистого листа (System Prompt). Иллюзия «памяти» создаётся подгрузкой сохранённых данных из файлов.
- **Калибровка весов внутри сессии.** Последующие промты могут перебалансировать предыдущие. System Prompt — самый устойчивый, но даже его можно изменить.
- **TopP и TopC.** Агенты не перебирают всю матрицу вариантов, а работают в ограниченных параметрах.
- **Роли и инструкции.** Базовая база знаний — терабайты данных. Роли и инструкции сужают контекст до нужной области, значительно повышая качество работы.

### 2.2. Техники управления контекстом

| Техника | Описание | Плюсы | Минусы |
|---------|----------|-------|--------|
| **History Compression** | Сжатие всего контекстного окна в саммари через нейросеть | Создаёт иллюзию непрерывности | Потеря деталей, галлюцинации |
| **Sliding Window** | Сдвиг окна: старые сообщения удаляются, новые добавляются | Простая, эффективна для одной темы | Плохо работает при переключении тем |
| **Vector Embeddings** | Представление диалога/знаний в виде векторов, извлечение нужных по запросу | Сильно экономит контекстное окно | Требует дополнительную модель для эмбеддингов |
| **Context-Leveling (Слои)** | Разделение на стратегический, оперативный и task-specific слои | Не даёт каждому агенту полную историю | Сложная реализация, нетривиальное разбиение |
| **Новый диалог** | Полная очистка контекстного окна для новой задачи | Агент работает с чистого листа | Потеря всей истории |
| **Токенизация и обрезка** | Удаление «мусорных» токенов (слова-паразиты, формальности) | Сокращение использования окна | Не решает проблему полностью |
| **Topic Branches** | Дробление контекста по темам (как в ChatGPT) | Удобно для многозадачности | Промышленное решение |

### 2.3. Контекстное окно

- Современные модели: ~1 миллион токенов.
- Один диалог с кодом: 8 000–10 000 токенов.
- ~100 сообщений → достижение лимита → History Compression.

## 3. Memory Management

### 3.1. Типы памяти

| Тип | Описание | Плюсы | Минусы |
|-----|----------|-------|--------|
| **Session Memory** | Кратковременная память в рамках сессии | Простая, быстрая | Исчезает после завершения сессии |
| **Compressed Memory** | Сжатие сообщений в саммари перед сохранением | Мало токенов, большие сессии | Потеря деталей, галлюцинации |
| **Vector Base Memory** | Факты → эмбеддинги → векторная БД | Сохраняются все детали, масштабируемо | Много токенов, нет гарантии верных выводов |
| **Layered Memory** | Контекст разбивается на слои по приоритету | Точное попадание под задачу | Сложная реализация |
| **Rule-Based Memory** | Правила в стиле «если X, то Y» (нечёткая логика) | Жёсткий контроль, детерминированность | Негибкость, сложно поддерживать |
| **Self-Reflective Memory** | Сохранение семантических смыслов (настроение, предпочтения) | Высокое качество инференса, «эмоциональная» связь | Требует фильтрации, поддержки, расход токенов |

### 3.2. Эволюция ассистентов

1. **Basic Assistant** (GPT-3.5) — простой контекст сессии + общая база знаний.
2. **Smart Assistant** (GPT-4o, O1) — сессионная память + векторная память + правила.
3. **Modern Assistant** (GPT-5) — иерархическая память + self-reflection + vector retrieval + слоистая структура.

## 4. Planning (Планирование)

Этапы планирования при создании агента:

1. **Определение цели** — что нужно достичь в итоге.
2. **Разбиение цели на таски** — декомпозиция, как это делает человек.
3. **Выбор стратегии исполнения** — подбор подхода.
4. **Перепланирование** — если стратегия не подходит, пересмотр тасков.
5. **Подтверждение у пользователя** — согласование плана.
6. **Реализация** — выполнение по плану.

## 5. Tool Orchestration

### 5.1. Этапы работы с инструментами

1. **Tool Selection** — выбор инструмента (MCP-сервер, CLI-tool, skill).
2. **Tool Invocation** — вызов и применение инструмента.
3. **Получение результатов** — API-ответ, вывод shell-команды.
4. **Интерпретация** — проверка: результат соответствует цели?
5. **Обработка ошибок** — тулзы постоянно возвращают ошибки (API, shell).
6. **Обновление стейта** — фиксация прогресса в плане.

---

## 6. Лайфхаки работы с агентами

1. **Сужение контекста** — обязательно указывать язык, стек, задачу, прикреплять файлы.
2. **Индексация и векторизация проекта** — граф файлов, связность, векторизация.
3. **Документирование проекта** — комментарии, сигнатуры функций (без исходников).
4. **Stage-based execution** — разбиение работы на стадии, передача между независимыми агентами.
5. **Избегание суммаризации** — суммаризация убивает детали и увеличивает галлюцинации.

## 7. Промптинг

### 7.1. Уровни промптов

| Уровень | Описание |
|---------|----------|
| **Simple Prompt** | «Напиши функцию на Kotlin, которая проверяет простое число» |
| **Pro Prompt** | Указан стек, контекст (Android-модуль, аутентификация), документация |
| **Prompt Pro Max** | Мета-промт с примерами, шаблонами, зашитый в команды (не сгенерирован нейросетью) |

### 7.2. Протоколы обмена

- **JSON** — золотой стандарт, но жрёт много токенов (дублирование полей).
- **TUN** — кодирование JSON в компактный формат, экономия 30–60% токенов, повышение точности.
