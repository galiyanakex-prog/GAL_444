# День 8 — Работа с токенами (подсчёт токенов и стоимости диалога)

> **Неделя 2** — «Инструментарий LLM: Агенты и их внутреннее устройство».
> День 8 — развитие агента Дня 7: токены и деньги становятся видимыми.

## Суть проекта

Реализован CLI-чат-бот с LLM (RouterAI, модель `stepfun/step-3.5-flash`), который **считает токены текущего запроса, всей истории диалога и ответа модели, показывает стоимость каждого обмена и рост расходов сессии, а также демонстрирует поведение при переполнении контекстного окна**.

База — финальный `den_7_Kod.py` (День 7): JSON-персистентность контекста поверх трёх стратегий контекста (`--context`) и трёх типов памяти (`--memory`). День 8 добавляет сквозной токен-учёт поверх всех режимов.

От Дня 7 унаследованы и сохранены без изменений: **единый источник истины** (состояние восстанавливается только из JSON-снимка, а Markdown-лог и `.summary.md` — человекочитаемые копии, программа их не читает), флаг `--fresh` для старта новой сессии, послойные саммари leveled-памяти (`summary_by_layer` + приоритетный блок high/mid вне окна), валидация и миграция снимков, фильтр неизвестных slash-команд.

Ключевая идея дня: **модель stateless — весь диалог отправляется заново каждым запросом, значит контекст платный каждый обмен**. Расход входящих токенов растёт как 1+2+…+N, и это видно в цифрах.

## Что нового относительно Дня 7

- **Три счётчика токенов** (требование задания): `/tokens` показывает `usage.prompt_tokens` последнего обмена («токены текущего запроса» — весь отправленный контекст, т.к. модель stateless), `usage.completion_tokens` («ответ модели») и накопительную сумму всех обменов сессии («вся история»);
- **Локальная оценка токенов**: `estimate_tokens()` — эвристика (кириллица ≈ 1 токен / 3 символа, прочее ≈ 1 / 4) с опциональным tiktoken (если пакет появится — оценка станет точной, зависимость не обязательна); `estimate_messages_tokens()` оценивает весь запрос до отправки (+4 служебных токена на сообщение);
- **Стоимость в рублях**: `/cost` — цена последнего обмена, всей сессии и прогноз на 100 таких обменов. Тариф раздельный: входящие 11 ₽/1M, исходящие 33 ₽/1M (переопределяется флагами `--price-in` / `--price-out`);
- **CSV-журнал `den_8_tokens.csv`**: строка на каждый обмен — номер, время, режим, окно, три счётчика токенов, стоимость обмена и накопительная стоимость. Ошибка записи (битый путь) не роняет чат — предупреждение один раз;
- **Проверка переполнения до отправки**: `--max-context-tokens` задаёт лимит (по умолчанию — реальное окно модели 262K); запрос длиннее лимита блокируется **до** обращения к API с объяснением и подсказками — отказ дешевле оплаченного и отклонённого запроса. Если API всё же отклонил запрос по длине (4xx), причина распознаётся по маркерам и сообщается прямо;
- **`--max-tokens`**: лимит длины ответа передаётся в тело запроса — самый дешёвый способ урезать дорогие исходящие токены;
- **`/scenario`**: сравнение трёх сценариев (короткий / длинный / сверх-лимита; длинные тексты генерируются локально). Живые запросы к API — только после явного подтверждения `y/N`; без согласия всё считается локально с пометкой «оценка без API»;
- **Токен-учёт переживает перезапуск**: накопительные счётчики сохраняются в JSON-снимок (формат v2); снимки Дня 7 (v1, без usage) загружаются без падения — с предупреждением, что старые токены неизвестны;
- **Служебные запросы учитываются честно**: автосжатие саммари (режимы compression/leveling) тоже стоит денег — его токены идут в накопительную стоимость сессии, но не подменяют счётчики «текущего запроса».

## Команды

| Команда | Действие |
|---|---|
| `/tokens` | три счётчика: текущий запрос / ответ / вся история + локальная оценка последнего сообщения |
| `/cost` | стоимость последнего обмена, всей сессии, прогноз на 100 обменов |
| `/scenario` | сравнение трёх сценариев расхода (живой API только после y/N) |
| `/history` | полная история с пометками `[в окне]`/`[вытеснено]`/`[в саммари]`/`[слой]` |
| `/window` | состояние контекстного окна (sliding-window) |
| `/summary` | текущее саммари (compressed/layered) |
| `/compress` | принудительное сжатие истории в саммари (compressed/layered) |
| `/layers` | статистика по слоям (layered) |
| `/layer <№> <high\|mid\|low>` | сменить приоритет сообщения (layered) |
| `/save` / `/load` | сохранить / загрузить контекст в JSON |
| `/clear` | очистить контекст сессии в памяти (JSON на диске не трогается) |
| `/help` | список команд с пометкой доступности в текущем режиме |
| `/exit` | сохранить контекст и выйти |

## Запуск

```bash
# Через скрипт (из любого каталога)
./den_8_run.sh

# Демонстрация переполнения: лимит 60 токенов, любой длинный запрос будет заблокирован
./den_8_run.sh --max-context-tokens 60

# С флагами (как в Днях 6–7)
./den_8_run.sh --context leveling --memory layered --keep 6 --max-tokens 300

# Или напрямую (с активированным .venv недели)
python den_8_Kod.py --context sliding-window --memory session
```

Флаги Дней 6–7: `--context sliding-window|compression|leveling`, `--memory session|compressed|layered`, `--window`, `--keep`, `--load`, `--log`, `--context-file`, `--fresh` (начать новую сессию, игнорируя прошлый JSON-снимок).

Новые флаги Дня 8: `--max-context-tokens` (лимит контекста для проверки перед отправкой, по умолчанию окно модели), `--max-tokens` (лимит длины ответа), `--token-log` (CSV-журнал, по умолчанию `den_8_tokens.csv`), `--price-in` / `--price-out` (цены 1M токенов, по умолчанию 11 / 33 ₽).

## Тарификация (Step-3.5-Flash_params.md)

| Параметр | Значение |
|---|---|
| Модель | `stepfun/step-3.5-flash` |
| Контекстное окно | 262 144 токена (262K) |
| Входящие токены | 11 ₽ за 1M |
| Исходящие токены | 33 ₽ за 1M (втрое дороже входящих) |

Авторитетный источник цифр — блок `usage` в ответе API. Локальная оценка (символы/3–4) — приблизительный прогноз до отправки.

## Рост стоимости (почему контекст платный каждый обмен)

Модель stateless: каждый запрос несёт весь диалог заново. Если ответ стоит ~30 токенов, а системный промпт ~20, то входящие растут как 50, 100+, 150+… — каждый обмен дороже предыдущего. Пример из `/scenario` (лимит 3000, оценки без API):

```
короткий:      ~29 токенов,  оценка без API: ~0.000319 ₽ вход
длинный:       ~861 токенов, оценка без API: ~0.009471 ₽ вход
сверх-лимита:  ~7861 токенов, ЗАБЛОКИРОВАН лимитом (запрос не отправляется, 0 ₽)
```

Прогноз на 100 обменов в `/cost` показывает, во что выливается длинный диалог.

## Общее с Днями 6–7

- API: RouterAI (OpenAI-совместимый), ключ в `.env` (переменная `API_KEY`);
- Retry при HTTP 429: до 3 попыток, задержка 2 → 4 → 8 сек; таймаут запроса 30 сек;
- Ошибки API не прерывают цикл; непредвиденные ошибки пишутся в `den_8_error.log` с ожиданием Enter;
- Уроки устойчивости: `sys.stdin.reconfigure(encoding='utf-8', errors='replace')` + `sys.stdout.reconfigure(errors='replace')`, `try: import readline`, пути через `BASE_DIR`;
- Стиль: учебный однофайловый скрипт, комментарий почти к каждой строке; зависимости — только `requests`, `python-dotenv` и стандартная библиотека (`csv`, `json`).

## Результат

- Агент, который делает токены и деньги видимыми (требование задания Дня 8);
- Три счётчика из `usage` + локальная оценка для прогноза до отправки;
- Стоимость обмена, сессии и прогноз роста — в консоли и в CSV-журнале;
- Переполнение контекста моделируется флагом `--max-context-tokens` без сжигания реального окна 262K;
- Токен-учёт переживает перезапуск (снимок v2), снимки Дня 7 (v1) загружаются без падения.
