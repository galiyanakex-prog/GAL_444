# START-PROMT_d8 — стартовый промт проекта `den_08` «Работа с токенами»

## 1. Суть дня
К концу дня агент должен **считать токены** своей работы: сколько уходит в текущий запрос,
сколько накопилось за всю историю диалога, сколько стоит ответ модели — и показывать, как это
растёт по мере диалога и **что ломается при переполнении** контекстного окна.
Формат результата — код (Python).

## 4. Главная инструкция
Работай **строго по `agents_memory_8/.plan_8`**, подшаг за подшагом, в порядке нумерации
(Блок 0 → 1 → 2 → 3 → 4 → 5 → 6). Отклонения от плана — только с явного согласия
пользователя. Один подшаг = один цикл работы, не склеивать.

## 5. Правила контекста
При новой сессии, потере контекста или непонятном смысле перечитать по порядку:
`agents_memory_8/.plan_8` → `agents_memory_8/.agents_memory_8` (последние отчёты) →
`agents_memory_8/.mem_8` (последние записи) → `meta_promt/ПРОМТ_den8_.txt`.
Первый невыполненный подшаг определять по `.mem_8`, а не по памяти.

## 6. Правила журналов
- После **каждого** подшага: запись в `.mem_8` (формат: Файл / Было / Стало / Проверка /
  Статус / Дата; для ознакомления — «Соответствует ли заданию» + «Предложения») и краткий
  отчёт в `.agents_memory_8` (3–5 строк + номер записи + следующий шаг).
- Журналы дописывать файловым инструментом (replace), не shell-heredoc: `$(...)` в командах
  блокируется политикой CLI.
- Предложенные, но не применённые правки остаются в `.mem_8` со статусом
  `⚠️ требует проверки` и закрываются в Блоке 5.

## 7. Критерии приёмки дня
1. `den_8_Kod.py` компилируется; в дне есть `README_d8.md`, `den_8_run.sh`,
   `den_8_run.desktop` (все непустые, `.sh`/`.desktop` исполняемые).
2. Считаются и выводятся **три числа**: токены текущего запроса, токены всей истории диалога
   (накопительно), токены ответа модели.
3. Есть стоимость в рублях по ценам 11/33 ₽ за 1M и CSV-лог роста токенов по обменам.
4. Реализованы сценарии: короткий диалог, длинный диалог, диалог сверх лимита (лимит
   задаётся искусственно флагом `--max-context-tokens`, реальные 262K не сжигаем).
5. При переполнении — понятное сообщение и подсказка, программа не падает.
6. Уроки Дней 6–7 перенесены: `errors='replace'` для stdin, `try: import readline`.
7. Тесты проходят без живого ключа (`API_KEY=test-key`, заглушка `requests`).
