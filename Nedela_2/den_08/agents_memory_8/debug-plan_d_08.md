### Группа A. Регрессии (фиксы den_07, потерянные при переносе)

#### A1. Вернуть фильтр неизвестных slash-команд + `KNOWN_COMMANDS`
- **Баг:** `/layerr`, `/helpp` и любые опечатки уходят в LLM как обычный текст — платные вызовы, мусор в истории.
- **Описание:** в den_8 нет `KNOWN_COMMANDS` и проверки `startswith("/")`.
- **Решение:** константа `KNOWN_COMMANDS` (12 команд + `/tokens`, `/cost`, `/scenario`); в начале цикла проверка `startswith("/")` → «Неизвестная команда … Доступны: …» и `continue`.
- **Проверка:** `grep KNOWN_COMMANDS` = 1+; стаб-тест: `/layerr` → 0 вызовов API.
- ☐

#### A2. Вернуть `/help` (`cmd_help`)
- **Баг:** `/help` отсутствует (и без A1 уходит в LLM).
- **Решение:** `cmd_help(agent, args)` с пометкой доступности по режимам + `/tokens`, `/cost`, `/scenario`.
- **Проверка:** `grep "def cmd_help"` = 1.
- ☐

#### A3. Вернуть `Agent.get_user_message()` и починить `cmd_layer`
- **Баг:** `cmd_layer` берёт текст через `get_history()` (архив + активные), а `set_layer` меняет только `full_history` → после сжатия `/layer N` меняет одно, показывает другое.
- **Решение:** метод `get_user_message(index)` (по `full_history`, 1 — последнее пользователя); в `cmd_layer` использовать его.
- **Проверка:** `grep "def get_user_message"` = 1; `cmd_layer` не содержит `get_history()`.
- ☐

#### A4. Вернуть `sys.stdout.reconfigure(errors='replace')`
- **Баг:** не-UTF-8 поток stdout → `UnicodeEncodeError` при печати кириллицы/эмодзи.
- **Решение:** строка сразу после `sys.stdin.reconfigure(...)`.
- **Проверка:** `grep stdout.reconfigure` = 1.
- ☐

#### A5. Вернуть флаг `--fresh`
- **Баг:** нет штатного способа начать новую сессию; снимок всегда перезаписывает флаги.
- **Решение:** `parser.add_argument("--fresh", action="store_true", …)`; при `args.fresh` пропускать автозагрузку (явное сообщение), снимок перезапишется при сохранении.
- **Проверка:** `--help` показывает флаг; `grep "\-\-fresh"` = 2 (парсер + ветка).
- ☐

#### A6. `SUMMARY_FILE` — сосед лога, а не всегда `BASE_DIR`
- **Баг:** `--log /tmp/x.md` оставляет саммари в `den_08/x.summary.md`.
- **Решение:** `SUMMARY_FILE = os.path.splitext(LOG_FILE)[0] + ".summary.md"`.
- **Проверка:** `grep basename(LOG_FILE)` = 0.
- ☐

#### A7. Ловить `OSError` при создании/дозаписи лога
- **Баг:** сбой прав/каталога валит программу до первого ввода.
- **Решение:** `try/except OSError` + `log_error` вокруг создания заголовка и дозаписи приветствия.
- **Проверка:** `grep -c "except OSError"` ≥ 2.
- ☐

#### A8. Защитить `input("Нажмите Enter…")` от EOF
- **Баг:** Ctrl+D в обработчике общей ошибки даёт traceback.
- **Решение:** `try/except EOFError` → корректный выход.
- **Проверка:** `grep -c "EOFError"` ≥ 2.
- ☐

#### A9. Ловить голое `/layer` без аргументов
- **Баг:** `/layer` (без аргументов) уходит в LLM (ловится только `/layer `).
- **Решение:** условие `user_input == "/layer" or user_input.startswith("/layer ")`.
- **Проверка:** grep по `== "/layer" or`.
- ☐

#### A10. Восстановить append-режим `save_history` + `saved_count` / `mark_saved`
- **Баг:** `save_history` перезаписывает лог целиком («w») и не вызывается → дубли/потеря строк.
- **Решение:** `saved_count` в `__init__`, `mark_saved()`, `save_history` дозаписывает только `full_history[saved_count:]`; в цикле после `append_log` → `mark_saved()`; `/exit` вызывает `save_history`.
- **Проверка:** `grep -c "saved_count"` ≥ 4.
- ☐

### Группа B. Логические дефекты JSON-персистентности (те же, что закрывались в den_07)

#### B1. Валидировать режимы из снимка
- **Баг:** мусорный `context_strategy`/`memory_type`/`window` в снимке роняет сборку запроса/арифметику.
- **Решение:** `KNOWN_STRATEGIES`, `KNOWN_MEMORY_TYPES`; проверка + корректность `window` (int ≥ 1); при несовместимости — чистая сессия с объяснением, файл не удалять.
- **Проверка:** grep констант; снимок со `"context_strategy": "xxx"` → понятное сообщение, не падение.
- ☐

#### B2. Проверять `version` снимка + миграция v1→v2
- **Баг:** `version` пишется, но при загрузке не читается; старые/новые снимки молча грузятся.
- **Решение:** `MIN_MIGRATABLE_VERSION = 1`; `version < 1` или `> CONTEXT_VERSION` → отказ с причиной; v1 → миграция (единое `summary` в `summary_by_layer["low"]` + `usage_total` нули + предупреждение).
- **Проверка:** снимок v1 грузится с предупреждением; v99 отказ.
- ☐

#### B3. Предупреждать о расхождении снимка с флагами CLI
- **Баг:** снимок молча перезаписывает флаги запуска.
- **Решение:** `load_context_json(..., cli_strategy, cli_memory, cli_window)`; при расхождении — `[Конфиг] … беру из снимка`.
- **Проверка:** запуск с другими флагами → предупреждение.
- ☐

#### B4. Единый источник истины: убрать `load_history`/`load_summary`
- **Баг:** после `load_context_json` вызывается `load_history(LOG_FILE)` — затирает JSON (слои/саммари) и печатает противоречивое «лог найден».
- **Решение:** удалить методы `load_history`, `load_summary` и вызов из цикла; `notify_old_log()` печатать ТОЛЬКО когда снимок не восстановлен.
- **Проверка:** `grep "def load_history\|def load_summary\|load_history(LOG_FILE)"` = пусто.
- ☐

#### B5. `clear_context`: сбрасывать `summary_by_layer`/`saved_count` и удалять файл саммари
- **Баг:** `/clear` неполон (послойные саммари остаются; старый файл саммари вернётся после рестарта).
- **Решение:** в `clear_context` сбросить `summary_by_layer`, `saved_count`, удалить `SUMMARY_FILE` при compressed/layered.
- **Проверка:** `/clear` → пусто в памяти и файл удалён.
- ☐

### Группа C. Эволюция leveled-памяти (функциональная дыра den_07, унаследована в den_08)

#### C1. Послойные саммари `summary_by_layer` + три промпта сжатия
- **Баг:** один `self.summary` стирает разницу важности; high-факт сжимается наравне с болтовнёй.
- **Решение:** `summary_by_layer` (high/mid/low) для layered; `self.summary` — только для compressed; `COMPRESS_PROMPTS` (3 промпта).
- **Проверка:** grep; `/summary` в layered показывает секции.
- ☐

#### C2. Сжатие по слоям: `_run_compression` / `_apply_compression`
- **Баг:** `_compress_history` не знает о слоях.
- **Решение:** перенести den_07: `_compress_history(..., prompt)`, `_run_compression` (группировка по слоям), `_apply_compression` (частичное сжатие по слоям); `send_message` и `compress()` перевести на них.
- **Проверка:** py_compile; при автосжатии layered непустые слои имеют отдельные саммари.
- ☐

#### C3. Приоритетный блок high/mid вне окна в `_build_messages_leveling`
- **Баг:** до первого сжатия high-сообщение вне окна не попадает в запрос → модель «не знает» дедлайн.
- **Решение:** блок `[приоритет {layer}]` для сообщений вне окна (high/mid), newest-first, лимит `PRIORITY_CAP = 6`; порядок: system → правила → послойные саммари → приоритетный блок → окно.
- **Проверка:** живой/сухой прогон `--keep 2`: модель называет дедлайн.
- ☐

#### C4. Синхронизировать `/summary`, `/layers`, `/window`, `save_summary`, `get_summary_length`
- **Баг:** методы знают только об одном саммари.
- **Решение:** порт den_07: `get_summary` (секции), `get_context_summary` (длины по слоям), `get_layers_stats` (вкл. длину саммари), `save_summary` (послойно), `get_summary_length()`.
- **Проверка:** py_compile; `/layers`/`/summary` показывают послойные данные.
- ☐

### Группа D. Собственные дефекты Дня 8 (токен-учёт)

#### D1. В `load_context_json` сбрасывать токен-счётчики при отказе загрузки
- **Баг:** ветка структурной ошибки сбрасывает историю, но оставляет `usage_total`/`last_usage`/`exchanges` — после `/load` из битого файла старые токены «залипают».
- **Решение:** в ветках отказа сбрасывать `usage_total`, `last_usage = {}`, `exchanges = 0`.
- **Проверка:** `/load` из битого снимка → `/tokens` показывает «нет данных», история 0.
- ☐

#### D2. В валидацию версии добавить восстановление `usage_total` и миграцию v1 (usage отсутствует)
- **Баг:** при добавлении проверки версии (B2) нужно сохранить уже имеющееся чтение `usage_total` и, для v1, честно обнулить токены.
- **Решение:** в общем блоке: `usage_total` читается с `.get`-дефолтами; v1 → нули + предупреждение «токены прошлой сессии неизвестны».
- **Проверка:** снимок v1 грузится, токены с нуля.
- ☐

#### D3. CSV-строка пишется ДО добавления ответа в историю — порядок допустим, но `exchanges`/`last_usage` уже актуальны
- **Баг (потенциальный):** `append_token_log` читает `last_usage`/`exchanges` — убедиться, что они уже обновлены (в `_ask_llm` и `send_message` — да).
- **Решение:** документировать порядок в комментарии; проверки кода не требуют изменения.
- **Проверка:** CSV содержит верные `exchange`/токены (уже покрыто тестами mem_8:3.7).
- ☐

## Блок 4 — Результат выполнения

Все пункты Блока 1 применены к `den_8_Kod.py`. `py_compile` — OK.

**Причина всех багов.** `den_8_Kod.py` был скопирован с промежуточной (до финального
дебага) версии `den_7_Kod.py`, поэтому потерял все фиксы Дня 7: регрессии
(`KNOWN_COMMANDS`, `/help`, `get_user_message`, `stdout.reconfigure`, `--fresh`,
`SUMMARY_FILE` от `LOG_FILE`, `try/except OSError/EOFError`, `/layer` голое,
`saved_count`/`mark_saved`), логические исправления JSON-персистентности
(валидация режимов/версии, предупреждение о расхождении с CLI, единый источник
истины — удаление `load_history`/`load_summary`) и эволюцию leveled-памяти
(послойные саммари). Плюс закрыты точечные дефекты Дня 8: сброс токен-счётчиков
при отказе загрузки, восстановление `usage_total`/миграция v1, исправление
локальной оценки (считалась по последнему сообщению истории, а не по реплике
пользователя).

**Что сделано (по группам Блока 1):**
- **A (регрессии):** A1–A10 — все выполнены.
- **B (JSON-валидация):** B1–B5 — все выполнены (`load_context_json` переписан:
  проверка версии + миграция v1→v2, валидация `KNOWN_STRATEGIES`/`KNOWN_MEMORY_TYPES`
  и `window`, предупреждения `[Конфиг]`, фильтрация слоёв по `--load`, сброс
  `usage_total`/`last_usage` при отказе).
- **C (leveled-память):** C1–C4 — все выполнены (`summary_by_layer`,
  `COMPRESS_PROMPTS`, `_run_compression`/`_apply_compression`, приоритетный блок
  `PRIORITY_CAP`, синхронизация `/summary`/`/layers`/`/window`/`save_summary`/
  `get_summary_length`).
- **D (день 8):** D1–D3 — выполнены (D3 — порядок подтверждён, правок не требовал).

**Проверки.**
- `py_compile` — OK.
- grep-чеклист: регрессии/двойной источник — 0 совпадений; все возвращённые
  фиксы — на месте.
- Сухой стаб-тест (заглушка `_ask_llm`, без сети/`input`): приоритетный блок
  leveling попадает в запрос; послойное сжатие даёт `{high, low}`; битый снимок →
  чистая сессия без падения; снимок v1 мигрирует (`summary` → `summary_by_layer["low"]`);
  переполнение (`--max-context-tokens 20`) блокирует запрос и сохраняет историю;
  `/scenario` в режиме «без API» работает; `/clear` в layered сбрасывает послойные
  саммари.
- Смоук-тест (`API_KEY=test-key`, `--fresh`): старт, `/help`, `/tokens`, `/cost`,
  `/exit` — без падений, корректные сообщения.

**Открытые вопросы (не блокируют).**
1. Живой прогон с реальным API не выполнялся (только с явного согласия пользователя).

   при тестировании были засорены и откачены через `git checkout` — в них не осталось
   изменения при дебаг-фиксе.
3. `PRIORITY_CAP = 6` — эмпирическая константа; при раздувании приоритетного блока
   выносить в конфиг/флаг.
