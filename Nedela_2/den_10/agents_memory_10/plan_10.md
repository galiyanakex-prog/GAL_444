4. **Размер шага.** Подшаг выполняется без риска выйти за 70% контекстного окна: за один
   подшаг читаем 1–2 файла, правим 1 файл и не больше одного логического блока.
   **Батч-режим (включён по умолчанию):** независимые подшаги объединяются, если суммарный
   объём ≤ ~300 строк чтения и ≤ ~150 строк правки, подшаги однотипны и не требуют

## КОНТЕКСТ ЗАДАНИЯ (что именно должно работать в конце)

Из `Задание_Д10.txt`: реализовать в агенте минимум 3 стратегии управления контекстом и
переключатель между ними; протестировать все стратегии на одном сценарии («собираем ТЗ,
10–15 сообщений»); сравнить качество ответа, стабильность (не теряет ли важные детали),
расход токенов, удобство для пользователя. Результат: агент с 3 стратегиями
(Sliding Window / Facts / Branching) + сравнение результатов. Формат: видео + код.

**Стратегия 1 — Sliding Window:** хранить только последние N сообщений, остальное
ОТБРАСЫВАТЬ (удаление, не сжатие — подтверждено Алексеем Гладковым в чате). Уже есть в
доноре (`sliding_window`).

**Стратегия 2 — Sticky Facts / Key-Value Memory:** отдельный блок `facts` (ключ-значение:
цель, ограничения, предпочтения, решения, договорённости); обновляется после КАЖДОГО
сообщения пользователя; в запрос отправляется facts + последние N сообщений. По чату:
Ivan Bazhenov — окно едет «сырым», обогащённым JSON фактов в том же промпте; Dmitry
Sevostianov — похоже на суммаризацию, но суше, «выжимка по шаблону», обновлять только если
появились новые факты; Алексей Гладков — факты можно хранить «многие ко многим» и не
обязательно в одном месте (усложнение сверх минимума — фиксируется в README как вариант
развития, в код не внедряется).

**Стратегия 3 — Branching (ветки диалога):** checkpoint в диалоге → 2 ветки от одного
места → независимое продолжение → переключение между ветками. Близко к Topic Branches
(Суть_N2 §2.2). **Требования пользователя (обязательные):**
- ветки хранятся в отдельной директории `Branches/` в папке дня;
- каждая ветка — отдельный файл (JSON: сообщения + метаданные);
- активная ветка ВИДНА в терминале (приглашение ввода и/или шапка);
- `/branch list` — просмотр веток;
- `/branch switch <имя>` — переключение между ветками.

**Сравнение стратегий** (из задания): прогон одного сценария на каждой стратегии, сравнение
по 4 критериям. Инфраструктура Дня 9 переиспользуется: токен-учёт (usage, CSV), `/compare`
(переосмысляется как сравнение стратегий), `/scenario`.

Из `Суть_N2.txt` (для метапромтов): §2.2 — Sliding Window (простая, эффективна для одной
темы; плохо при переключении тем), Topic Branches (дробление контекста по темам, удобно
для многозадачности, промышленное решение); §3.1 — Vector Base Memory (факты → эмбеддинги;
«много жрёт токенов», нужна доп. модель — поэтому в Д10 факты БЕЗ эмбеддингов, key-value);
§2.1 — отсутствие памяти между сессиями.
