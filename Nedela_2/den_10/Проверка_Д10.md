# Сценарий ручной проверки — День 10 «Управление контекстом: разные стратегии (без summary)»

> Чек-лист для живой проверки проекта `Nedela_2/den_10` руками, без автотестов.
> Время прохождения: ~20–25 минут. Живые запросы к API — платные (≈1–3 ₽ на весь сценарий).
> Отметки: ☐ — не выполнено, ✅ — прошло, ❌ — не прошло (записать, что именно).

## Подготовка (5 минут)

☐ **П.1** Открыть терминал в каталоге `Nedela_2/den_10`.

☐ **П.2** Убедиться, что ключ API на месте:
```bash
grep -q "API_KEY" ../../.env && echo "ключ есть" || echo "ключа НЕТ"
```
Ожидание: «ключ есть». Если нет — создать `.env` по `.env.example` в корне `AI_9`.

☐ **П.3** Убедиться, что папка чистая (нет артефактов прошлых прогонов):
```bash
ls
```
Ожидание: НЕТ файлов `den_10_facts.json`, `den_10_context.json`, `den_10_tokens.csv`,
`Den_10_log.md`, директории `Branches/`. (Они появятся в ходе проверки — это нормально.)

## Часть 1. Стратегия Sliding Window (базовая, 3 минуты)

☐ **1.1** Запустить:
```bash
./den_10_run.sh --context sliding-window --memory session --window 4
```

☐ **1.2** Проверить шапку: `контекст=sliding-window`, приглашение ввода — обычное `Вы: `
(без `[main]`).

☐ **1.3** Отправить 6 коротких сообщений по очереди (живой API):
```
Меня зовут Алексей
Мой любимый цвет — синий
Я живу в Казани
У меня два кота
Работаю программистом
Люблю кофе
```
Ожидание: после 5-го сообщения появляется `[Контекст] Сообщение вышло из окна
(осталось 4 последних)` — старые реплики УДАЛЯЮТСЯ (Ч1: отбрасывание = удаление).

☐ **1.4** Ввести `/history` — убедиться, что «Меня зовут Алексей» в истории есть, но
пометки показывают вытеснение из окна.

☐ **1.5** Спросить: `Как меня зовут?`
Ожидание: модель НЕ знает имени (оно вытеснено) — это демонстрация слабости стратегии.

☐ **1.6** Ввести `/exit`. Убедиться, что создались `den_10_context.json`, `Den_10_log.md`,
`den_10_tokens.csv`.

## Часть 2. Стратегия Sticky Facts (5 минут)

☐ **2.1** Запустить:
```bash
./den_10_run.sh --context facts --memory session --window 4
```

☐ **2.2** Отправить те же 6 сообщений из Части 1.
Ожидание: после КАЖДОГО сообщения — строка `[Факты] Обновлено: … (N фактов всего)`
(служебный запрос обновления фактов). Если новых фактов нет — строки может не быть
(это корректно: Ч3 — обновлять только при появлении новых фактов).

☐ **2.3** Ввести `/facts`.
Ожидание: блок «ключ: значение» примерно вида:
```
имя: Алексей
цвет: синий
город: Казань
```

☐ **2.4** Проверить файл фактов:
```bash
cat den_10_facts.json
```
Ожидание: валидный JSON с теми же фактами.

☐ **2.5** Спросить: `Как меня зовут и где я живу?`
Ожидание: модель ЗНАЕТ имя и город — факты сохранились, хотя сообщения уже вытеснены
из окна. Это главное отличие от Части 1.

☐ **2.6** Ввести `/tokens` — убедиться, что есть счётчики; стоимость сессии выше, чем
в Части 1 (каждое сообщение = 2 запроса: основной + обновление фактов).

☐ **2.7** Ввести `/exit`.

☐ **2.8** Запустить повторно ту же команду (2.1).
Ожидание: `[Факты]`-блок загружен из файла (факты персистентны). Спросить
`Как меня зовут?` — модель помнит. Ввести `/exit`.

## Часть 3. Стратегия Branching (7 минут)

☐ **3.1** Запустить:
```bash
./den_10_run.sh --context branching --memory session
```

☐ **3.2** Проверить шапку: строка `Активная ветка: main (список: /branch list)`,
приглашение — `Вы [main]: `.

☐ **3.3** Ввести `/branch list`.
Ожидание: одна ветка `* main (0 сообщений, создана …)` — звёздочка у активной.

☐ **3.4** Отправить 3 сообщения (живой API):
```
Собираем ТЗ. Цель: интернет-магазин косметики
Целевая аудитория: женщины 25–45 лет
Срок запуска: 1 октября
```

☐ **3.5** Создать ветку от текущего места:
```
/branch new вариант-б
```
Ожидание: `[Ветки] Создана ветка «вариант-б» от текущего места (checkpoint: 6 сообщений),
продолжаю в ней`. Приглашение сменилось на `Вы [вариант-б]: `.

☐ **3.6** Продолжить диалог в ветке (живой API):
```
Добавляем: оплата только криптовалютой
```

☐ **3.7** Переключиться на main:
```
/branch switch main
```
Ожидание: `[Ветки] Переключился на «main» (6 сообщений в ветке)`, приглашение —
`Вы [main]: `.

☐ **3.8** Спросить: `Какая оплата в нашем ТЗ?`
Ожидание: модель НЕ знает про криптовалюту — это сообщение осталось в ветке «вариант-б».

☐ **3.9** Переключиться обратно: `/branch switch вариант-б`, спросить то же.
Ожидание: модель знает про криптовалюту — ветки независимы.

☐ **3.10** Ввести `/branch list`.
Ожидание: три ветки, звёздочка у «вариант-б», у каждой — число сообщений и дата.

☐ **3.11** Проверить файлы веток:
```bash
ls Branches/ && cat Branches/main.json | head -8
```
Ожидание: отдельный JSON-файл на каждую ветку; внутри `name`, `created`, `parent`,
`messages`.

☐ **3.12** Проверить отказные случаи:
- `/branch switch несуществующая` → `[Ветки] Не удалось загрузить… Доступны: /branch list`;
- `/branch new main` → `[Ветки] Ветка «main» уже существует…`;
- `/branch` без аргументов → подсказка по формату.

☐ **3.13** Ввести `/exit`, затем запустить снова (3.1).
Ожидание: шапка показывает `Активная ветка: вариант-б` — активная ветка восстановилась
из снимка. Ввести `/exit`.

## Часть 4. Сравнение стратегий /compare-strategies (5 минут)

☐ **4.1** Запустить в любом режиме:
```bash
./den_10_run.sh --context sliding-window --memory session
```

☐ **4.2** Ввести `/compare-strategies`, на вопрос про живой прогон ответить `N`.
Ожидание: локальная оценка без API — три строки вида:
```
sliding-window: ~N токенов на последнем запросе; …ранние детали теряются из окна
facts:          ~N токенов …; факты обновляются автоматически…
branching:      ~N токенов …; полный контроль через /branch…
```
Плюс примечание про платные запросы обновления фактов. Порядок токенов:
sliding-window < facts < branching.

☐ **4.3** Ввести `/compare-strategies` ещё раз, ответить `y` (живой прогон, ~39 запросов).
Ожидание: последовательный прогон трёх стратегий (сообщения `[Контекст]… вышло из окна`,
`[Факты] Обновлено…`, `[Сжатие]…` — по режимам), затем таблица по 4 критериям:
- **КАЧЕСТВО** — три ответа на контрольный вопрос («аудитория и срок»);
- **СТАБИЛЬНОСТЬ** — `N/2 ключевых деталей`: у facts и branching ожидается 2/2,
  у sliding-window часто 0/2 или 1/2 (детали вытеснены);
- **РАСХОД ТОКЕНОВ** — у facts заметно больше остальных (платные обновления фактов);
- **УДОБСТВО** — по строке описания на каждую стратегию.

☐ **4.4** Ввести `/exit`.
