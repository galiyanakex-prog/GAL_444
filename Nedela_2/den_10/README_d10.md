# День 10 — Управление контекстом: разные стратегии (без summary)

> **Неделя 2** — «Инструментарий LLM: Агенты и их внутреннее устройство».
> День 10 — развитие агента Дня 9: не одна техника, а НАБОР стратегий + переключатель + сравнение.

## Суть проекта

Реализован CLI-чат-бот с LLM (RouterAI, модель `stepfun/step-3.5-flash`), который **управляет контекстом тремя разными стратегиями и переключается между ними**: Sliding Window (старое отбрасывается), Sticky Facts (блок фактов «ключ: значение», обновляемый после каждого сообщения), Branching (ветки диалога с checkpoint и переключением). Все три стратегии прогоняются на одном сценарии («собираем ТЗ, 12 сообщений») и сравниваются по 4 критериям: качество, стабильность, расход токенов, удобство.

База — `den_9_Kod.py` (День 9): токен-учёт, сжатие истории, `/compare`, снимок v3. Режимы `compression` и `leveling` сохранены (задание требует «минимум 3» стратегии — готовое не выбрасываем).

Ключевая идея дня: **«без summary» относится к трём обязательным стратегиям** — окно (старое удаляется), факты (старое сворачивается в key-value выжимку), ветки (старое разъезжается по независимым веткам). И урок, который обязан быть виден: **обновление фактов после каждого сообщения — дополнительный платный LLM-запрос**, его стоимость честно показывается в сравнении.

## Что нового относительно Дня 9

- **`--context facts` — Sticky Facts / Key-Value Memory**: блок `facts` (цель, ограничения, предпочтения, решения, договорённости) обновляется после КАЖДОГО сообщения пользователя служебным LLM-запросом «по шаблону» (Ч3: только новые/изменённые факты, пустой ответ — блок не меняется); в запрос идёт facts (system-сообщением) + последние N сообщений «сырыми» (Ч2 Ivan: окно не искажается); токены служебных запросов — в отдельный накопитель `facts_usage` (урок Ч8 Дня 9);
- **`--context branching` — ветки диалога**: checkpoint → ветки от одного места → независимое продолжение → переключение. Ветки хранятся в директории `Branches/` (каждая — отдельный JSON-файл с метаданными и сообщениями), активная ветка видна в терминале: приглашение `Вы [main]:` и строка шапки; `/branch list` — просмотр, `/branch switch <имя>` — переключение, `/branch new <имя>` — создание от текущего места;
- **`/compare-strategies` — ядро дня**: сценарий «собираем ТЗ» (12 сообщений, генерируются локально — детерминизм) прогоняется на каждой из трёх стратегий во временных агентах (артефакты в /tmp); печатается таблица по 4 критериям задания. Живой прогон — только после явного `y/N`; без него — локальная оценка токенов и описание механики;
- **`/facts`** — печать текущего блока фактов (режим facts);
- **Снимок v4**: + `facts`, `facts_usage`, `active_branch`, список веток (сами сообщения веток — в файлах `Branches/`, не дублируются); снимки v1–v3 грузятся без падения;
- **Исправлена автокоррекция памяти донора**: `session`-память больше не перебивает `context=facts|branching` (иначе новые стратегии было бы не запустить);
- **Токен-учёт, сжатие, `/compare`, `/compress on|off` Дня 9 сохранены полностью.**

## Команды

| Команда | Действие |

## Запуск

```bash
# Через скрипт (из любого каталога)
./den_10_run.sh

# Три обязательные стратегии дня:
./den_10_run.sh --context sliding-window --memory session
./den_10_run.sh --context facts --memory session
./den_10_run.sh --context branching --memory session

# Сравнение стратегий на сценарии «ТЗ» (внутри чата: /compare-strategies)
./den_10_run.sh --context sliding-window --memory session

# Сохранённые режимы Дней 6–9:
./den_10_run.sh --context compression --memory compressed
./den_10_run.sh --context leveling --memory layered
```

Флаги Дней 6–9 сохранены: `--window`, `--keep`, `--memory`, `--max-context-tokens`, `--max-tokens`, `--token-log`, `--price-in/--price-out`, `--compress-every`, `--summary-word-limit`, `--compress-temperature`.

## Механика трёх стратегий

```
Sliding Window:  [m1 m2 m3 m4 m5 m6] окно=4 → запрос: [m3 m4 m5 m6], m1 m2 УДАЛЕНЫ
Sticky Facts:    facts{цель: магазин, срок: 1 октября} + [m3 m4 m5 m6]  ← окно «сырое»
                 ↑ обновляется после каждого сообщения (служебный запрос)
Branching:       main: [m1 m2 m3] ──checkpoint──> variant-b: [m1 m2 m3, ...]
                 запрос = полная история АКТИВНОЙ ветки; /branch switch меняет историю
```

## Сравнение стратегий (результаты /compare-strategies)

Локальная оценка на сценарии «ТЗ» (12 сообщений, окно 4):

```
sliding-window: ~72 токенов на последнем запросе; ранние детали теряются из окна
facts:          ~98 токенов на последнем запросе; детали сохраняются, но каждый обмен дороже
branching:      ~203 токена на последнем запросе; полный контроль, переключение вручную
```

Живой прогон (заглушка API, порядок величин): sliding-window 1560 токенов, facts 3360 (удорожание — платные запросы обновления фактов), branching 1800.

**Выводы по 4 критериям:**

| Критерий | Sliding Window | Facts | Branching |
|---|---|---|---|
| Качество | теряет ранние детали | сохраняет ключевые | сохраняет всё в ветке |
| Стабильность | низкая на длинных диалогах | высокая (факты персистентны) | высокая внутри ветки |
| Расход токенов | минимальный | средний + платные обновления | зависит от длины ветки |
| Удобство | нулевая настройка | автоматическое | ручное управление |

## Что показал чат курса (уточнения к заданию)

- **Ч1** (Данил Котин + Алексей Гладков): «отбрасывание» = удаление из контекста, не сжатие; N — настраиваемый параметр → sliding-window донора;
- **Ч2** (Ivan Bazhenov): окно едет «сырым», обогащённым JSON фактов в том же промпте → facts отдельным system-сообщением перед нетронутым окном;
- **Ч3** (Dmitry Sevostianov): facts — «сухая выжимка по шаблону», обновлять только при появлении новых фактов → FACTS_PROMPT с правилом «верни только новые/изменённые; если новых нет — пусто»;
- **Ч4** (Алексей Гладков): факты «многие ко многим», не обязательно в одном месте → ℹ️ вариант развития (граф фактов/векторная БД), в код дня не внедрялось — «единственно верного решения нет».

## Общее с Днями 6–9

- API: RouterAI (OpenAI-совместимый), ключ в `.env` (переменная `API_KEY`);
- Retry при HTTP 429: до 3 попыток, задержка 2 → 4 → 8 сек; таймаут 30 сек;
- Ошибки API не прерывают цикл; непредвиденные — в `den_10_error.log` с ожиданием Enter;
- Уроки устойчивости: `sys.stdin.reconfigure(errors='replace')`, `try: import readline`, пути через `BASE_DIR`;
- Стиль: учебный однофайловый скрипт, комментарий почти к каждой строке; зависимости — только `requests`, `python-dotenv` и стандартная библиотека.

## Результат

- Агент с тремя обязательными стратегиями (Sliding Window / Facts / Branching) + переключатель `--context` (всего 5 режимов — сохранены compression и leveling);
- Facts: автообновление после каждого сообщения, «сырое» окно, честный учёт стоимости служебных запросов;
- Branching: ветки в `Branches/` (файл на ветку), активная ветка видна в терминале, `/branch list|switch|new`;
- `/compare-strategies`: сценарий «ТЗ» на каждой стратегии + таблица по 4 критериям задания;
- Снимок v4 с обратной совместимостью v1–v3; токен-учёт и сжатие Дня 9 сохранены.
