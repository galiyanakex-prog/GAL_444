**Цель.** Дать LLM возможность запрашивать инструменты: нативный OpenAI-совместимый
`tools`/`tool_calls` **и** детерминированный fallback-протокол.

---

## 1. Шаги этапа

### Шаг 5.1 — Расширение контракта (`core/llm_client.py`)
- Сохранить `complete(messages, **params) -> str` (обратная совместимость).
- Добавить опциональный путь: `complete(messages, tools=None, **params)` — если `tools`
  передан, вернуть **структурированный** результат (или отдельный метод `complete_with_tools`).
- Ввести носитель `LLMReply(content: str, tool_calls: list[dict], raw)`; tool_call:
  `{"id","name","arguments"(dict)}`.

### Шаг 5.2 — Нативный путь `RouterAIClient`
- При непустом `tools`: в `data` добавить `"tools": [...openai-формат...]`,
  `"tool_choice": "auto"`; разобрать `result["choices"][0]["message"]`:
  `content` + `tool_calls` (имя/аргументы JSON). Ошибки/таймауты → прежняя обработка
  (не ронять цикл).

### Шаг 5.3 — Fallback-протокол (детерминированный)
- Если нативный `tool_calls` пуст/недоступен, а `tools` задан: в системный промт
  добавляется инструкция вернуть ровно один JSON-объект
  `{"tool": "<name>", "arguments": {...}}` для вызова либо `{"final": "<текст>"}`.
- Код парсит ответ: JSON → `tool_calls` (или `content`). Невалидный JSON →
  трактуется как финальный текст (не падаем).
- Fallback включается флагом/эвристикой (например, отсутствие нативного `tool_calls`).

### Шаг 5.4 — `MockClient`
- Детерминированная поддержка tool-use: по ключевым словам намерения (например,
  «найди/город/Москва») возвращает tool_call на `search_locations` с `{"query":"Москва"}`;
  иначе — обычный текст (регрессия).

### Шаг 5.5 — Проверка
- Разбор нативного `tool_calls` (мок-ответ); fallback-разбор JSON; ответ без тулов —
  прежний текст; ошибки сети — `None`/текст (цикл жив).
