## 1. Шаги этапа

### Шаг 7.1 — Расширение `Agent.respond` (`core/agent.py`)
- Активируется только если каталог тулов непуст и тул-политика включена (иначе — прежний
  путь, регрессия).
- Цикл (лимит итераций, напр. ≤5):
  1. собрать промт с `[tools]` (доставка включает `tools`) + машинные `tool_specs`;
  2. `reply = llm.complete(messages, tools=specs)`;
  3. если `reply.tool_calls`: для каждого — `tool_executor.execute(...)` → добавить в
     `messages` tool-сообщение с результатом (по `tool_call_id`/имени);
  4. повторить; иначе — финальный `reply.content` → ответ.
- Защита от бесконечного цикла; ошибки исполнителя → сообщение об ошибке в цикле, не
  падение.

### Шаг 7.2 — Память (минимал)
- В `working_memory` — нормализованный `external_actions[]` (execution_id, tool, status,
  summary, at); **сырой** ответ — только текущий execution context (не в память).
- Секреты/полные аргументы — не сохранять.

### Шаг 7.3 — Аудит
- Каждая попытка вызова — `tool_audit.jsonl` (success/denied/failed) через `ToolExecutor`.
- Успех вызова **не** создаёт запись в `transition_log` (инструмент ≠ переход).

### Шаг 7.4 — Востановление совместимости
- Без `--mcp`/каталога `respond` работает как прежде (одноразовый LLM-ответ).
- Существующие сценарии/resume/инварианты — без изменений.

### Шаг 7.5 — Проверка
- MockClient: намерение «найди город Москва» → вызов тула → финальный ответ;
- policy-отказ → вызов не исполнен, аудит `denied`;
- без каталога → прежнее поведение.
