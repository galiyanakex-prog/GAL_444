половину нового» каталога). Реестр **не проверяет бизнес-правила** и **не вызывает**
`StateMachine`.

## 2. Шаги этапа (исполняемый алгоритм)

### Шаг 2.1 — Каркас `ToolRegistry`
1. `core/tool_registry.py`: класс `ToolRegistry` с полями `_providers: dict[str,
   ToolProvider]`, `_current_snapshot: ToolCatalogSnapshot` (начальный — пустой,
   version=0), `_version: int = 0`.
2. Методы: `add_provider(provider)` (повторный `provider_id` → замена с логом),
   `unregister_provider(provider_id)`, `get(name) -> ToolDescriptor` (неизвестное
   имя → `KeyError` с понятным сообщением и списком доступных), `available_for(
   context=None) -> list[ToolDescriptor]` (задел: пока возвращает все тулы текущего
   snapshot), `snapshot() -> ToolCatalogSnapshot` (текущий, без пересборки),
   `refresh() -> ToolCatalogSnapshot`.
3. **Ожидаемый результат:** API по arch §2.3 построчно.

### Шаг 2.2 — Механика `refresh()` (атомарность)
1. `discover()` у всех зарегистрированных провайдеров; исключение провайдера →
   его тулы **исключаются** из нового snapshot, ошибка логируется (print/log),
   остальные провайдеры не страдают.
2. Валидация схем (JSON Schema-примитивы): `input_schema` — dict с `type`
   (object) и опциональными `properties`/`required`; невалидная схема → тул
   исключается + лог (не падение).
3. Разрешение коллизий: квалифицированные имена `mcp.<server>.<tool>` /
   `local.<tool>`; дубликаты квалифицированных имён → последний побеждает + лог
   (коллизия — сигнал конфигурации, не ошибка рантайма).
4. Сборка нового `ToolCatalogSnapshot` (`version` — монотонный счётчик
   `self._version += 1`; `created_at` — ISO-время) → **атомарный swap**
   `self._current_snapshot = new_snapshot` (одна операция присваивания; между
   сборкой и swap читатели видят старый snapshot целиком).
5. **Ожидаемый результат:** refresh атомарен; version монотонный; «половинного»
   каталога не бывает.

### Шаг 2.3 — Заглушечный провайдер для смоука (в смоук-скрипте, не в продукте)
1. `class StubProvider(ToolProvider)`: фиксированный список из 2–3 тулов
   (`local.echo`, `local.time`), программируемый отказ (`discover` → raise) и
   невалидная схема — для проверки веток реестра.
2. **Ожидаемый результат:** реестр проверяется без MCP и без сети.

### Шаг 2.4 — Примитив-смоук этапа (инлайн, `.tmp/`)
```bash
python - <<'EOF'
# 1. add_provider(StubProvider) → refresh() → snapshot содержит local.echo/local.time
# 2. get("local.echo") → ToolDescriptor; get("nope") → KeyError с сообщением
# 3. коллизия: два провайдера с одинаковым квалифицированным именем → лог, один тул
# 4. невалидная input_schema → тул исключён, остальные живы
# 5. провайдер с discover→raise → его тулы исключены, остальные живы, refresh не падает
# 6. атомарность: version монотонный (1,2,3...); snapshot() между refresh — старый целиком
# 7. unregister_provider → refresh → тулы покинули каталог
# 8. available_for() → все тулы snapshot (задел фильтров)
EOF
```
**Ожидаемый результат:** все блоки OK, EXIT 0.

### Шаг 2.5 — Проверка границ реестра
1. `grep -n "state_machine\|StateMachine\|import mcp" core/tool_registry.py` → пусто
   (реестр не контролирует и не импортирует SDK).
2. **Ожидаемый результат:** границы чистые.

### Шаг 2.6 — Регрессия
1. L1 → ok (включая новый модуль); L2 → **91 OK, 0 FAIL**; L3/L4/гейт — без
   изменений (13+2⚠).
**Ожидаемый результат:** полная нерегрессия.

## 4. Автоматический гейт M2→M3

Гейт считается **зелёным**, если одновременно:
- [ ] API реестра соответствует arch §2.3 (add/unregister/get/available_for/
      snapshot/refresh);
- [ ] refresh атомарен: version монотонный; snapshot() между refresh возвращает
      старый каталог целиком;
- [ ] коллизии имён разрешаются квалификацией; дубликат → лог, не падение;
- [ ] невалидная схема → тул исключён, остальные живы;
- [ ] недоступный провайдер → его тулы исключены, остальные живы, refresh не падает;
- [ ] unregister → тулы покидают каталог при следующем refresh;
- [ ] `get()` неизвестного имени → понятная ошибка;
- [ ] реестр не импортирует `mcp`/`state_machine` (grep);
- [ ] L1 зелёный; L2 **91 OK, 0 FAIL**; L3/L4/гейт — без изменений.

**Зелёный** → запись M2 в `migr_log.md` (✅) → **перечитать `migr_plan.md`** →
создать `migr_plan_3.md`.
**Красный** → карточка ошибки, этап M2 открыт.
