## Сценарий 2 — Тот же путь в REPL + хранение снимка каталога

**Цель демонстрации:** показать тот же путь через интерактивный контур
(**подключение → refresh → список → статус → закрытие**) и что снимок каталога
хранится в **штатной** базе пользователя и **переживает перезапуск**.

**Формат отчёта:** живой ручной прогон, чек-лист отмечается ☐ / ✅ / ❌.

**Запуск:**
```bash
cd "$KOD"
./run.sh --user demo16 --mcp
```
> Ожидание: инициализация/интервью нового `demo16` (при первом запуске) + активный
> MCP-слой; приглашение `Вы [Основная_задача]:`. Ответы даёт **живой** LLM RouterAI
> (ключ из `.env`).

**Шаги:**
1. Собрать каталог и получить список инструментов:
   ```
   /mcp refresh
   /mcp tools
   ```
2. Посмотреть состояние подключения и серверы:
   ```
   /mcp status
   /mcp servers
   ```
3. Проверить снимок каталога на диске (штатная база):
   ```bash
   find users/demo16 -path '*integrations/mcp*' -type f | sort
   $PY -c "import json;d=json.load(open('users/demo16/integrations/mcp/catalog.json'));print('schema',d['schema_version'],'version',d['version'],'tools',[t['name'] for t in d['tools']])"
   ```
4. Закрыть соединение и выйти:
   ```
   /mcp disconnect
   /exit
   ```

**Ожидаемый вывод:**
- `/mcp refresh` → `[MCP] Каталог обновлён: 4 тулов (версия N); серверы READY: ['time', 'weather']; снимок сохранён (catalog.json)`;
- `/mcp tools` → `[MCP] Доступные инструменты (каталог vN):` и те же **4 тула**

  даёт версию 2, 3, …);
- `/mcp status` → `[MCP] Общее состояние: ready`, строки `time: ready`, `weather: ready`,
  `scheduler/pipeline/demo: disconnected`, `Каталог инструментов: версия N, тулов: 4`;

- `catalog.json` → `schema_version 1`, ненулевая `version`, четыре имени `mcp.*`;
- `/mcp disconnect` → `[MCP] Соединения закрыты (DISCONNECTED).`;
- `/exit` → `[Выход] Состояние сохранено. До встречи!`

> *(Примечание: `servers.json` в базе не создаётся автоматически — при отсутствии файла
> работает дефолтный конфиг; файл появляется только если его положить руками, см. 3.1.)*

**Как это устроено (код):**
- CLI-команды MCP-слоя: `/mcp connect|refresh|tools|status|servers|disconnect` в `Kod.py`

## Сценарий 3 — Изоляция прав, деградация и регрессия

**Цель демонстрации:** показать, что права сервера ограничиваются на уровне
**discovery** (`denied_tools`), при сбое MCP агент **деградирует, а не падает**,
и что без `--mcp` поведение агента = предыдущий день (MCP-слой не собирается).

**Формат отчёта:** живой ручной прогон, чек-лист отмечается ☐ / ✅ / ❌.

**Запуск:**
```bash
cd "$KOD"
./run.sh --user demo16 --mcp        # шаги 3.1–3.3
./run.sh --user demo16              # шаг 3.4 (регрессия)
```

**Шаги:**
1. Ограничить права сервера (создать `servers.json` в формате загрузчика —
   `{"servers": [ … ]}`) и проверить фильтр:
   ```bash
   mkdir -p users/demo16/integrations/mcp
   cat > users/demo16/integrations/mcp/servers.json <<JSON
   {
     "servers": [
       {
         "server_id": "time",
         "transport": "http",
         "endpoint": "http://91.188.212.77:8000/mcp",
         "enabled": true,
         "trust_level": "low"
       },
       {
         "server_id": "weather",
         "transport": "http",
         "endpoint": "https://weatherapi.projecteol.ru/mcp/",
         "enabled": true,
         "trust_level": "low",
         "denied_tools": ["get_weather_forecast"]
       }
     ]
   }
   JSON
   ```
   Затем в REPL: `/mcp refresh` → `/mcp tools`.
2. Вернуть конфиг в исходный и убедиться, что агент жив при сбое MCP:
   ```bash
   rm -f users/demo16/integrations/mcp/servers.json   # снова дефолтный конфиг
   ```
   В REPL выполнить `/mcp connect откуда_то` (несуществующий сервер).
3. Регрессия: запустить **без** `--mcp` и вызвать MCP-команду:
   ```
   ./run.sh --user demo16
   /mcp status
   ```

**Ожидаемый вывод:**
- шаг 1: в списке **три** тула (`mcp.time.get_time`, `mcp.weather.search_locations`,
  `mcp.weather.get_forecast_metadata`), `get_weather_forecast` **исключён** —
  запрещённый тул не попадает в discovery (изоляция прав через тулинг);
- шаг 2: понятное сообщение `[MCP] Сервер «откуда_то» не найден. Сконфигурированы: time, weather`;
  при недоступном MCP-сервере статус `failed`/`degraded`, тулов нет, но REPL жив —
  память, профили и машина состояний продолжают работать (деградация, не падение);
- шаг 3: `[MCP] MCP-слой выключен (запустите с флагом --mcp).`

**Как это устроено (код):**
- конфиг серверов: `users/<user_id>/integrations/mcp/servers.json`
  (`server_id`, `transport`, `command`/`endpoint`, `enabled`, `trust_level`,
  `allowed_tools`/`denied_tools`) — при отсутствии файла работает дефолтный конфиг;
- фильтр прав применяется при сборе каталога (`/mcp refresh` → `/mcp tools`);
- флаг сборки MCP-слоя: `--mcp` (`Kod.py` / `./run.sh`).

**Чек-лист-итог (сценарий 3):**
| Пункт | Что проверяем | Как | Статус |
|---|---|---|---|
| 3.1 | Права сервера задаются конфигом (`servers.json`) | файл принят загрузчиком, `/mcp refresh` проходит | ☐ |
| 3.2 | Изоляция прав: `denied_tools` режет discovery | `/mcp tools` → 3 тула, `get_weather_forecast` исключён | ☐ |
| 3.3 | Возврат к дефолтному конфигу | `rm servers.json` → снова 4 тула | ☐ |
| 3.4 | Понятная ошибка на неизвестном сервере | `/mcp connect откуда_то` → «Сервер «откуда_то» не найден. Сконфигурированы: time, weather» | ☐ |
| 3.5 | Деградация без падения REPL | статус `failed`/`degraded`, тулов нет; память, профили, машина состояний работают | ☐ |
| 3.6 | Регрессия: MCP **off** по умолчанию | без `--mcp` → «MCP-слой выключен», поведение = предыдущий день | ☐ |
