## Шаги

### ШАГ 6.1 — Датасет (один и тот же для обоих режимов)

`rag/datasets/queries.jsonl` — 10 контрольных вопросов (с `expect`/`relevant`/`must_contain`).
Если контрольных меньше 10 — дополнить (это вход для сравнения).

### ШАГ 6.2 — Команда сравнения

```bash
.venv/bin/python Kod.py --rag-gen-compare \
  --gen-modes cloud,local --repeat 3 \
  --gen-report dev/logs_reports/stages/rag_local_compare.md
```

> **Уточнение реализации (этап 6).** Клиентов строит `Kod.py` (граница §5: `rag/`
> не импортирует `core/`), поэтому сравнение генераторов запускается из `Kod.py`,
> а не из `python -m rag.compare`. В `rag/compare.py` добавлены
> `compare_generators(cfg, queries, generators, k, repeat)` и
> `render_generator_report(result)`; `generators` — dict `{имя: callable(messages)->str}`
> (DI). `cloud` = облачный `llm`, `local` = локальный `llm` из `ModelRegistry`;
> различается **только** генератор. `python -m rag.compare --modes cloud,local`
> печатает подсказку и не запускает прогон (клиентов там нет).

### ШАГ 6.3 — Метрики (три оси)

- **качество:** `must_contain`-покрытие, наличие и валидность ссылок, `grounding.verdict`,
  hit-rate@5 retrieval (одинаков для обоих);
- **скорость:** ttft/полная латентность, медиана и p95 по `--repeat 3`, токены/с;
- **стабильность ответов:** доля ответов с ошибкой/пусто/таймаутом, **дисперсия** латентности,
  совпадение факта в 3 повторах одного вопроса (самопротиворечивость).

### ШАГ 6.4 — Обязательный вывод отчёта

Таблица «вопрос × (cloud / local)», сводка по трём осям, **вердикт** (где локальная не хуже /
хуже и почему), разбор 3 расхождений.

### ШАГ 6.5 — Тесты + запись в журнал

- Тесты: парсер отчёта и агрегация метрик на фиксированных данных; сравнение воспроизводимо
  (одинаковый вход → одинаковая сводка).
