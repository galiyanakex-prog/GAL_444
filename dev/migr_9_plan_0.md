## 5. Шаги

### 0.1. Перечитать мастер-план и журнал — Исполнитель

Действие: прочитать `dev/migr_9_plan.md` целиком и раздел этапа 0 журнала.
Ожидаемый результат: известны границы, гейт, запретные зоны.
Фиксация: дата и редакция мастер-плана в журнале.

### 0.2. Инвентаризация только чтением — Исполнитель

Действие: собрать дерево значимых путей (`cli`, `core`, `mcp`, `rag`, `storage`,
`tests`, `dev/tests_debug`), список модулей, текущие контракты `TaskStage`,
`InvariantChecker`, `MemoryManager`, `StateMachine`, наличие `session_log.py`.
Ожидаемый результат: `$LOGS/baseline_inventory.txt` с путями и краткими фактами.
Проверка: файл существует, пути резолвятся; в файле нет содержимого секретов.
Ветвление: путь не найден → зафиксировать как «отсутствует», не создавать.

### 0.3. Прогон текущего набора тестов — Исполнитель

Действие: запустить существующий тестовый раннер (какой именно — определить по
репозиторию, не изменяя его), зафиксировать вывод.
Команда → ожидаемый вывод → чем проверить: `python3 -m pytest -q` (или
`dev/tests_debug/*_runner.py`, если pytest не настроен) → сводка pass/fail → код
возврата и повторный прогон.
Ожидаемый результат: `$LOGS/baseline_tests.txt`; таблица «набор → passed/failed/skip,
время».
Ветвление: тесты падают → зафиксировать как есть (это базовая линия, не дефект
этапа); набор отсутствует → С-3 и запись.

### 0.4. Замер промпта и бюджетов — Исполнитель

Действие: найти сборку промпта; измерить размер целевым токенизатором (если
токенизатор недоступен — символами/словами с пометкой метода).
Ожидаемый результат: `$LOGS/baseline_prompt.txt`: блок → размер, общий размер, метод.
Ветвление: токенизатор не найден → измерить приближённо, пометить «оценка», внести
в O-5.

### 0.5. Зафиксировать базовую линию — Исполнитель

Действие: заполнить мастер-план §3 (факты среды) и журнал этапа 0 числами из 0.2–0.4;
создать таблицу эталонных значений «сущность → значение → где встречается».
Ожидаемый результат: числа воспроизводимы, у каждого есть путь к артефакту.
Проверка: повторный запуск 0.3 даёт те же числа (допуск — время выполнения).
Ветвление: числа расходятся → зафиксировать расхождение, не усреднять.

### 0.6. Запись в журнал и передача — Исполнитель

Действие: заполнить раздел этапа 0 журнала: было/стало, команды, КП, артефакты с
путями, регрессия, гейт, следующий шаг; перечитать мастер-план; предложить текст
фиксации.
Ожидаемый результат: запись в журнале; предложенный текст коммита (выполняет
оператор): `docs(r9): add baseline measurements`.
Фиксация: отметка перечитывания (дата, v0.1).
