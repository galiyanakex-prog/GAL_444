## 5. Шаги

### 8.1. Инвентаризация генерации — Исполнитель

Действие: найти текущий путь генерации кода и сборки контекста; выписать точки
записи.
Ожидаемый результат: `$LOGS/s8_generation_inventory.txt`.
Проверка: каждая точка записи идёт через propose/apply.

### 8.2. `FileOperation` и шаг плана — Исполнитель

Действие: `PlanStep` → `FileOperation` (`operation_id`, `action`, `path`,
`expected_hash`, `content`, `reason`); операция не исполняется без proposal.
Ожидаемый результат: каждая операция прослеживается до шага плана.
Проверка: операция без `PlanStep` отклоняется.

### 8.3. Контекст и патч — Исполнитель

Действие: сборка контекста по приоритету: структура → релевантные файлы → нужные
диапазоны строк → краткие фрагменты; `FileContextBudget`; патч вместо полной
перезаписи; контроль области (workspace scope, forbidden files, лимит diff).
Ожидаемый результат: diff не выходит за разрешённые файлы и размер.
Проверка: файл вне scope → отказ; diff > лимита → отказ.

### 8.4. Validator и Test Report — Исполнитель

Действие: проверки compile/import, unit, integration, lint, format, type check,
docs links, requirements coverage, security rules; только ограниченные команды
(`run_python_tests`, `run_py_compile`, `run_ruff`, `run_mypy` или эквиваленты);
`max_fix_attempts = 3`; Test Report: summary, checks table, failures, warnings,
coverage.
Ожидаемый результат: сломанный файл даёт красный отчёт; после исправления — зелёный;
попытки ограничены.
Проверка: парная проверка на демо-проекте.

### 8.5. AI Code Review — Исполнитель

Действие: 4 категории (баги, архитектура, безопасность, качество); `ReviewFinding`
с severity, файлом, строкой, рекомендацией; вывод не содержит секретов.
Ожидаемый результат: findings структурированы и воспроизводимы.
Проверка: фикстура с намеренным дефектом → finding; секрет в коде → finding без
раскрытия значения.

### 8.6. Тесты L1–L4 и безопасность — Исполнитель

Действие: оформить уровни тестов; добавить проверки oversized file/diff,
unapproved write, tool substitution, replay approval, secret read; прогнать базовый
набор.
Ожидаемый результат: каждый уровень имеет команду и отчёт.
Проверка: тесты красные до правки и зелёные после.

### 8.7. Журнал и передача — Исполнитель

Действие: заполнить журнал; перечитать мастер-план; коммит
`feat(pipeline): add stepwise generation, validator and AI review`.
