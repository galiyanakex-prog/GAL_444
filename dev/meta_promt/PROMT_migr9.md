## 3. БЮДЖЕТ КОНТЕКСТА — главное правило (введено оператором)

**Суммарный объём информации, читаемой + обрабатываемой + генерируемой на ОДНОМ шаге,
не должен превышать 100 000 токенов.** Плановая норма — **≤ 80 000** (запас на правки).

Обязательные правила:

- **Р1.** Рабочий план этапа (`migr_9_plan_N.md`) должен быть ≤ ~12k токенов.
- **Р2.** На один шаг — **не более одного крупного документа целиком**. Крупные
  (`README.md` ~45–55k, `Plan_N7.txt` ~55–70k, `migr_plan.md` ~35–45k) читать **по разделам**
  через `read_file` с `offset/limit`.
- **Р3.** Если шаг требует > 3 крупных артефактов или прогноз > 80k — **дробить шаг**.
- **Р4.** Код читать **точечно** (`search_file_content`, `read_file` с offset/limit);
  целиком — только малые модули (< ~300 строк).
- **Р5.** Каждый шаг рабочего плана обязан содержать поле **«Бюджет»** (вход + обработка +
  выход ≤ 100k) и перечень входов с оценкой токенов.
- Каждый завершённый шаг фиксируется в `dev/migr_log.md` **с фактическим бюджетом**.

> Помни: `README.md` и `Plan_N7.txt` вместе ≈ 100–125k → одновременно в одном шаге
> их читать НЕЛЬЗЯ.

## 4. Железные правила процесса

- **`git` — только оператор.** Ты не выполняешь `git add/commit/checkout/reset/push` и
  иных изменяющих `git`-команд. Ты готовишь правки/патчи/diff и **предлагаешь текст
  коммита**; коммитит оператор.
- **Код и историю git читай только когда это реально нужно шагу** (на этапе создания
  мастер-плана — не читать; при выполнении этапов — точечно).
- **Регрессия запрещена:** без новых флагов/команд поведение и промпт прежние; база
  (этап 0) обязана оставаться зелёной на каждом этапе.
- **Контракты не меняются:** `LLMClient.complete`, `PromptBuilder.build`, `ToolDescriptor`,
  `RagService`, `TaskStage` — только расширение.
- **`MCP ≠ переход`:** ни MCP, ни RAG, ни файловые операции не меняют `TaskStage`/`DevelopmentStage`.
- **Наименьшие привилегии:** запись только в разрешённый workspace; запрет чтения
  `.git/.env/ssh/secrets/users`; `delete`/произвольный `shell` в MVP запрещены.
- **Опасные действия (HIGH/CRITICAL): write/commit/push/merge/deploy — только после
  exact-action approval** (hash действия, actor, срок, одноразовость). Сам ты PR не
  merge-ишь и не деплоишь.
- **Секреты:** только в `.env`/скрытых файлах; в конфигах, логах, транскриптах — нет
  (проверяется гейтом).
- **Тесты — без сети:** `unit_runner.py`, `smoke.py`, `scenario.py`, `dialog_runner.py`,
  `check_acceptance.sh`; заглушки `MockClient`/`FakeMCPTransport`. Живой прогон обязателен
  там, где есть живая проверка (гейт на заглушках = красный).
- **Временные файлы — только `dev/tests_debug/.tmp/`;** каталог `users/` тестами не трогается.
- **Один этап = один рабочий план = один гейт.** Вначале каждого этапа — **перечитать
  `migr_9_plan.md`**.
- **Расширяй, не переписывай** ядро Ревизии 8.
