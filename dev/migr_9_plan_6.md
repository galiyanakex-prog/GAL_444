## 5. Шаги

### 6.1. Инвентаризация знаний — Исполнитель

Действие: собрать существующие README/Wiki/RAG-источники, их статус и покрытие.
Ожидаемый результат: `$LOGS/s6_docs_inventory.txt`: тема → файл → статус.
Проверка: нет секретов; пути резолвятся.

### 6.2. Продуктовая рамка — Исполнитель

Действие: `docs/product_goal.md` (цель, пользователь, результат),
`docs/product_scope.md` (MVP/R2/R3, что не делаем), `docs/roadmap.md`.
Ожидаемый результат: три файла с проверяемыми границами; R2/R3 не выдаются за MVP.
Проверка: каждое утверждение имеет источник или помечено как задел.

### 6.3. Wiki и ADR — Исполнитель

Действие: `docs/WIKI.md` + 15 страниц (обзор, архитектура, память, профили,
состояния, инварианты, MCP, RAG, инструменты, CLI, storage, тестирование, деплой,
безопасность, Developer Factory); стандарт страницы (заголовок + 9 разделов);
`ADR-001-workspace`, `ADR-002-approval-model`, `ADR-003-project-scoped-rag`,
`ADR-004-file-tools`.
Ожидаемый результат: все ссылки резолвятся; у каждой страницы есть owner/status.
Проверка: `check_docs_links.py` (создаётся на этапе 10; здесь — ручная проверка или
временный скрипт в `$WORK/tools`).

### 6.4. README — Исполнитель

Действие: краткое описание, возможности, быстрый запуск, ссылка на Wiki.
Ожидаемый результат: README не дублирует Wiki; команды запуска проверены.
Проверка: запуск по инструкции в offline-профиле.

### 6.5. Project RAG — Исполнитель

Действие: scopes `global` (Wiki, README, архитектура AI_9) и `project` (код, тесты,
требования проекта); метаданные `scope`, `kind`, `module`, `language`, `project_id`;
инкрементальная индексация только изменённых документов; разные запросы по стадиям;
типы запросов: архитектурный, проектный, требовательный, операционный, проверочный.
Ожидаемый результат: project-запрос не отдаёт global-документы как project.
Проверка: фикстура с двумя корпусами, проверка метаданных и выдачи.

### 6.6. Project MCP read-only — Исполнитель

Действие: инструменты `get_git_branch`, `get_git_status`, `get_git_diff`,
`list_project_files`, `read_project_file`, `search_project`; лимиты
`max_file_bytes=1M`, `max_diff_bytes=5M`, `max_search_results=200`;
`allowed_tools`/`denied_tools`; матрица доступности по стадиям.
Ожидаемый результат: запись через MCP невозможна; лимиты срабатывают.
Проверка: попытка записи → отказ; файл > 1M → отказ.

### 6.7. `ProjectContext`, `/help`, тесты — Исполнитель

Действие: контекст проекта для CLI; `/help` показывает проектные команды; прогнать
RAG/MCP/документацию; заполнить журнал; перечитать мастер-план; коммит
`docs(r9): add product frame, wiki/ADR, project RAG and read-only MCP`.
