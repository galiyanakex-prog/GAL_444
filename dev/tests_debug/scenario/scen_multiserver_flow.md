# Сценарий «День 20 — Мультисерверный длинный флоу (D3, Ревизия 5)»

> Назначение: исполняемое доказательство пункта «Проверьте» из `Задание_d20.txt`:
> инструменты с **разных** MCP-серверов, **корректный выбор и порядок** вызовов,
> **без лишних** вызовов. Два зеркальных прогона: детерминированный (L4) и живой (VPS).

## Участники

| Сервер | Транспорт | Инструменты (в флоу) |
|---|---|---|
| `time` :8000 | HTTP | `get_time` |
| `pipeline` :8020 | HTTP | `search` → `summarize` → `saveToFile` |
| `scheduler` :8010 | HTTP | `schedule_reminder` |

Плюс `weather` :внешний (не участвует в цепочке — проверка «без лишних вызовов»).

## Ожидаемая цепочка (порядок обязателен)

```
1. mcp.time.get_time              (time)       — «свежие данные»: время
2. mcp.pipeline.search            (pipeline)   — шаг 1 пайплайна: получить данные
3. mcp.pipeline.summarize         (pipeline)   — шаг 2: обработать
4. mcp.pipeline.saveToFile        (pipeline)   — шаг 3: сохранить
5. mcp.scheduler.schedule_reminder(scheduler)  — напоминание о свежей сводке
```

Никаких прочих инструментов (11 из 15 каталога не вызываются).

## Инварианты сценария

- **Выбор инструмента** — по квалифицированному имени `mcp.<server>.<tool>`.
- **Маршрутизация** — каждый вызов уходит на СВОЙ транспорт (`provider`).
- **Порядок** — строго равен ожидаемому; запись ведётся обёртками транспортов.
- **Без лишних** — число «invoked»-записей аудита == 5.
- **Инструмент ≠ переход** — `TaskStage` после флоу не изменился.
- Нет захардкоженной последовательности в продукте: клиент (LLM) выбирает шаги,
  продукт лишь маршрутизирует.

## Детерминированный прогон (L4)

```bash
API_KEY=test-key .venv/bin/python dev/tests_debug/scenario.py
# → [scenario] D3: мультисерверный длинный флоу (... ) OK
```

`(server, tool)`), программируемый `ScriptedClient`.
