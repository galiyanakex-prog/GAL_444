# Сценарий ручной демонстрации «Ревизия 6 — RAG-модуль (`rag/`)»

> Назначение: показать куратору выполнение требований `Задание_d21.txt` в живом
> контуре — **настоящий** корпус, **настоящие** локальные эмбеддинги (Ollama
> `bge-m3`), **настоящий** гибридный поиск, **настоящий** блок `[rag]` в промпте
> со ссылками и **настоящая** проверка опоры ответа (grounding).
> Время: 7–10 минут. Файл — артефакт процесса, живёт только в `dev/`.

## Реквизиты

- Терминал в корне проекта, venv активирует обёртка сама.
- **Ollama** установлен и слушает только `127.0.0.1:11434`; модель `bge-m3` подтянута
  (`ollama pull bge-m3`). Проверка: `curl -s http://127.0.0.1:11434/api/tags`.
- **Живой режим** (нагляднее): ключ LLM в `.env` (`API_KEY`) — для ответов со ссылками
  и авто-перегенерации grounding. `/rag`-команды и `--rag-search`/`--rag-eval`/
  `--rag-compare` токенов LLM **не** тратят.
- **Запасной режим** (без LLM): `--mock` — блок `[rag]` и `/rag`-команды работают,
  ответы — заглушка MockClient.
- Демо-пользователь — свежий (`demo`), чтобы показать интервью и создание дерева с нуля.

## Шаг 1. Индексация корпуса (одна команда)

```bash
./run.sh --rag-ingest
```

**Увидите:** дельту индексации и число чанков.

```
[RAG] Индексация завершена: +0 новых, ~0 изменённых, -0 удалённых, =9 без изменений
[RAG] Чанков в индексе: 110; эмбеддингов запрошено: 0; время: 0.029s
[RAG] Индекс сохранён: …/rag/index
```

> Первый прогон на чистом индексе: `+9 новых`, эмбеддингов запрошено ~110 (bge-m3).
> Повторный — `=9 без изменений`, 0 эмбеддингов (инкрементальность).

## Шаг 2. Поиск без LLM: `--rag-search`

```bash
./run.sh --rag-search "как запретить агенту менять технологический стек проекта"
```

**Увидите:** топ-5 источников со скорами и метаданными (`source`, `section`, `chunk_id`).

```
[RAG] Запрос «…» (режим hybrid): Найдено источников: 5
  1. [5a49d570…#5a49d570…#0] core/invariants.py · раздел: … · score=0.0179
  2. [5a49d570…#5a49d570…#7] core/invariants.py · раздел: … · score=0.0174
  …
```

> Скоры объяснимы: в `scores` видны `bm25_rank`, `dense_rank`, `rrf`, `rerank`.

## Шаг 3. REPL-демо: вопрос → источники → ответ со ссылками

```bash
./run.sh --rag --user demo
```

В REPL:

```
как запретить агенту менять технологический стек проекта
```

**Увидите:**

- строку режима: `[Режим] RAG: включён (hybrid, топ-5), в промпт подмешивается; … grounding: strict`;
- в промпте блок `[rag]` **после** `[tools]` и **до** `[long_term]`;
- в логе `[RAG] запрос «…» → 5 ист. (режим=hybrid, … мс)` со скорами;
- ответ агента со ссылками вида `[doc_id#chunk_id]`.

> Без `--rag` блок `[rag]` в промпт не попадает, `rag` не импортируется вовсе.

## Шаг 4. Команды `/rag` (без LLM)

```
/rag status
/rag find как считается бюджет токенов промпта
/rag check Инварианты запрещают менять стек [<doc_id>#<chunk_id>].
/rag stats
```

**Увидите:**

- `/rag find` — топ-5 со скорами (задаёт «последние источники» для `/rag check`);
- `/rag check` — вердикт grounding (`ok`/`partial`/`hallucination`), покрытие,
  число ссылок (битых), числа вне источников;
- `/rag stats` — индекс, модель, размер, RAM, кэш (хиты/промахи/TTL), латентность
  p50/p95, состояние Ollama.

## Шаг 5. Метрики и сравнение стратегий

```bash
./run.sh --rag-eval
./run.sh --rag-compare
```

**Увидите:**

- `--rag-eval`: `recall@k`, `hit_rate@k`, `mrr`, `ndcg@k`, латентность p50/p95
  (на golden-датасете `rag/datasets/queries.jsonl`, 24 запроса);
- `--rag-compare`: таблицу «стратегия × режим» с вердиктом и разбором расхождений;
  гибрид ≥ каждой компоненты.

## Шаг 6. Grounding: ловим галлюцинацию

В REPL после обычного вопроса (или через `/rag check`) подайте ответ с выдуманным
числом, которого нет в источниках:

```
/rag check Метод предложили в 1994 году и он даёт точность 99.9% [<doc_id>#<chunk_id>].
```

**Увидите:** `Вердикт: hallucination`, `числа вне источников: 1994, 99.9`.

> В режиме `strict` при обычном ответе агента такая ситуация запускает **одну**
> авто-перегенерацию с фидбэком; при повторном провале — явная пометка в ответе.

## Ожидаемый итог

- Индекс строится одной командой, переживает перезапуск, обновляется инкрементально.
- Поиск гибридный, объяснимый; обе стратегии чанкинга дают разное разбиение.
- Блок `[rag]` в промпте со ссылками; без `--rag` промпт байт-в-байт прежний.
- Grounding ловит выдуманные числа; `TaskStage` не затронут; сеть — только localhost.
