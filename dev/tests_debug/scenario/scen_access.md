# Сценарий ручной демонстрации «Часть 5 — доступ извне: фасад, туннель, шлюз, устойчивость»

> Назначение: показать куратору **часть 5** `ND/tasks/n_6/Задание.txt` в живом контуре:
> домашний агент доступен извне **приватно** (вход по логину/паролю), через VPS с белым
> IP, без открытия домашней сети; канал переживает обрыв; запросы идут под лимитами.
> Время: 10–15 минут. Файл — артефакт процесса, живёт только в `dev/`.

## Топология

```
интернет ──► VPS:8080 (шлюз, Flask) ──► VPS:127.0.0.1:8090
                                              ▲
                                    SSH reverse tunnel (с хоста)
                                              │
                              хост:127.0.0.1:8090 (фасад serve.py) ──► агент (Kod.py)
```

- Наружу открыт **только** порт `8080` шлюза. Фасад (`8090`) слушает **только loopback**.
- Путь наружу — **SSH reverse tunnel** (WireGuard не применяется, проброс портов не нужен).
- MCP-серверы на VPS (`:8000/:8010/:8020`) **не трогаются**.

## Реквизиты

- **На хосте:** LM Studio `127.0.0.1:1234` (боевая 3B); фасад `serve.py`
  (`127.0.0.1:8090`); юнит туннеля `ai9-tunnel.service` (на **хосте**, `Restart=always`).
- **На VPS:** юнит шлюза `ai9-gateway.service` (`:8080`); venv `/home/t/doc/.venv`.
- Внешнее устройство — телефон/другой компьютер с обычным интернетом.

## Шаг 1. Поднять фасад на хосте (loopback)

```bash
python serve.py            # слушает 127.0.0.1:8090
curl -s -o /dev/null -w "facade=%{http_code}\n" "http://127.0.0.1:8090/state?user=probe"
```

**Увидите:** `[Фасад] слушает http://127.0.0.1:8090 …`; проверка → `facade=200`.

> Фасад **тонкий**: ноль бизнес-логики; удаление `serve.py` не меняет терминального агента.

---

## Шаг 2. Туннель: авторестарт (устойчивость канала)

```bash
systemctl --user is-active ai9-tunnel      # → active
systemctl --user show ai9-tunnel -p MainPID --value   # PID
kill <MainPID>                             # «роняем» канал
sleep 12
systemctl --user is-active ai9-tunnel      # → active (systemd поднял сам)
systemctl --user show ai9-tunnel -p MainPID --value   # новый PID
```

**Увидите:** через ~5–12 секунд канал восстановлен, PID сменился.

```bash
ssh mcp-vps 'curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8090/state?user=probe'
# → 200 (туннель снова работает)
```

> Юнит содержит `-o ControlMaster=no -o ControlPath=none` — туннелю нужна собственная
> SSH-сессия (иначе конфликт с общим мультиплексированным каналом).

## Шаг 3. Публичный шлюз отвечает

```bash
curl -s -o /dev/null -w "public / -> %{http_code}\n"     http://91.188.212.77:8080/
curl -s -o /dev/null -w "public /login -> %{http_code}\n" http://91.188.212.77:8080/login
```

**Увидите:** `/` → `302` (редирект на `/login`), `/login` → `200`.

## Шаг 4. Вход с внешнего устройства

На телефоне/другом ПК открыть `http://91.188.212.77:8080`:

1. «Регистрация» → логин/пароль → отправить;
2. пройти короткое **знакомство** (3 вопроса: стиль, ограничения, контекст);
3. задать вопрос в чате («Привет! Кто ты?») → дождаться ответа (первый ответ до минуты);
4. **перезагрузить страницу** (F5) → вся переписка на месте;
5. закрыть браузер, войти снова → переписка на месте.

> Полное подтверждение внешнего пользователя — `access_peer_confirm.md`.

## Шаг 5. Устойчивость: повтор, параллель, деградация

Живые прогоны этапа 11 (`access_resilience.md`):

| Что | Ожидаемо | Факт |
|---|---|---|
| Повтор того же `request_id` | тот же ответ, без дублей (`repeated: true`) | ✅ |
| Обрыв во время генерации | `503`, «половины» ответа нет | ✅ |
| N=5 параллельных | 5×`200` | ✅ |
| N=9 параллельных | 6×`200` + 3×`429` (лимит 6/мин) | ✅ |
| Недоступный фасад | `503` «Сервис временно недоступен» | ✅ |
| Запрос > 8000 символов | `413` | ✅ |

## Шаг 6. Сохранность MCP на VPS

```bash
./dev/vps/mcp_vps.sh status
```

**Увидите:** `mcp-time-server`, `mcp-scheduler-server`, `mcp-pipeline-server` — `active`;
порты `:8000/:8010/:8020` слушают. Шлюз их не затронул.

## Шаг 7. Автономность без интернета (на хосте)

```bash
export HTTPS_PROXY=http://127.0.0.1:1 HTTP_PROXY=http://127.0.0.1:1
export NO_PROXY=127.0.0.1,localhost
curl -s -o /dev/null -w "routerai=%{http_code}\n" https://routerai.ru/   # → 000
./run.sh --model-list                                                    # → 6 моделей (локально)
```

**Увидите:** без интернета терминал и локальный агент работают; шлюз при мёртвом фасаде
отдаёт `503` за ~0.06 с (не зависает).
