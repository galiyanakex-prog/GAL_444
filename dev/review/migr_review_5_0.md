## ⚠️ ЖЁСТКОЕ ОГРАНИЧЕНИЕ: `--temperature`, `--max-tokens`, `--context-window`

**Флаги `--temperature F`, `--max-tokens N`, `--context-window N` и вся связанная
с ними информация (профили `temperature` / `max_tokens` / `context_window`, описания
оптимизации, значения в примерах `models.json`) — ТРОГАТЬ НЕЛЬЗЯ.**

**Причина:** это следы функционала, реализованного в задании Дня 5
(`ND/tasks/n_1/005_День 5/`, см. `Den_5_Kod.py` и `Задание_Д5.txt`), **ошибочно
затёртого в одной из прошлых ревизий**. Функционал подлежит **восстановлению
в следующей ревизии**.

**Следствия для этапа (и всех последующих этапов ревью):**
- строку флагов `--temperature F`, `--max-tokens N`, `--context-window N` в README
  **сохранить без изменений** — она описывает целевое состояние, а не ошибку;
- строку `--max-tokens` в перечне флагов запуска **сохранить** (это точка
  восстановления соответствующего CLI-флага);
- раздел «Оптимизация: профили параметров» и значения `temperature` / `max_tokens` /
  `context_window` в примерах — **не редактировать**;
- **при любых расхождениях** между README и текущим `Kod.py` по этим параметрам —
  **не править README**, а зафиксировать расхождение в `migr_log.md` как «ожидаемое:
  функционал затёрт, восстанавливается в следующей ревизии».

> **Примечание о прошлой редакции плана.** В редакции v1.1 этот подшаг предписывал
> **удалить** указанные флаги из README как «несуществующие в `Kod.py`». Это указание
> **отменено оператором**: удаление закрепило бы ошибочную потерю функционала. В README
> добавлена пометка «НЕ ТРОГАТЬ» рядом с блоком флагов и у профилей параметров.
