# error_20260920_234900 — гейт №10: экранирование переменных в `bash -c`

- **Этап:** 6 (подшаг 6.4, `check_acceptance.sh`, проверка №10 «task_state.json переживает перезапуск»).
- **Тип ошибки:** shell-экранирование (не код проекта).
- **Симптомы:**
  1. `check_acceptance.sh: строка 53: SNAP: не заданы границы переменной` → гейт EXIT 1 (9/10).
  2. В корне дня создавался мусорный каталог `$D/` с тестовыми данными (`users/u/...`, task_state.json).
- **Контекст/причина:** тело проверки №10 — строка в двойных кавычках для `bash -c`.
  Переменные, которые должен раскрывать **внутренний** шелл (`$D`, `$MD`, `$SNAP`), не были
  экранированы (`\$`), поэтому:
  - `$SNAP`/`$D` раскрывались **внешним** шеллом в пустые строки → при `set -u` падало;
  - `MD='\$D/users'` (одинарные кавычки внутри двойных) попадал в Python-аргумент literally →
    `--memory-dir '$D/users'` создавал каталог с именем `$D` в корне дня (загрязнение корня,
    нарушение правила «временные файлы только в `.tmp/`»).
- **Стек:** не применимо (shell).
- **Решение:**
  1. Все обращения к внутренним переменным в теле проверки — через `\"` и `\$`:
     `MD=\"\$D/users\"`, `SNAP=\$(find \"\$MD\" ...)`, `grep -q '\"stage\": \"paused\"' \"\$SNAP\"` и т.д.
  2. Мусорный каталог `$D/` удалён из корня дня (`rm -rf '$D'`).
  3. Примечание: инструмент `replace` экранирует обратные слэши в аргументах — буквальная
     правка `\$`-последовательностей выполнена через Python-скрипт (heredoc).
- **Проверка после фикса:** `API_KEY=test-key bash dev/tests_debug/check_acceptance.sh` →
  **10 из 10, FAIL=0, EXIT 0**; каталог `$D` в корне не появляется; TMP изолирован в `.tmp/acc_$$`.
- **Статус:** ✅ исправлено.
