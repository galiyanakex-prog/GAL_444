# tunnel_setup.md — SSH reverse tunnel: хост → VPS (этап 10, S2)

> Инструкция и транскрипт настройки туннеля. Туннель — **SSH reverse tunnel**
> (решение №12); WireGuard **не применяется**. Проброс портов на роутере не нужен:
> хост сам держит исходящий SSH-канал к VPS.

## Топология

```
интернет ──► VPS:8080 (шлюз, публичный порт)
                 │  шлюз обращается к фасаду по http://127.0.0.1:8090
                 ▼
             VPS:127.0.0.1:8090  ◄── SSH reverse tunnel ──  хост:127.0.0.1:8090 (фасад)
```

- Публичен **только** веб-порт шлюза `:8080` (решение №22).
- Проброшенный порт `8090` слушает **только loopback VPS** — фасад напрямую из
  интернета недоступен.
- MCP `:8000/:8010/:8020` не трогаются (решение №18).

## Важное уточнение по `GatewayPorts`

В нашей схеме шлюз работает **на самом VPS** и обращается к фасаду по
`http://127.0.0.1:8090` (loopback VPS). Reverse-туннель пробрасывает порт именно
на loopback (`-R 127.0.0.1:8090:127.0.0.1:8090`), поэтому настройка `GatewayPorts`
**НЕ требуется** — оставляем значение по умолчанию (`no`).

`GatewayPorts yes` нужен только если проброшенный порт должен слушать внешние
интерфейсы VPS (`0.0.0.0`). Нам это не нужно и вредно: фасад обязан оставаться
внутренним. Справка на случай смены топологии — в `dev/vps/sshd_gateway.snippet`.

## Шаги (выполняет оператор)

### 1. Юнит туннеля на ХОСТЕ

```bash
cp dev/vps/units/ai9-tunnel.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now ai9-tunnel
systemctl --user status ai9-tunnel --no-pager
```

Ожидаемо: `active (running)`. Юнит держит `ssh -NT -R 127.0.0.1:8090:127.0.0.1:8090 mcp-vps`
с `Restart=always` (упал канал — поднимется сам).

### 2. Проверка на VPS: порт слушает loopback

```bash
ssh mcp-vps 'ss -ltnp | grep 8090'
```

Ожидаемо: `127.0.0.1:8090` (НЕ `0.0.0.0:8090`). Из интернета порт 8090 недоступен.

### 3. Проверка сквозного пути (на VPS)

```bash
ssh mcp-vps 'curl -s http://127.0.0.1:8090/models | head -c 120'
```

Ожидаемо: JSON со списком моделей (значит, туннель дотягивается до фасада хоста).

### 4. Авторестарт (проверка устойчивости — детально на этапе 11)

```bash
# на хосте: убить процесс туннеля и убедиться, что systemd поднял его снова
pkill -f 'ssh -NT.*8090' ; sleep 6 ; systemctl --user is-active ai9-tunnel
```

Ожидаемо: `active` (канал восстановился сам).

## Транскрипт (заполняется при выкатке)

| Шаг | Команда | Ожидаемо | Факт |
|---|---|---|---|
| 1 | `systemctl --user status ai9-tunnel` | `active (running)` | ☐ |
| 2 | `ssh mcp-vps 'ss -ltnp \| grep 8090'` | `127.0.0.1:8090` | ☐ |
| 3 | `ssh mcp-vps 'curl -s http://127.0.0.1:8090/models'` | JSON моделей | ☐ |
| 4 | `pkill -f 'ssh -NT.*8090'` → `is-active` | `active` | ☐ |

> Живой прогон туннеля выполняется оператором на VPS (агент не имеет доступа к
> внешнему контуру). Транскрипт дополняется фактическими выводами.
