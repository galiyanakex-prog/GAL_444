## Шаги

### ШАГ 5.1 — Явный инжект генератора (`rag/service.py`)

- `RagService(cfg, llm=…, embedder=…)`; `answer(question, use_rag=True, llm=None)` использует
  переданный `llm`, иначе — `self.llm`. Смену модели внутри `rag/` **не** делаем.

### ШАГ 5.2 — Секция `generation` в `rag/config.json`

```json
"generation": {"provider": "cloud", "model": null, "profile": null}
```

Переопределение: `--gen-provider`, `--gen-model`, `AI9_GEN_PROVIDER`, `AI9_GEN_MODEL`.
`profile: null` = «профиль самой модели из реестра» (напр. `rag-strict` у боевой 3B);
иначе профиль перезаписывается и локальная модель генерирует без лимита токенов
(упирается в таймаут).

### ШАГ 5.3 — Флаг `--local-gen` и REPL `/gen local`

Собирает клиента из `ModelRegistry` и подставляет в `agent.llm` **и** `rag_service.llm` —
одна точка, без расхождений. `/gen status` — кто генерирует сейчас (модель + профиль).

### ШАГ 5.4 — Полный локальный контур

`--rag --local-gen` ⇒ эмбеддинги Ollama + retrieval локально + генерация локально;
**ни одного внешнего запроса** (проверка транскриптом/логом: в сессии нет обращений к `routerai.ru`).

### ШАГ 5.5 — Проверка истинного офлайна

Прогон при **выключенном интернете** (или заблокированном внешнем доступе) — агент отвечает.
Это и есть «приватный сервис доступен всегда» (§0.2).

### ШАГ 5.6 — Сверка индекса + тесты

- Индекс **не пересобираем**; сверяем, что `meta.json` совпадает с конфигом (иначе — плановый
  ребилд и запись в журнал).
- `dev/tests_debug/unit/test_rag_local_gen.py`: при `llm=FakeLocal` ответ формируется без
  обращения к облачному клиенту (счётчик вызовов); блок `[rag]` и источники/цитаты сохраняются
  как с облаком; при пустом индексе — «не знаю», не падение; `--local-gen` без поднятого
  сервиса → понятная ошибка и откат к прежней модели.
