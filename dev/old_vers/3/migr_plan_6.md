## 1. Шаги этапа

### Шаг 6.1 — Блок `[tools]` (`core/prompt_builder.py`)
- Добавить в `DELIVERABLE` имя `"tools"`; в `BLOCK_ORDER` — позицию **после `invariants`,
  до `long_term`** (существующие блоки не смещаются):
  `("role","profile","invariants","tools","long_term","working","summary","short_term","current")`.
- Блок добавляется только если `"tools"` ∈ `deliver` и в контексте есть `tools_block`
  (или `ctx.tools`). Содержимое: по каждому тулу — имя, описание, краткая схема аргументов.
- Для нативного пути дополнительно передать машинную спецификацию тулов
  (OpenAI `tools`) — через контекст (`ctx.tool_specs`).

### Шаг 6.2 — `ToolPromptPolicy`
- Минимальный объект лимитов: `max_tools`, `max_schema_tokens`, `include_descriptions`.
- Каталог обрезается: сначала по числу тулов, затем по бюджету токенов схем; при
  переполнении описания сокращаются. Значения по умолчанию задать в `Kod.py` при `--mcp`.

### Шаг 6.3 — Проверка
- Блок появляется только при `tools` ∈ `deliver`;
- лимит `max_tools` соблюдается; порядок блоков не нарушен (`test_blocks_order` зелёный);
- сборка без тулов — прежняя (регрессия).
