> Контур: **К (код)**. Метка цели: **К2**. Зависимости: **этап 0**.
> Порядок: **пошагово с оператором**. **Коммиты — только за оператором** (ШАГ 2.5).

## Цель этапа

**Решение оператора №13, Вариант (C).** Добавить в `rag/verify.py` режим **N прогонов**
одного набора вопросов с отчётом **среднее / разброс** (min–max, σ) по метрикам
«источники / цитаты / смысл=цитаты»; отчёт `dev/logs_reports/stages/rag_verify_stability.md`.

> **Факт (Ш10):** два живых прогона `--rag-verify` дали разный «смысл» (9/10 и 6/10)
> из-за недетерминизма LLM; в журнале это читается как противоречие.

## Предусловия

- `rag/verify.py` — `verify_answers`, `render_report`, CLI `python -m rag.verify` (этап 9 Ревизии 7).
- `rag/service.py` — `answer` с источниками/цитатами/вердиктом.
- 10 контрольных вопросов (`rag/datasets/queries.jsonl`).

## Границы этапа

- **Не** меняем логику оценки (только агрегация по прогонам).
- **Не** делаем N>1 по умолчанию (`runs=1` — обратная совместимость).
- **Не** меняем `requirements.txt`.

### ШАГ 2.2 — Параметр `runs` и агрегация в `rag/verify.py` (агент)

- `verify_answers(..., runs: int = 1)`: при `runs>1` — N прогонов одного набора;
- агрегация по прогонам: **среднее**, **min–max**, **σ** для каждой метрики
  (источники / цитаты / смысл=цитаты);
- `render_report` — таблица «метрика × (среднее / разброс)» при `runs>1`;
  при `runs=1` — прежний отчёт (обратная совместимость).
