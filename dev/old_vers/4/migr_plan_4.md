**Цель.** Сквозной живой прогон: пользователь просит «который час в Москве?» → LLM **сам**
запрашивает `get_time` (Вариант A — автовызов через `Agent._respond_with_tools`) → реальный
вызов на сервере задания → результат возвращается в модель → **финальный ответ использует
результат** (Вариант 1 — через LLM-цикл: tool-сообщение → финальный ответ модели).

## 1. Шаги этапа

### Шаг 4.1 — Живой REPL (Вариант A + Вариант 1)
bash
PY="../../.venv/bin/python"
printf 'который час в Москве?\n/exit\n' | timeout 120 $PY Kod.py --user w17live --mcp

(ключ `API_KEY` — из `.env`; endpoint — `MCP_SERVER_URL` или дефолт).
**Ожидаемо:** подключение READY; LLM **сам** формирует tool_call
`get_time({"timezone_name":"Europe/Moscow"})`; реальный вызов на сервере задания;
tool-сообщение с ISO 8601 возвращается в модель; **финальный ответ содержит время**
(например, «в Москве сейчас 11:33 (MSK)»).

### Шаг 4.2 — Живой `--mcp-probe`
`timeout 60 $PY Kod.py --mcp-probe` → тул `get_time`, exit 0.

### Шаг 4.3 — Зафиксировать доказательства
- Транскрипт REPL, `Den_log.md` (фрагмент), `tool_audit.jsonl`, `catalog.json` →
  `dev/logs_reports/stages/`.
- Проверить: `TaskStage` не изменился; `transition_log` без записей от вызовов;
  сырые данные не в память.

### Шаг 4.4 — Устранить шероховатости
- Любой сбой (сеть/LLM/схема) → точечный фикс; повторить прогон.
- Если провайдер не поддержал нативный tool_calls — проверить работу fallback-протокола
  (JSON tool-call в тексте).
