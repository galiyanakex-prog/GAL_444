## 2. Шаги этапа (исполняемый алгоритм)

### Шаг 0.1 — Активировать окружение и зафиксировать точку старта
1. `cd Nedela_4/den_17`; использовать venv недели (`../../.venv/bin/python`).
2. Зафиксировать дерево модулей: `ls core/tools.py core/tool_registry.py
   core/tool_policy.py core/tool_executor.py integrations/mcp/*.py`.

### Шаг 0.2 — Сверить факт с §0.3 плана-эталона
Составить таблицу «есть / нет»:
- **есть**: внутренняя модель, реестр, stdio+HTTP-транспорт, client/gateway/provider/demo,
  конфиг/каталог в Store, `/mcp`-семейство (вкл. `/mcp call`), `--mcp`/`--mcp-probe`,
  `ToolPolicy`/`ToolExecutor`/аудит, LLM tool-use (нативный + fallback), блок `[tools]`,
  агентный цикл `Agent._respond_with_tools`;
- **нет** (закрывается M1–M6): сервер задания `time` в `DEFAULT_SERVERS`; чтение env
  `MCP_SERVER_URL`; реальное discovery к серверу задания; реальный вызов `get_time`;
  живой LLM tool-use «который час»; документация под день 17.

### Шаг 0.3 — Зафиксировать факты о сервере задания (из §0.4 плана-эталона)
Записать в `migr_log.md` M0: protocol `2025-06-18`, `Time Server`, 1 тул `get_time`
(`timezone_name: string`, default `UTC`, не required; описание на русском, IANA/ISO 8601);
`call_tool("get_time", {"timezone_name":"Europe/Moscow"})` →
`2026-09-27T11:33:00.230958+03:00`, `isError=false`, `structuredContent.result`;
транспорт Streamable HTTP (`streamable_http_client`). Погодный `weatherapi` — жив (HTTP 200).

### Шаг 0.4 — Зафиксировать точки внедрения (не менять)
`core/state_machine.py` (TaskStage 8, карта, API контроля), `core/invariants.py`,
`memory/*` (полностью), `storage/db.py`, базовые контракты `core/llm_client.py` и
`core/prompt_builder.py`, MCP-инфраструктура Ревизии 2 (транспорт/gateway/provider/
registry/policy/executor/tool-use) — **не переписываются**.

### Шаг 0.5 — Регрессионный baseline (без живого ключа)
```bash
PY="../../.venv/bin/python"
$PY -m py_compile Kod.py core/*.py memory/*.py storage/*.py integrations/mcp/*.py   # L1
env -u API_KEY $PY dev/tests_debug/unit_runner.py                                   # L2
API_KEY=test-key $PY dev/tests_debug/smoke.py                                       # L3
API_KEY=test-key $PY dev/tests_debug/scenario.py                                    # L4
API_KEY=test-key bash dev/tests_debug/check_acceptance.sh                           # гейт
```
**Ожидаемый результат:** L1 ok; L2 — все OK, 0 FAIL; L3 SMOKE OK; L4 — все сценарии
зелёные; гейт — все проверки зелёные, exit 0. (Точные числа — по факту прогона; фиксируются
в `migr_log.md`.)

### Шаг 0.6 — Подготовить служебные документы под Ревизию 3
