## 5. Шаги

### 2.1. Снимок поведения CLI — Исполнитель

Действие: зафиксировать `--help`, запуск REPL, 5–7 базовых команд, коды возврата.
Ожидаемый результат: `$LOGS/s2_cli_before.txt`.
Проверка: снимок повторяем.

### 2.2. Разгрузка `Kod.py` — Исполнитель

Действие: вынести `cli/arguments.py`, `cli/repl.py`, `cli/commands/`, `bootstrap.py`;
`Kod.py` оставить точкой входа или удалить, если entrypoint перенесён и все ссылки
обновлены. Никаких двойных путей запуска.
Ожидаемый результат: каждый модуль < ~400 строк; импортная зависимость в одну
сторону; циклических импортов нет.
Проверка: снимок 2.1 совпадает по командам/кодам; `python -c "import ..."` без побочных
эффектов.
Ветвление: расхождение поведения → откат шага, разбор по одной команде.

### 2.3. Бюджет промпта — Исполнитель

Действие: ввести лимиты на блоки памяти/контекста, убрать дублирование, считать
токены целевым токенизатором; при переполнении — приоритетное усечение с записью
в лог (без секретов).
Ожидаемый результат: общий размер ≤ установленного бюджета; блоки не дублируются.
Проверка: замер до/после, тест «переполнение → усечение по приоритету».
Ветвление: бюджет недостижим → O-5 и решение оператора, не молчаливое превышение.

### 2.4. Fail-closed и risk-уровни — Исполнитель

Действие: таблица «инструмент → риск → требуется подтверждение»; неизвестный
инструмент, схема, риск или стадия → запрет; порядок проверок единый; отказ
логируется без аргументов.
Ожидаемый результат: неизвестное не исполняется; LOW/MEDIUM/HIGH/CRITICAL
различаются правилами подтверждения.
Проверка: тест «неизвестный инструмент» красный до и зелёный после.
Ветвление: конфликт с существующим `ToolPolicy` → расширять, не дублировать.

### 2.5. Доверие к RAG — Исполнитель

Действие: показывать embedder и признак fallback; проверять утверждения (claims),
а не только наличие ссылок; при неподтверждённом утверждении — пометка/отказ.
Ожидаемый результат: ответ содержит статус источника; fallback не маскируется под
штатный режим.
Проверка: фикстура с ложным утверждением → помечено.
Ветвление: проверка требует внешней модели → offline-режим с эвристикой и явной
пометкой.

### 2.6. Внешние сервисы — Исполнитель

Действие: health-check, circuit breaker (переиспользовать этап 1), таймауты,
версионированные контракты; деградация без падения ядра.
Ожидаемый результат: недоступный сервис не блокирует CLI.
Проверка: фиктивный сервис, отказ/таймаут.

### 2.7. Offline-профиль — Исполнитель

Действие: флаг/конфиг, отключающий сеть, MCP и внешние модели в тестах; явная
пометка в выводе.
Ожидаемый результат: тесты не ходят в сеть; production-профиль не меняется.
Проверка: запуск с сетевым монитором/флагом, отсутствие соединений.

### 2.8. Строгий JSON tool-use — Исполнитель

Действие: строгий парсер fallback-протокола, валидация JSON Schema, лимит попыток,
понятная ошибка без сырого ответа модели.
Ожидаемый результат: невалидный JSON отклоняется, повтор ограничен.
Проверка: набор «валидный/невалидный/лишние поля/огромный ответ».

### 2.9. Тесты, регрессия, журнал — Исполнитель

Действие: прогнать базовый набор и новые тесты; заполнить журнал; перечитать
мастер-план; предложить коммит `refactor(core): split CLI, budget prompt, fail-closed`.
Ожидаемый результат: пары «падало → проходит», снимок CLI совпадает.
