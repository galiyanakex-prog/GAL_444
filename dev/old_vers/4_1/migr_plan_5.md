## 0. Цель и границы

**Цель** — пользователь запускает фоновую работу 24/7, видит периодическую сводку,
может вручную запустить пайплайн и посмотреть маршрутизацию.

**Границы**: `--scheduler` поднимает worker; `/mcp summary|jobs|pipeline|route` —
ручные команды. Без `--mcp`/`--scheduler` поведение = `den_15` (регрессия запрещена).

| Файл | Назначение |

| `Kod.py` | флаг `--scheduler` (+ `--scheduler-interval`), сборка/остановка worker, `/mcp summary|jobs|pipeline|route` |

---

## 2. Шаги

1. `Kod.py`: флаг `--scheduler` — поднять фоновый worker (24/7) с дефолтным
   расписанием (периодический сбор + регулярная сводка); аккуратное завершение при
   `/exit`/`EOF`/`Ctrl+C`.
2. `/mcp`-семейство: `/mcp summary [window]` (последняя сохранённая сводка),
   `/mcp jobs` (задачи планировщика), `/mcp pipeline <запрос>` (автоцепочка),
   `/mcp route <текст>` (объяснение выбора инструмента/сервера).
3. Живой прогон: `--mcp --scheduler` → наблюдения в JSON → `/mcp summary` отдаёт
   сохранённую сводку (без нового запроса к модели).
4. Проверка регрессии: без `--mcp`/`--scheduler` поведение = `den_15`.

## 3. Гейт M5→M6 (критерии)

- [ ] фоновый worker работает и корректно останавливается;
- [ ] сводка выдаётся (`/mcp summary` — сохранённый текст);

- [ ] регрессия без флагов (MCP off, worker не поднимается);
- [ ] L1/L2/L3/L4/гейт без регрессии.
