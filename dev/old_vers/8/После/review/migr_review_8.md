## Шаги

### ШАГ 8.1 — Сверить все числовые утверждения с эталоном

```bash
cd "$KOD"
# Гейт: везде ли 58
grep -n 'проверок\|из 58\|58/58' README.md
# Приёмка: везде ли 48
grep -n 'критериев\|48/48' README.md
# L2: везде ли 412
grep -n '412\|OK, 0 FAIL' README.md
# Модули
grep -nE '(16|19|11|6|42) (модул|файл)' README.md
```

**Действие:** любое расхождение с эталонной таблицей → правка по эталону.
Если эталон сам под вопросом — вернуться к соответствующему этапу, а не «усреднять».

### ШАГ 8.2 — Проверить отсутствие устаревших ссылок

```bash
grep -n 'migr_2_plan\|scen_model_switch\|README_3\.md\|README_4\.md' README.md
```

**Ожидаемо:** 0 совпадений. (Сейчас в файле есть строки 1660, 1661, 1686 — их
удаляют этапы 2 и 4; если этап 2 выполнен, здесь должно быть пусто.)
Если остались — это **база этапа 2**, вернуться и закрыть.

### ШАГ 8.3 — Проверить, что каждое имя файла в README существует

```bash
# Все backtick-пути вида dir/file.ext, упомянутые в README
grep -oE '`[a-zA-Z0-9_./-]+\.(py|md|json|sh|html|service|snippet|list|txt|csv|example)`' README.md \
  | tr -d '`' | sort -u > /tmp/readme_paths.txt
while read -r p; do
  case "$p" in
    /*|*'*'*|*'…'*|*'<'*|*'>'*|*'*') continue ;;
  esac
  [ -e "$p" ] || echo "НЕТ: $p"
done < /tmp/readme_paths.txt
```

**Действие:** по каждому «НЕТ» решить: путь опечатка (править README) или путь
условный/шаблонный (оставить, добавив в README пояснение вида `…/*_params.md`).
Исключения-шаблоны (`m*_smoke.py`, `subagent_*.md`, `*_params.md`) — не баг.

### ШАГ 8.4 — Сверить терминологию

```bash
# Синонимы-двойники
grep -c 'веб-шлюз\|шлюз' README.md
grep -c 'фасад' README.md
grep -c 'боевая модель' README.md
grep -n 'LM Studio\|lmstudio' README.md | wc -l
```

**Правило сверки (не переписывание):** «шлюз» = `gateway/` (VPS), «фасад» = `serve.py`
(хост). Если в каком-то месте `serve.py` назван шлюзом или наоборот — исправить
это одно место. Термины-синонимы в пределах одного раздела допустимы.

### ШАГ 8.5 — Проверить перекрёстные ссылки между разделами

```bash
# Ссылки вида «см. раздел …» / «подробнее в …»
grep -nE 'см\. |подробнее|см\. раздел|инструкция в' README.md
```

По каждой ссылке убедиться, что раздел/файл существует и называется так, как указано.

### ШАГ 8.6 — Проверить согласованность деревьев и карты артефактов

Выборочно: 10 файлов, добавленных на этапах 1–4, должны упоминаться **и** в дереве,
**и** в карте артефактов (если относятся к продукту/процессу):

```bash
for f in serve.py models.json gateway/sync_questions.py integrations/mcp/auth.py \
         integrations/mcp/time_server.py core/subagents.py core/resources.py \
         agents.md ND/models dev/vps/units; do
  printf "%-34s упоминаний: " "$f"; grep -c -- "$f" README.md
done
```

**Ожидаемо:** у каждого ≥ 2 (дерево + карта). Если 1 — добавить во второй место.
