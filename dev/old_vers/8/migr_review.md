# migr_review.md — план доскональной проверки актуальности данных проекта (после Ревизии 7)

> **Зачем.** В `dev/migr_log.md` этапы 10–12 и «Итог Ревизии 7» заявляют результаты,
> которые **не подтвердились** при первой же сверке с файловой системой:
> `.tmp/` не очищен (11 МБ / 813 файлов вместо «пусто»), `dev/Проверка.md` содержит
> раздел «Ревизия 5» и счётчики `148 OK` / `25/25`, `README.md` не содержит заявленных
> `280 OK` / `43/43` и новых флагов, а его mtime (02:04) **раньше** завершения ревизии
> (05:43). Значит часть записей журнала — план, выданный за факт.
>
> **Правило этого документа.** Ничему из `migr_log.md`, `README.md` и `Проверка.md`
> не верим на слово. Каждое утверждение сверяется **командой** с реальностью.
> Результат шага — один из: **АКТУАЛЬНО** / **УСТАРЕЛО** / **ЛОЖЬ** / **НЕ ПРОВЕРЕНО**.
>
> **Протокол каждого шага (обязателен):**
> 1. выполнить команды шага;
> 2. записать отчёт в раздел `## Проверка актуальности данных проекта` файла `dev/migr_log.md`
>    (формат — §3);
> 3. **перечитать `dev/migr_review.md`** целиком;
> 4. только затем переходить к следующему шагу.
>
> **Запреты:** ничего не исправлять в продукте и документации в ходе проверки
> (только фиксация расхождений); не запускать `git commit`; не трогать `users/`;
> живые прогоны с LLM-ключом — только на шаге Ш10 и только через `env -u API_KEY`.

---

## 1. Метки и критерии

| Метка | Значение |
|---|---|
| **АКТУАЛЬНО** | утверждение документа подтверждено командой |
| **УСТАРЕЛО** | было верно, теперь противоречит коду/файлам |
| **ЛОЖЬ** | утверждено то, чего нет (или утверждено «сделано», а не сделано) |
| **НЕ ПРОВЕРЕНО** | проверить невозможно без действий пользователя (коммит, VPS, живой ключ) |

Вердикт шага — **зелёный**, если все его утверждения **АКТУАЛЬНО**; иначе шаг
фиксирует расхождения и **не** закрывается как «всё хорошо».

---

## 2. План шагов

### Ш1 — Снимок состояния: git, время, размеры
**Цель:** зафиксировать объективную точку отсчёта, независимую от документов.
**Команды:** `git status --short`; `git log --oneline -6`; `git diff --stat`;
`stat -c '%y %n'` для `README.md`, `dev/Проверка.md`, `dev/migr_log.md`, `dev/migr_plan.md`,
`Kod.py`, `core/agent.py`, `memory/working.py`, `rag/*.py`.
**Сверяем:** что реально в HEAD, что не закоммичено, хронология правок.
**Ожидание (гипотеза):** итог этапа 12 не закоммичен; `README.md` правился раньше `migr_log.md`.

### Ш2 — Чистота `.tmp/` и временных артефактов
**Цель:** проверить заявление этапа 12 «`dev/tests_debug/.tmp/` — очищен (203 МБ → пусто)».
**Команды:** `du -sh dev/tests_debug/.tmp`; `find … -type f | wc -l`; `ls` верхнего уровня;
`find . -name '*.tmp' -o -name 'audit0.py'`; проверка `rag/.tmp/`.
**Сверяем:** пусто ли; что именно лежит; есть ли артефакт этапа 0 `audit0.py`.

### Ш3 — Детерминированный контур: фактические счётчики
**Цель:** проверить `280 OK`, `SMOKE OK`, `SCENARIO OK`, `DIALOG OK` без веры журналу.
**Команды:** `unit_runner.py`; `smoke.py`; `scenario.py`; `dialog_runner.py` (офлайн/`--mock`).
**Сверяем:** число модулей и OK/FAIL; код возврата.
**Важно:** запускать без живого ключа (`env -u API_KEY`), чтобы не тратить токены.

### Ш4 — Гейт приёмки
**Цель:** проверить `43/43`.
**Команды:** `bash dev/tests_debug/check_acceptance.sh`; подсчёт объявленных проверок в скрипте.
**Сверяем:** фактическое число зелёных/красных; совпадает ли заявленное 43 с числом проверок в скрипте.

### Ш5 — `README.md` против кода
**Цель:** проверить, что README описывает текущий продукт.
**Команды:** сверка дерева `rag/` в README со `ls rag/*.py`; поиск в README заявленных
счётчиков (`280`, `43/43`) и новых флагов (`--rag-ask`, `--rag-verify`, `--rag-threshold`,
`--rag-unknown`, `--rag-reranker`, `--rag-rewrite`); поиск устаревших следов
(`den_15`, `den_16`, `25/25`, `244`, `33/33`, «задел следующих дней»);
раздел «Тестирование и приёмка» — какие числа там стоят.
**Сверяем:** каждый заявленный в README артефакт существует; каждая строка дерева — реальный файл.

### Ш6 — `dev/Проверка.md` против кода
**Цель:** проверить, что чек-лист годен к ручному прогону **сегодня**.
**Команды:** поиск устаревших разделов и ссылок («Ревизия 5», `148 OK`, `25/25`, `den_16`,
«40 критериями», «задание Д16», «предыдущий день»); для **каждой** команды из файла —
проверка, что соответствующий флаг/команда реально существует в `Kod.py`
(`--mcp-probe`, `--rag-ingest`, `--rag-ask`, `--rag-eval`, `--rag-verify`, `--rag-compare`,
`--rag-search`, `--rag-rewrite`, `--rag-threshold`, `/rag …`, `/mcp …`).
**Сверяем:** есть ли в файле разделы, которые надо удалить/переписать; ссылаются ли пути
`$KOD/../../.venv/bin/python` на существующий интерпретатор.

### Ш7 — `Kod.py`: заявленные флаги и команды реально зарегистрированы
**Цель:** проверить заявление этапа 12 о новых флагах/командах.
**Команды:** `grep` по `add_argument` и по обработчикам REPL; `--help`;
проверка существования функций `run_rag_ask`, `run_rag_verify`, `_load_queries`,
`_rag_llm_callable`, `_print_answer_sources`.
**Сверяем:** флаг объявлен → обработан → функция существует; обратное (обработчик без флага) тоже ищем.

### Ш8 — Границы и инварианты архитектуры
**Цель:** проверить ключевые «не сломать» из мастер-плана.
**Команды:** `grep -rn "^from core\|^import core" rag/` (должно быть пусто);
`grep -rn "import rag" core/ memory/ storage/` (должно быть пусто, кроме ленивого DI в `Kod.py`);
`TaskStage` — 8 значений и `ALLOWED_TRANSITIONS` без новых дуг;
RAG off по умолчанию (`rag_enabled`); без `--rag` в промпте нет `[rag]`.
**Сверяем:** запрет «RAG ≠ переход», запрет циклов импортов.

### Ш9 — Память задачи и RAG-слой агента (часть 4)
**Цель:** проверить `goal` / `clarifications` / `terms` в `WorkingMemory` и поиск на каждый обмен.
**Команды:** `grep` полей в `memory/working.py`; наличие `_rag_retrieve`/`_grounding_guard`
в `core/agent.py`; чтение `users/*/tasks/*/working_memory.json` — есть ли поля на практике;
существование `dev/tests_debug/scenario/scen_dialog_A.md`, `scen_dialog_B.md` и числа 12/13.
**Сверяем:** заявленное расширение реально в коде, а не только в описании.

### Ш10 — Заявленные метрики против транскриптов
**Цель:** проверить, что цифры из журнала/документации подтверждены артефактами.
**Команды:** для каждого числа (`hit-rate@5 0.8824`, `MRR 0.724`, `nDCG 0.903`,
`источники 10/10`, `цитаты 10/10`, `смысл 6/10` и `9/10`, `117 чанков / 9 документов`,
`must_contain 5/19 → 12/19`, `порог 0.45`) — найти транскрипт в `dev/logs_reports/stages/`
и извлечь значение; отметить, где транскрипта нет или значение отличается.
**Отдельно:** живые прогоны (`--rag-eval`, `--rag-verify`) — **только** при наличии
`.env`-ключа и с явного согласия пользователя; иначе **НЕ ПЕРЕПРОВЕРЕНО** (сверка по файлам).
**Сверяем:** противоречия между двумя прогонами одного и того же (например «смысл 9/10» в
этапе 9 и «смысл 6/10» в этапе 12).

### Ш11 — Данные, конфиг и индекс
**Цель:** проверить корпус, датасеты, конфиг, индекс.
**Команды:** `wc -l rag/datasets/queries.jsonl` (заявлено 34); наличие `expect` у `c01…c10`;
`wc -l rag/datasets/corpus.list` (9); `rag/config.json` — секции `retrieval.threshold`,
`unknown`, `rewrite`; `rag/index/` — файлы и `meta.json` (`model_id`, `dim`, `strategy`);
`stats()` — `n_docs`/`n_chunks` (заявлено 9 / 110 в этапе 5 и 117 в этапе 12).
**Сверяем:** расхождение 110 vs 117 чанков; не засоряют ли артефакты git.

### Ш12 — Зависимости, секреты, приватность
**Цель:** проверить «новых зависимостей нет» и чёрный список индекса.
**Команды:** `git diff HEAD --stat requirements.txt`; `grep -rn "import " rag/*.py` на
сторонние пакеты; проверка, что в `rag/index/chunks.json` нет путей `users/`, `.env`, `.ssh`;
`grep -rn "91.188.212.77\|token\|API_KEY" rag/` на утечки; `.gitignore` — закрыто ли
`dev/old_vers/`, `dev/tests_debug/.tmp/`.
**Сверяем:** нет ли в индексе приватных данных; нет ли секрета в трекемых файлах.

### Ш13 — Журнал против реальности (аудит достоверности `migr_log.md`)
**Цель:** по каждому этапу 0–12 и «Итогу» — отметить, какие утверждения подтверждены
шагами Ш1–Ш12, какие опровергнуты.
**Команды:** сводная таблица «утверждение → шаг → вердикт».
**Особо:** заявления «Правок кода нет» (этапы 3–6) сверить с `git log -p --stat` по этим файлам;
заявления «Предложен оператору» — с реальным `git log`.

### Ш14 — Резюме
**Цель:** итоговая запись в `dev/migr_log.md` в раздел «Проверка актуальности данных проекта»:
сводка вердиктов по всем шагам, перечень **всех** подтверждённых расхождений,
классификация (ЛОЖЬ / УСТАРЕЛО / НЕ ПРОВЕРЕНО), список документов и разделов,
требующих исправления, и **что именно** в них неверно.
**Важно:** резюме **не** меняет продукт и документацию — только фиксирует диагноз.
Исправления — отдельным решением пользователя после резюме.

## 3. Формат отчёта по шагу (в `dev/migr_log.md`)

```
### Ш<N> — <название> (дата)
- Команды: <что запускалось>
- Факт: <числа/вывод, без интерпретаций>
- Сверялось: <какие утверждения документов>
- Вердикт: АКТУАЛЬНО / УСТАРЕЛО / ЛОЖЬ / НЕ ПРОВЕРЕНО (по пунктам)
- Расхождение: <утверждение → реальность> или «нет»
- Миграция плана: migr_review.md перечитан ✅
```

## 4. Ожидаемый результат проверки

1. Таблица «документ → утверждение → вердикт» по всем ключевым заявлениям.
2. Подтверждённый список того, что **реально** работает (по фактическим прогонам Ш3–Ш4).
3. Подтверждённый список того, что **не** сделано или сделано не полностью.
4. Перечень файлов/разделов, требующих правки, с указанием причины — **без** самой правки.
