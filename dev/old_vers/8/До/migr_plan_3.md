# migr_plan_3.md — Этап 3. `/model` + отображение модели во всех CLI-сессиях (L2)

> Рабочий план **одного этапа** на основе `dev/migr_plan.md` (**Ревизия 8, v1.1**, §4 «Этап 3»).
> Контур: **L (локальные LLM)**. Метка цели: **L2**. Зависимости: **этап 2**.
> Порядок: **пошагово с оператором**. **Коммиты — только за оператором** (ШАГ 3.6).

## Цель этапа

Часть 2 `Задание.txt`: «переключение облачных/локальных моделей **простой командой
`/model`**» и «**во всех CLI-сессиях явно отображается**, какая модель (сервис) подключена».

## Предусловия (после этапа 2)

- `ModelRegistry` + `Agent.set_model`/`model_label` работают; `models.json` создан.
- REPL-диспетчер команд — в `Kod.py` (`while True` → `if user_input.startswith("/")` → `command == …`).
- `append_token_log(exchange, prompt_tokens, cost_rubles)` пишет `tokens.csv`
  (колонки `exchange, timestamp, prompt_tokens, cost_rubles, cost_total_rubles`).
- `Den_log.md` — лог сессии (`log_line`).

## Границы этапа

- **Не** меняем контракт `LLMClient.complete` и сигнатуру `PromptBuilder.build`.
- **Не** трогаем `TaskStage`/`transition_log` (переключение модели — не переход).
- **Не** добавляем pip-зависимостей.
- Без `--model` подпись = облачная модель; **промпт байт-в-байт прежний** (подпись — вывод CLI, не содержимое `messages`).

## Шаги

### ШАГ 3.1 — Флаги запуска (`Kod.py`)

- `--model <id>` (по умолчанию `cloud:stepfun/step-3.5-flash`);
- `--model-list` (печать реестра и выход);
- `--model-profile <name>`.

### ШАГ 3.2 — Команды REPL (`Kod.py`, диспетчер `/`)

| Команда | Действие |
|---|---|
| `/model` / `/model current` | текущий `service/model`, профиль, параметры, окно, квант |
| `/model list` | все модели реестра + отметка текущей + `local/cloud` + статус probe |
| `/model use <id>` | переключение в сессии + запись выбора + подтверждение с новой подписью |
| `/model status` | живой health-check сервиса (latency, версия, доступность) |
| `/model profile <name>` | применить профиль параметров (часть 4) |

`/model list`, `/model status` токенов LLM **не тратят**.

### ШАГ 3.3 — Явное отображение модели (обязательная часть)

1. **Баннер** при старте и после `/model use`:
   `[Сессия] модель: lmstudio/Qwen2.5-Coder-3B-Instruct-Distill-Qwen3-Coder-Next-abliterated-Q6_K (локально, q6_K, ctx 8192, профиль rag-strict)`.
2. **Префикс реплики:** каждая строка ответа ассистента помечена `[lmstudio/Qwen2.5-Coder-3B-Instruct-Distill-Qwen3-Coder-Next-abliterated-Q6_K]`.
3. **Лог:** в `Den_log.md` каждая запись ответа несёт `model=`.
4. **`tokens.csv`:** новая колонка `model` (старые строки не переписываем).
5. **HTTP-ответ** (задел на этап 9): ответ фасада обязан нести поле `model`.
6. **Субагентные сессии** (этап 4) наследуют 1–4 автоматически (тот же `Kod.py`).

### ШАГ 3.4 — Регрессия

`PromptBuilder.build(...)` до/после (в `messages` подпись не попадает).

### ШАГ 3.5 — Тесты `test_model_switch.py`

и **сохранением** прежней модели; подпись присутствует в выводе каждого ответа (перехват stdout).
