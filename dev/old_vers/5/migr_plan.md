> **Роль документа.** Это **план-эталон** (мастер-план) доработки `/AI_9/`
> до состояния, в котором **требования `AI_9/ND/tasks/n_4/Задание_d20.txt` подтверждаются живым
> исполнением, а не декларацией**. Документ **не исполняется напрямую**: на его

> только цифры `0…N`. Буквенные метки (`И1…И4`, `D1…D7`) — это идентификаторы

> Этапы `4…12` — **контур правок продукта (D1–D7)**: точечные исправления `den_20`.
> **Приоритет живых проверок:** гейт этапа закрыт только если зелёный **живой**
> прогон против VPS; детерминированные тесты — обязательная регрессия, но сами
> гейт не закрывают.
>
> **Источники истины:** `Задание_d20.txt` (неизменяемый первоисточник), `arch.md`

- **Не меняет семантику** `MCPConnectionState`/`overall_state()` — правится

- **MCP выключен по умолчанию**: без `--mcp` агент = `den_15`; без `--scheduler`

- **Секреты/личные данные в тулы не кладём**; секреты клиента — только из `.env`.
- **Коммиты — только за оператором** (см. §5): агент **не** выполняет `git commit`

## 1. Конвейер документов: `migr_plan.md` → `migr_plan_N.md` → `migr_log.md`

```text
migr_plan.md  (план-эталон, ЭТОТ файл; единая нумерация этапов 0…N)
      ▼
migr_plan_0.md, migr_plan_1.md, … migr_plan_N.md   (рабочий план ОДНОГО этапа)
      ▼
выполнение этапа  →  АВТОМАТИЧЕСКИЙ ГЕЙТ (§6): живой прогон обязателен
      │   зелёный  → ПЕРЕЧИТАТЬ migr_plan.md → migr_plan_(N+1).md
      │   красный → карточка в logs_reports/errors/, этап НЕ закрыт
      ▼
migr_log.md  (журнал обоих контуров: было → стало → проверка → статус)
```

### 1.1 Правила
- `migr_plan.md` — единственный источник истины по составу/порядку этапов; рабочие
  планы не противоречат ему и не расширяют объём этапа без записи в `migr_log.md`.
- Один рабочий план = один этап = один гейт. **Нумерация строго сквозная `0…N`.**
- **ОБЯЗАТЕЛЬНО: перечитывать `migr_plan.md` после каждого этапа, перед следующим.**
- Каждый дефект/цель закрывается парой **«падало → проходит»**: рабочий план
  начинается с команды, воспроизводящей проблему на текущем состоянии (красный),
  и заканчивается той же командой в зелёном.
- `migr_log.md` **обнуляется до шапки Ревизии 5 перед этапом 0** (бэкап прошлой
  ревизии уже в `dev/old_vers/`).
- **Коммиты:** агент готовит правки и **предлагает текст коммита**; `git commit`
  (локально и на VPS) выполняет **только оператор**.

## 2. Принципы миграции

- **Живой приоритет:** базовая линия и гейты опираются на реальные прогоны против
  VPS; `FakeMCPTransport`/`MockClient` — слой воспроизводимой регрессии.
- **Инварианты:** контракты дней 11–15 не меняются; `TaskStage` не трогается;
  MCP off по умолчанию; SDK не протекает в `core`; временные файлы — только в
  `dev/tests_debug/.tmp/`; рабочие `users/` не трогать.
- **Управление без пароля:** сервисы — под `systemctl --user` (+ linger); root-
  операции — только через узкий `/etc/sudoers.d/mcp-ops`; **пароль sudo в скрипты
  и историю не попадает**.
- **Публичность осознанная:** серверы доступны извне (`0.0.0.0`, открытые порты);
  защита — `TransportSecuritySettings.allowed_hosts` (точный набор `host:port`),
  отсутствие секретов в тулах; авторизация по токену — D7 (запланировано).
- **Реальные endpoint'ы/секреты — только из `.env`** (`MCP_SERVER_URL`,
  `MCP_WEATHER_URL`, `SCHEDULER_MCP_URL`, `PIPELINE_MCP_URL`, флаги `*_ENABLED`);
  не логировать, не коммитить.
- **Минимум изменений наследия; обратимость:** каждый этап оставляет репозиторий
  компилируемым и запускаемым (зелёный гейт = точка отката).
- **Серверная часть — в git VPS:** каждая правка сервера — отдельный коммит
  (текст предлагает агент, выполняет оператор).

## 4. Детальный план по этапам

### Этап 0 — Доступ и привилегии (И1 + И2а) (`migr_plan_0.md`)
- **Цель:** агент управляет VPS по ключу и выполняет ограниченный набор root-операций
  без пароля; публичные порты открыты.
- **Шаги:** (1) алиас `mcp-vps` в `~/.ssh/config` (файл вне репозитория, вставляет
  оператор); (2) `loginctl enable-linger t` (user-дэймон живёт без сессии);
  (3) `/etc/sudoers.d/mcp-ops` — узкий белый список (`loginctl`, `ufw allow
  800/8010/8020/tcp`, `ufw status/show`); (4) `ufw allow` трёх портов;
  (5) **панель провайдера**: открыть 8000/8010/8020 (только веб-консоль — делает
  оператор).
- **Гейт 0→1:** `ssh mcp-vps 'whoami'` без пароля; `sudo -n ufw status verbose`
  проходит без запроса пароля и показывает правила; `loginctl show-user t
  --property=Linger` = `yes`.

### Этап 1 — `time` под управлением без sudo + публичный доступ (И2б) (`migr_plan_1.md`)
- **Цель:** `mcp-time-server` запускается/перезапускается агентом через
  `systemctl --user`, доступен снаружи, `Host`-защита настроена.
- **Шаги:** (1) пользовательский unit `~/.config/systemd/user/mcp-time-server.service`
  (`ExecStart=…/venv/bin/python time_server_http.py`, `Restart=always`);
  (2) `services.list` + `deploy_services.sh` (rsync unit'ов, `daemon-reload`,
  `enable --now` по списку, вывод статуса/портов); (3) в `time_server_http.py`
  `allowed_hosts` ⊇ {`91.188.212.77:8000`, `127.0.0.1:8000`, `localhost:8000`};
  (4) `systemctl --user start`; (5) **предложить коммит** в `/home/t/doc/mcp`.
- **Гейт 1→2:** `systemctl --user is-active mcp-time-server` = active; снаружи
  `curl -X POST http://91.188.212.77:8000/mcp … initialize` → HTTP 200 +
  `Mcp-Session-Id`; `tools/list` содержит `get_time`.

### Этап 2 — Скрипты отладки + живая базовая линия D1 (И4) (`migr_plan_2.md`)
- **Цель:** операторский контур `dev/vps/` и **воспроизведение D1 на живом сервере**.
- **Шаги:** (1) создать `dev/vps/{mcp_vps.sh, README_vps.md, ssh_config.snippet,

  (4) `Kod.py --mcp-probe` против живого `time` → зафиксировать **красный**
  `exit 1` при `degraded` (это и есть D1 вживую); (5) `tools`/`call get_time`.
- **Гейт 2→3:** скрипты работают; живой probe показывает `time` **READY**, но
  `exit 1` (D1 воспроизведён живьём, а не на мёртвых URL); транскрипты в `evidence/`.

  командами (D1 — живой прогон).

### Этап 5 — D1: порог probe + `enabled`-политика (`migr_plan_5.md`)
- **Цель:** `--mcp-probe` = «≥1 READY-сервер и непустой список» → `exit 0`;
  опция `--mcp-probe-server <id>`; в выводе только `enabled`; `scheduler`/`pipeline`
  `enabled=False` по умолчанию + env-переопределение (`SCHEDULER_MCP_ENABLED`/
  `PIPELINE_MCP_ENABLED`), но остаются зарегистрированными.
- **Гейт 5→6 (живой):** против VPS `--mcp-probe-server time` → `exit 0`; без env →
  `exit 0` по одному READY; с env (3 сервера) → `exit 0`; при всех мёртвых → `exit 1`;
  unit-регрессия зелёная.

### Этап 6 — D2: каталог в промте (`migr_plan_6.md`)
- **Цель:** `deliver` не затирает `tools` при `--mcp` (флаг `--no-tools-block` для
  диагностики); `render_tool_protocol(tools)` перечисляет квалифицированные имена +
  обязательные аргументы; assistant-системное сообщение строится от каталога.
- **Гейт 6→7 (живой):** в REPL `--mcp` лог `[Режим] … 'tools'`; в собранном промте
  блок `[tools]` с `mcp.*`; при MCP off — блока нет; unit-регрессия зелёная.

### Этап 7 — D5: таймауты транспорта (`migr_plan_7.md`)
- **Цель:** `asyncio.wait_for` в `initialize`/`list_tools`/`call_tool`; таймаут →
  `MCPConnectionError("таймаут …")`, состояние `FAILED`, процесс жив.
- **Гейт 7→8:** unit-тест таймаута зелёный; **живая** регрессия — реальные VPS-
  серверы отвечают в пределах лимита (ложных `FAILED` нет); без cancel-scope ошибок.

### Этап 8 — D3: мультисерверный длинный флоу (`migr_plan_8.md`)
- **Цель:** исполняемое доказательство «тулы разных серверов, корректный выбор и
  **порядок**, без лишних» — **живой** прогон + детерминированный L4.
- **Шаги:** программируемый многошаговый `MockClient`; `scenario_multiserver_flow`
  (≥2 сервера, ≥4 вызова, порядок == ожидаемому, лишних нет, маршрутизация по
  `provider`, `TaskStage` не изменился, аудит == N записей); описание
  `dev/tests_debug/scenario/scen_multiserver_flow.md`; **живой зеркальный прогон**
  против VPS (time + scheduler/pipeline) → `logs_reports/stages/`; проверка в
  `check_acceptance.sh`.
- **Гейт 8→9 (живой):** живой флоу с разных серверов даёт ожидаемый порядок и ровно
  N вызовов (транскрипт+аудит); детерминированный L4 зелёный; в продукте нет
  захардкоженной последовательности.

### Этап 9 — D4: выбор инструмента (`migr_plan_9.md`)
- **Цель:** `core/tool_routing.py` (`rank_tools`, чистая функция, RU→EN-эвристика) +
  `/mcp route` печатает кандидата с обоснованием, при нуле — «совпадений нет».
- **Гейт 9→10 (живой):** RU-запрос против живого каталога даёт кандидата (не весь
  каталог); unit-тесты ранжирования зелёные.

### Этап 10 — D6: пакет мелких исправлений (`migr_plan_10.md`)
- **Цель:** `/mcp connect <id>` — только целевой; `ToolExecutionResult.text` (полный)
  vs `summary` (усечённый), `run_pipeline` несёт полный текст; терминальные стадии —
  только read-only, с внятной причиной; assistant-сообщение с валидным `tool_calls`
  (+ `tool.tool_call_id`).
- **Гейт 10→11 (живой):** `connect time` → READY только `time`; ответ >500 → полный
  `text` в пайплайне; на `done` read-only разрешён, мутация `denied`; формат
  сообщений каноничен; прежние tool-use-тесты без регрессии.

### Этап 11 — D7: авторизация транспорта (запланировано) (`migr_plan_11.md`)
- **Цель:** `MCPServerConfig.headers`/`token_env` → `HttpMCPTransport` шлёт
  `Authorization`; серверная часть проверяет токен. **Не блокирует** финал, пока
  серверы публичные и без секретов.
- **Гейт 11→12:** unit (заголовок уходит) + живой прогон с токеном (когда включим).

### Этап 12 — Финал: живой прогон, гейт, синхронизация (M7) (`migr_plan_12.md`)
- **Цель:** подтвердить правки вживую, закрыть итоговый гейт, привести документы
  в соответствие.
- **Шаги:** живые прогоны D1/D2/D3/D4/D6 (транскрипты в `logs_reports/stages/`,
  аудит `tool_audit.jsonl`); итоговый гейт L1→L2→L3→L4→`check_acceptance.sh`;
  `README.md`/`arch.md`/`dev/Проверка.md` ← синхронизация; «Итог Ревизии 5» в
  `migr_log.md`; **предложить коммит** (выполняет оператор).
- **Гейт (финальный):** детерминированный контур зелёный; живые прогоны D1–D6
  выполнены с транскриптами; документы соответствуют коду.

## 5. Сквозные требования и запреты

- **Коммиты — только за оператором.** Агент **не** выполняет `git commit`/`push`
  (ни локально, ни на VPS); готовит правки и **предлагает текст** сообщения.
- **Регрессия запрещена:** без `--mcp` = `den_15`; без `--scheduler` worker не
  поднимается; unit/L3/L4/гейт зелёные на каждом этапе.
- **Инструмент ≠ переход:** `TaskStage` не меняется от вызовов MCP; MCP-стадий нет.
- **SDK не протекает в `core`** (grep-проверка на каждом этапе);
  `core/tool_routing.py` — без SDK и без сети.
- **Нет захардкоженной последовательности в агенте:** порядок выбирает модель;
  детерминизм — только в тестах и в явной конфигурации пайплайна CLI.
- **Семантика состояний не меняется** (`overall_state()` как был).
- **Публичные серверы без секретов**; `allowed_hosts` — точный набор `host:port`;
  `allowed_hosts=["*"]` **запрещён**.
- **Секреты/endpoint'ы — только из `.env`**; не логировать, не коммитить.
- **Пароль sudo не попадает** в скрипты/аргументы/историю — только NOPASSWD-белый
  список.
- **Временные файлы — только `dev/tests_debug/.tmp/`**; рабочие `users/` не трогать;
  расшифровки живых прогонов — в `dev/vps/evidence/`.
- **Один этап = один рабочий план = один гейт**; порядок по §3.
- **ОБЯЗАТЕЛЬНО: перечитывать `migr_plan.md` после каждого этапа.**

## 6. Механизм автоматического гейта

### 6.1 Порядок
```text
завершение migr_plan_N.md → авто-прогон гейта этапа N (§4)
   зелёный → ПЕРЕЧИТАТЬ migr_plan.md → migr_plan_(N+1).md, запись в migr_log.md (✅)
   красный → карточка в logs_reports/errors/, этап N открыт
```
### 6.2 Критерии
Компилируемость/запускаемость; нерегрессия; изоляция временных файлов;
перечитывание плана. **Особенность Ревизии 5:** гейт закрыт **только если зелёный
живой прогон** против VPS; детерминированный тест — обязательная регрессия, но сам
по себе гейт не закрывает. Каждый гейт показывает переход **«красное → зелёное»**
по своей цели (команда из базовой линии до и после).
### 6.3 Шаблон записи в `migr_log.md`
```text
## Этап <N> — <название> (цель: И…/D…)
- Статус: ✅ завершён | ⚠️ обход | ❌ открыт
- Было: <состояние + вывод красной проверки>
- Стало: <состояние + вывод той же проверки (зелёный)>
- Живой прогон: <команда против VPS + результат, exit-код>
- Регрессия: <unit/L3/L4/гейт>
- Артефакты: <файлы (локально / VPS)>
- Коммит: <предложенный текст; выполнен оператором — хеш>
- Перечитывание migr_plan.md: ✅ (дата/время)
- Гейт <N>→<N+1>: ✅ | ❌
```

## 7. Определение готовности (DoD) Ревизии 5

**Инфраструктура:**
1. `ssh mcp-vps` без пароля; `systemctl --user` управляет `time`/`scheduler`/
   `pipeline`; `loginctl … Linger=yes`; sudo — только белый список.
2. Все три сервера активны и **доступны снаружи** (`initialize`+`tools/list` на
   8000/8010/8020); `allowed_hosts` настроены; `deploy_services.sh` идемпотентен.
3. `dev/vps/mcp_vps.sh` даёт `status/probe/tools/call/log`; расшифровки в `evidence/`.

**D1:** `--mcp-probe` → `exit 0` при ≥1 READY; `--mcp-probe-server <id>` — строгая
проверка; в выводе только `enabled`; `scheduler`/`pipeline` `enabled=False` по
умолчанию, но зарегистрированы; `overall_state()` не изменён.
**D2:** при `--mcp` в промте блок `[tools]` с `mcp.*`; `render_tool_protocol` —
имена + обязательные аргументы; при MCP off — блока нет.
**D3:** **живой** мультисерверный флоу (порядок, без лишних, аудит) + зелёный
`scenario_multiserver_flow`; описание сценария и проверка в гейте.
**D4:** `core/tool_routing.py` + тесты; `/mcp route` — кандидат с обоснованием,
при нуле — «совпадений нет».
**D5:** `wait_for` в трёх методах; таймаут → `FAILED` за `timeout_seconds`; реальные
серверы не режутся ложно.
**D6:** `connect <id>` — только целевой; `text` полный vs `summary`; пайплайн несёт
полный текст; терминальные стадии объяснимы; `assistant.tool_calls` каноничен.
**D7 (запланировано):** транспорт шлёт `Authorization` (когда включим приватный режим).
**Сквозное:** контур зелёный полностью; MCP off — без регрессии; `README`/`arch`/
`Проверка` соответствуют коду и живым прогонам; все этапы 0–12 в `migr_log.md`.

## 8. Риски и откат

| Риск | Проявление | Смягчение |
|---|---|---|
| Порт открыт, но `421 Misdirected Request` | `Host:` нет в `allowed_hosts` | точный набор `host:port` на каждом сервере (этапы 1, 3) |
| Порт закрыт снаружи при активном сервисе | `ufw`/security group провайдера | этап 0: ufw + панель; проверка `probe` снаружи |
| `systemctl --user` не поднимается по SSH | нет `XDG_RUNTIME_DIR`/дэймона | `enable-linger` (этап 0); скрипты выставляют `XDG_RUNTIME_DIR` |
| Ослабление порога probe маскирует деградацию | `exit 0` при 1 из 3 | `--mcp-probe-server`; печать READY/FAILED |
| Публичный сервер без токена | посторонние вызовы | без секретов в тулах; `allowed_hosts`; D7 для приватного режима |
| Регрессия tool-use при смене формата сообщений | падение `scenario_llm_tool_use` | правка формата с fallback-парсерами; L4 на каждом шаге |
| Таймаут обрывает медленный рабочий сервер | ложные `FAILED` | настраиваемый `timeout_seconds`; текст ошибки с лимитом |
| Загрязнение `users/`/серверного git | испорченные данные/история | `.tmp/` и `evidence/`; серверные правки — отдельными коммитами |
| Секреты/пароль sudo в логах/истории | утечка | NOPASSWD-белый список; `.env`; не логировать значения |

**Откат:** последний зелёный гейт — точка отката; серверная часть — `git revert`
(выполняет оператор). Откат только по явной команде.
