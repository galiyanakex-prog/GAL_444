## Сценарий 1 — Планировщик и фоновые задачи (задание 1)

**Цель демонстрации:** показать, что MCP-инструмент с отложенным/периодическим
выполнением **сохраняет данные в JSON**, **выполняется по расписанию** и **возвращает
агрегированный результат**; агент работает **24/7** и периодически выдаёт **сводку**
(фон обеспечивает внешний worker, а **не LLM** — «у агента нет heartbeat»).

**Формат отчёта по заданию:** **Видео + Код** (видео записывает пользователь).

**Запуск (живой режим; для наглядности — укороченный интервал):**
```bash
cd "$KOD"
$PY Kod.py --mcp --scheduler --scheduler-interval 5
```
> Для чистого воспроизведения на видео можно добавить `--mock` (MockClient, ключ не
> нужен) и `--memory-dir dev/tests_debug/.tmp/video_users`. Без `--mock` нужен
> `API_KEY` в `.env` (живой LLM) — фоновый worker от ключа не зависит.

**Шаги на видео:**
1. Пройти интервью нового пользователя (имя + 3 ответа).
2. Убедиться, что напечатано: `[Планировщик] Фоновый worker запущен (24/7), интервал …`.
3. Подождать несколько интервалов (worker сам пишет наблюдения в JSON).
4. Команда `/mcp jobs` — список задач планировщика (видно `state`, `interval`,
   `runs` растёт от тика к тику).
5. Команда `/mcp summary` — **последняя сохранённая** агрегированная сводка
   (текст с `count/min/max/avg/last`), отдаётся **без нового запроса к модели**.
6. Показать JSON-файлы на диске:
   ```bash
   ls users/<user_id>/integrations/mcp/scheduler/
   cat users/<user_id>/integrations/mcp/scheduler/jobs.json
   cat users/<user_id>/integrations/mcp/scheduler/observations.json
   cat users/<user_id>/integrations/mcp/scheduler/summaries.json
   ```
7. `/exit` — worker корректно останавливается.

**Ожидаемый вывод (фрагмент, транскрипт `m6_scen1_scheduler.txt`):**
```
[Планировщик] Фоновый worker запущен (24/7), интервал 0.2 c. Данные: users/s1/integrations/mcp/scheduler/
...
[Планировщик] Задачи (2):
  job-… [collect] state=scheduled interval=0.2s next=… runs=1
  job-… [summary] state=scheduled interval=0.2s next=… runs=1
[Планировщик] Сводка (окно все):
Наблюдений в окне: 1
Источники: heartbeat
ticks: count=1, min=1, max=1, avg=1.0, last=1
```

**Как это устроено (код):**
- ядро: `integrations/scheduler/{models,store,runner,aggregator}.py` (stdlib, без LLM);
- MCP-сервер: `integrations/mcp/scheduler_server.py` (`schedule_reminder`,
  `schedule_collection`, `record_observation`, `run_due`, `get_summary`,
  `latest_summary`, `list_jobs`);
- CLI: `Kod.py` — флаг `--scheduler`, `setup_scheduler`/`stop_scheduler`,
  команды `/mcp jobs`, `/mcp summary`.

**Чек-лист-итог (задание 1):**
| Пункт | Что проверяем | Как | Статус |
|---|---|---|---|
| 1.1 | MCP-инструмент с отложенным/периодическим выполнением | `scheduler_server.py` (`schedule_reminder`/`schedule_collection`/`run_due`) | ✅ |

| 1.3 | Выполняется по расписанию | `interval_seconds` + `next_run_at`; worker-тик | ✅ |

| 1.5 | Агент работает 24/7, периодически выдаёт сводку | `--scheduler` (внешний worker, не LLM) | ✅ |
