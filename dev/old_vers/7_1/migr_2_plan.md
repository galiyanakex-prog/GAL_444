## 0. Назначение, границы, решения

### 0.1 Что делаем и зачем

Ревизия 7 (RAG-модуль по 4 частям `Задание.txt`) **закрыта по коду**, но проверка
актуальности (`migr_log.md`, Ш1–Ш14) выявила **расхождения между документацией и
фактическим состоянием проекта**. Ревизия 7.1 **не добавляет новых продуктовых фич** —
она **приводит документацию, конфигурацию и журнал в соответствие с реальностью**,
закрывает два «НЕ ПРОВЕРЕНО» живыми прогонами и выполняет две небольшие правки кода,
явно запрошенные оператором.

**Ключевой принцип:** документу не верим — каждое утверждение сверяем командой; правки
вносим **только** по решениям оператора (раздел «5» журнала), ничего «от себя».

## 1. Конвейер документов

```text
migr_2_plan.md  (мастер-план, ЭТОТ файл; единая нумерация этапов 0…9)
      ▼
migr_2_plan_0.md, migr_2_plan_1.md, … migr_2_plan_9.md   (рабочий план ОДНОГО этапа)
      ▼
выполнение этапа → АВТОМАТИЧЕСКИЙ ГЕЙТ (§7)
      │   зелёный  → ПЕРЕЧИТАТЬ migr_2_plan.md → migr_2_plan_(N+1).md
      │   красный  → карточка в logs_reports/errors/, этап НЕ закрыт
      ▼
migr_log.md  (журнал: было → стало → проверка → статус)
      ▼ (этап 9)
README.md + dev/Проверка.md  ← окончательное описание (постоянные источники знаний)
```

### 1.1 Правила

- `migr_2_plan.md` — единственный источник истины по составу и порядку этапов; рабочие
  планы не противоречат ему и не расширяют объём этапа без записи в `migr_log.md`.
- Один рабочий план = один этап = один гейт. **Нумерация строго сквозная `0…9`.**
- **ОБЯЗАТЕЛЬНО: перечитывать `migr_2_plan.md` после каждого этапа, перед следующим.**
- Каждая правка закрывается парой **«падало → проходит»**: рабочий план начинается
  командой, воспроизводящей расхождение (красный), и заканчивается той же командой в зелёном.
- **Коммиты:** агент готовит правки и **предлагает текст**; `git commit` — только оператор.
- **Правки — только по решениям оператора** (§0.2); ничего «от себя» не добавляем.

## 2. Принципы реализации

- **Документу не верим — сверяем командой.** Каждая правка подтверждается `grep`/прогоном;
  числа берутся из фактического вывода, а не из прежних записей.
- **Минимальность.** Правки кода — только две (секция `rewrite`, метрика стабильности);
  остальное — документация/конфиг/журнал.
- **Нулевые обязательные зависимости.** `requirements.txt` не меняется; тесты — stdlib.
- **Детерминизм без Ollama.** Юнит-тесты работают на `HashingEmbedder`; живой Ollama/LLM —
  только интеграционные прогоны (этапы 3–4).
- **Регрессия запрещена.** После каждой правки — `unit_runner.py` / `smoke.py` /
  `scenario.py` / `check_acceptance.sh` зелёные; без `--rag` поведение агента прежнее.
- **Секреты и приватность.** Ключ LLM — только в `.env` (не в трекинге); в индекс не
  попадают `.env`, `.ssh/`, `users/`, `.venv/`, `rag/index/`, `*.db`.
- **Чистка — финальный шаг.** `dev/tests_debug/.tmp/` очищается **после** последнего
  зелёного гейта (этап 9); `rag/index/` не удаляется.
