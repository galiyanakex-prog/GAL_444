# migr_plan_9.md — Этап 9. Фасад агента на хосте (S1)

> Рабочий план **одного этапа** на основе `dev/migr_plan.md` (**Ревизия 8, v1.1**, §4 «Этап 9»).
> Контур: **S (доступ извне)**. Метка цели: **S1**. Зависимости: **этап 3** (реестр + `/model`).
> Порядок: **пошагово с оператором**. **Коммиты — только за оператором** (ШАГ 9.6).

## Цель этапа

Дать агенту возможность принимать запросы по HTTP, **не добавляя ему бизнес-логики**.
Это фундамент части 5: туннель пересылает сетевые соединения, а терминал соединением не является.

## Предусловия (после этапа 3)

- `ModelRegistry` + `/model` + подпись модели работают.
- `Kod.py` — `--oneshot` (этап 4) для вызова агента одним обменом.
- `flask` **не установлен** в `.venv` → установка за оператором (единственная новая зависимость).

## Границы этапа

- `serve.py` слушает **только** `127.0.0.1:8090`; наружу не смотрит никогда.
- **Нет** бизнес-логики: ни памяти, ни лимитов, ни прав доступа, ни истории чата,
  ни выбора модели «в обход» реестра.
- Правило: любую новую логику решаем «или в агент, или на VPS»; третье запрещено.
- **Не** трогаем `TaskStage` (по канону «инструмент ≠ переход»).

### ШАГ 9.2 — `serve.py` (Flask, только `127.0.0.1:8090`)

Единственная обязанность: принять запрос → передать агенту → вернуть ответ.

| Метод и путь | Действие |
|---|---|
| `POST /ask` | `{user, text, provider?, model?, profile?}` → `{answer, model, sources, quotes, verdict, usage}` |
| `GET /models` | провайдеры и модели из `ModelRegistry` (для выпадающих списков шлюза) |
| `POST /model` | переключение модели пользователя (тот же путь, что `/model use`) |
| `POST /interview` | ответы нового пользователя → существующий механизм интервью агента |
| `GET /state?user=…` | модель, RAG, стадия задачи, жив ли сервис |

### ШАГ 9.3 — Очередь на 1 запрос (решение №16)

Второй запрос ждёт, а не падает; во время ожидания клиент получает статус, а не зависание.

### ШАГ 9.4 — Подпись модели в каждом ответе

Обязательное поле `model` в ответе (задел этапа 3, п. 5).

### ШАГ 9.5 — Тесты `test_facade.py` (Flask test client, без сети)

Маршруты отвечают; неизвестный пользователь создаётся по существующему механизму; очередь
держит параллельные запросы; в ответе всегда есть `model`; ошибка агента → понятный
HTTP-статус, не 500 с traceback; фасад не импортирует `rag/` напрямую (через агента).
