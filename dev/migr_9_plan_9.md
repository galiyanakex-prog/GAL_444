Не делаем: не выполняем `git push/merge`; не публикуем наружу; не пишем в

## 5. Шаги

### 9.1. Инвентаризация выдачи — Исполнитель

Действие: найти текущие точки экспорта, документации и поддержки.
Ожидаемый результат: `$LOGS/s9_delivery_inventory.txt`.
Проверка: у каждой точки есть владелец и зона.

### 9.2. Docs Sync Pipeline — Исполнитель

Действие: обновлять только страницы со статусом «stable»; нестабильные — предлагать
diff, не менять; проверять ссылки; фиксировать источник изменения (файл/коммит).
Ожидаемый результат: стабильная страница обновлена, экспериментальная — нет.
Проверка: фикстура с двумя статусами.

### 9.3. Delivery и PR-симуляция — Исполнитель

Действие: сформировать diff и подготовку коммита; выгрузить результат в `exports/`
без права правки проекта; PR-событие: JSON с `base`, `head`, путями; пайплайн
читает `git diff base..head`; запрет push/merge/approve своего PR.
Ожидаемый результат: `$LOGS/s9_pr_event.json`, diff воспроизводим, экспорт полный.
Проверка: повторный прогон даёт тот же diff; попытка push → отказ.

### 9.4. CRM support MCP — Исполнитель

Действие: доменный инструмент чтения/записи поддержки в `users/<id>/support/`;
изоляция по пользователю; без доступа к остальным `users/**`; аудит.
Ожидаемый результат: пользователь A не читает данные B.
Проверка: матрица доступа.

### 9.5. Тесты и журнал — Исполнитель

Действие: тест-файл на каждый критерий этапа; прогнать базовый набор; заполнить
журнал; перечитать мастер-план; коммит
`feat(delivery): add docs sync, exports and local PR simulation`.
