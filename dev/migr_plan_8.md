  `default` / `rag-strict` / `fast`;
- **ось кванта/размера — по уже скачанным GGUF** (скачивать не нужно): `Qwen3-4B-Instruct-2507-Q4_K_M`,
  `Ministral-3-3B-Instruct-2512-Q4_K_M`, `Qwen3-8B-Q4_K_M`, `DeepSeek-R1-0528-Qwen3-8B-Q8_0`,
  `NVIDIA-Nemotron-3-Nano-4B-Q4_K_M`, `Qwen2.5-Coder-14B-Instruct-Q4_K_M`;

  Отсутствие второго тега у боевой модели **фиксируется как ограничение среды** и прямо
  указывается в отчёте — это честный ответ на «если доступно», а не пропуск.

### ШАГ 8.3 — Ресурсы (GPU на хосте нет)

Во время прогона снимаем:
- `ps -o rss=,pcpu= -p <pid>` для процесса LM Studio;
- `free -m` до/после;
- `~/.lmstudio/bin/lms ps` (размер загруженной модели);
- время ответа и токены/с из ответов API.

Раздел GPU в отчёте — явная строка «дискретного GPU нет, inference по CPU, VRAM неприменим».

### ШАГ 8.4 — Отчёт `stages/optimize_before_after.md`

Таблица «конфигурация × (качество, медиана/p95 латентности, токены/с, RSS RAM, доля ошибок)»
+ **вердикт**: какая конфигурация выбрана боевой и почему (обоснование по числам).

### ШАГ 8.5 — Фиксация выбора + тесты

- `models.json` → `current` + `profile` боевой конфигурации;
- `rag/config.json → generation` — тот же выбор;

- Тесты: парсинг `ps`/`free`/`lms ps` на фиксированных образцах; агрегация «до/после»
