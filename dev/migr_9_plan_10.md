## 5. Шаги

### 10.1. Инвентаризация эксплуатации — Исполнитель

Действие: найти CI-конфиги, скрипты тестов, точки логирования, зависимости.
Ожидаемый результат: `$LOGS/s10_ops_inventory.txt`.
Проверка: отсутствующие элементы помечены как «нет», не созданы фиктивно.

### 10.2. CI — Исполнитель

Действие: workflow: проверка зависимостей, security scan, интеграционные тесты с
отказами, матрица совместимости флагов (offline/production); отчёт с датой, commit
hash, окружением; артефакты — в `$ART`.
Ожидаемый результат: зелёный прогон на текущем commit; красный при намеренном
дефекте.
Проверка: парная проверка «дефект → красный, исправление → зелёный».

### 10.3. Property-based, fault injection, recovery — Исполнитель

Действие: добавить генеративные проверки для resolver/policy/ChangeStatus; инъекцию
сбоев записи/MCP; восстановление после падения.
Ожидаемый результат: находки воспроизводимы; ложных падений нет.
Проверка: повтор 10 прогонов, стабильность.

### 10.4. Метрики — Исполнитель

Действие: latency, ошибки MCP, размер промпта, cache hit rate, качество RAG; для
RAG — методика: размер корпуса, baseline, доверительные интервалы, примеры провалов.
Ожидаемый результат: `$ART/metrics_<дата>.json` + краткая выжимка в журнале.
Проверка: числа воспроизводятся на фиксированных данных.

### 10.5. Документация — Исполнитель

Действие: разделить `реализовано / экспериментально / задел`; `check_docs_links.py`
(пути, якоря, внешние ссылки — только наличие, без сети); прогнать по `docs/`.
Ожидаемый результат: отчёт 0 битых ссылок; статус страниц виден.
Проверка: намеренно битая ссылка → красный.

### 10.6. Воспроизводимость — Исполнитель

Действие: lock-файл зависимостей, фиксированная версия Python, контейнеры для
интеграционных тестов (если применимо).
Ожидаемый результат: установка с нуля по инструкции воспроизводит тесты.
Проверка: чистое окружение/контейнер.

### 10.7. `session_log.py` — Исполнитель

Действие: подключить три точки: старт сессии → `start`; каждый вызов инструмента →
`event` (действие + краткий объект); конец → `end`. Формат
`AI_9/dev/sessions_log/<ДД.ММ.ГГГГ>/sessions_log_<ДД.ММ.ГГГГ>-<ЧЧ-ММ>.md`, строка
`- <дата время> — <действие>: <объект>`. Без содержимого, аргументов, секретов,
домашних путей. Файл только дополняется; LLM не правит. Сбой хука виден (запись
ошибки, не проглатывание).
Ожидаемый результат: 7 критериев §18 зелёные.
Проверка: новая сессия; вызов инструмента; секрет-канарейка; повторный запуск;
`stats`.

### 10.8. Журнал и передача — Исполнитель

Действие: заполнить журнал; перечитать мастер-план; коммит
`chore(ops): add CI, metrics, docs checks and session logging`.
