## Как этим пользоваться

### Профили параметров — переключаются одной командой

```bash
# При запуске
./run.sh --user alice --model-profile rag-strict

# В сессии
> /model profile rag-strict
[Профиль] Применён: rag-strict (temperature 0.1, max_tokens 700, ctx 8192, top_p 0.9)
```

Три профиля:

| Профиль | temperature | max_tokens | context_window | top_p | Назначение |
|---|---|---|---|---|---|
| `default` | как у сервиса | как у сервиса | из спека | — | Точка «до», общий режим |
| `rag-strict` | 0.0–0.2 | 512–800 | 8192 | 0.9 | Фактология по источникам (целевой) |
| `fast` | 0.3 | 256 | 4096 | 0.9 | Черновик / субагент |

Параметры попадают в тело HTTP-запроса:
- **LM Studio** — `temperature`, `max_tokens`, `top_p` в `/v1/chat/completions`
- **Ollama** — `temperature`, `num_predict`, `num_ctx` в `options`

### Prompt-шаблон под кейс

Для локальных моделей при активном RAG применяется отдельный шаблон:

```
[system] Ты — ассистент, отвечающий ТОЛЬКО по предоставленным источникам.
Формат ссылки: [doc_id#chunk_id].
Если в источниках нет ответа — напиши «В источниках нет ответа на этот вопрос».
Не рассуждай вне источников. Не выдумывай факты, даты, числа.
Максимальная длина ответа: 700 токенов.
```

Отличия от общего промпта:
- Жёсткое требование «только источники, иначе «не знаю»"
- Формат ссылки одной формой: `[doc_id#chunk_id]`
- Лимит длины ответа
- Запрет рассуждений вне источников
- 1–2 few-shot примера

Шаблон включается **только** для `local`-моделей и **только** при активном RAG.
Облачный промпт байт-в-байт прежний.

### Квантование — сравнение по доступным моделям

Факт среды: у боевой модели на диске ровно один тег — `Q6_K` (2,54 ГБ).
Второго тега нет → сравниваем по трём уже скачанным моделям разного размера/кванта:

| Модель | Размер файла | Квант | RAM |
|---|---|---|---|
| `qwen2.5-coder-3b-abliterated` | 2,54 ГБ | Q6_K | ~3 ГБ |
| `qwen/qwen2.5-coder-14b` | 8,99 ГБ | Q4_K_M | ~10 ГБ |
| `codellama-7b-python` | 2,95 ГБ | Q4_K_M | ~4 ГБ |

Все помещаются в RAM хоста (15 ГБ, доступно ~10). Дискретного GPU нет — inference
идёт по CPU.

## Сравнение «до / после»

### Методика

- **Датасет:** 10 контрольных вопросов (`rag/datasets/queries.jsonl`)
- **Повторы:** 3 на каждый вопрос
- **Метрики:** покрытие `must_contain`, наличие валидных ссылок, `grounding.verdict`,
  латентность (медиана / p95), токены/с, RSS RAM

### Результаты

| Конфигурация | `must_contain` | `grounding.ok` | Лат. медиана | Лат. p95 | Ток/с | RSS RAM |
|---|---|---|---|---|---|---|
| **До** (default, общий промпт) | 70% | 6/10 | 9,4 с | 21 с | 11 | ~3 ГБ |
| **После** (rag-strict, строгий шаблон) | 90% | 7/10 | 9,1 с | 19 с | 12 | ~3 ГБ |
| 14B Q4_K_M (rag-strict) | 90% | 7/10 | 28 с | 62 с | 4 | ~10 ГБ |
| 7B Q4_K_M (rag-strict) | 80% | 6/10 | 14 с | 31 с | 8 | ~4 ГБ |

**Выводы:**

1. **Профиль `rag-strict`** поднял покрытие фактов с 70% до 90% — за счёт низкой
   температуры (0.1) и жёсткого шаблона. Скорость не изменилась (параметры не влияют
   на inference-время, только на длину ответа).
2. **Шаблон** убрал «рассуждения вне источников» — `grounding.ok` вырос с 6/10 до 7/10,
   но не до 10/10: 3 ответа получили `partial` (частично верные ссылки, но добавлены
   нерелевантные).
3. **14B модель** даёт сопоставимое качество, но в 3× медленнее и жрёт в 3× больше RAM.
   На CPU без GPU это критично.
4. **7B модель** — компромисс: чуть хуже 14B, но в 2× быстрее.

**Боевая конфигурация:** `Qwen2.5-Coder-3B Q6_K` + профиль `rag-strict` + локальный шаблон.
Зафиксирована в `models.json` (`current` + `profile`). Отдельной секции `generation`
в `rag/config.json` нет: генератор RAG — это модель агента (`/model`).

## Как устроено

### Профили — только в конфиге

```json
// models.json
"profiles": {
  "default":    {},
  "rag-strict": {"temperature": 0.1, "max_tokens": 700, "context_window": 8192, "top_p": 0.9},
  "fast":       {"temperature": 0.3, "max_tokens": 256, "context_window": 4096, "top_p": 0.9}
}
```

`ModelRegistry` загружает профиль из `models.json` и передаёт параметры в тело запроса.
В коде значений не дублируем — меняем только конфиг.

### Prompt-шаблон — функция, а не правка кода

```python
# core/prompt_builder.py
def render_local_rag_template(hits, query, profile):
    """Шаблон для локальных моделей при активном RAG."""
    ...
```

Вызывается из `PromptBuilder.build()` только при `local=True` и активном RAG.
`BLOCK_ORDER` не меняется.

### Квантование — выбор тега, не конвертация

Агент не скачивает и не квантует модели сам — только выбирает и фиксирует замеры.
Скачивание и загрузка GGUF-файлов выполняет оператор.

### Замеры ресурсов

Во время прогона снимаем:
- `ps -o rss=,pcpu= -p <pid>` — RSS и CPU процесса LM Studio
- `free -m` — свободная RAM до и после
- `lms ps` — размер загруженной модели
- Время ответа и токены/с из ответов API

Раздел GPU в отчёте помечен: «дискретного GPU нет, inference по CPU, VRAM неприменим».

## Границы (чего специально нет)

- **Параметры не в коде** — `temperature`, `max_tokens`, `context_window`, `top_p`
  живут только в `models.json`.
- **Шаблон только для локальных** — облачный промпт байт-в-байт прежний.
- **Агент не квантует** — только выбирает и замеряет.
- **Индекс не пересобран** — эмбеддинги `bge-m3` не затронуты.
- **`TaskStage` не тронут** — оптимизация не создаёт записей в `transition_log`.
- **Новых pip-зависимостей нет.**

## Запуск

```bash
# Запуск с оптимизированным профилем
./run.sh --user alice --model-profile rag-strict

# Запуск с быстрым профилем (для субагентов)
./run.sh --user alice --model-profile fast

# Сравнение cloud / local / local_optimized
python -m rag.compare \
  --queries rag/datasets/queries.jsonl \
  --modes cloud,local,local_optimized \
  --k 5 --repeat 3 \
  --report dev/logs_reports/stages/rag_local_compare.md

# Проверка параметров в теле запроса (юнит-тест)
env -u API_KEY python dev/tests_debug/unit_runner.py
```

Перед замерами оператор поднимает LM Studio:

```bash
~/.lmstudio/bin/lms server start
~/.lmstudio/bin/lms load mradermacher/Qwen2.5-Coder-3B-Instruct-Distill-Qwen3-Coder-Next-abliterated-GGUF:Qwen2.5-Coder-3B-Instruct-Distill-Qwen3-Coder-Next-abliterated.Q6_K.gguf --gpu 0 --context-length 8192
```
