# День 5 — версии моделей

Пятое практическое задание курса AI Advent по сравнению моделей разного уровня мощности через API.

## Задание

Отправить один и тот же запрос к трём моделям разного уровня:

- **Слабая модель** — простая, быстрая, дешёвая;
- **Средняя модель** — баланс возможностей и ресурсов;
- **Сильная модель** — наиболее мощная.

Замерить:

- время ответа;
- количество потреблённых токенов;
- стоимость вызова.

Сравнить:

- качество ответов;
- скорость;
- ресурсоёмкость.

Результат: короткий вывод о различиях между моделями + ссылки на выбранные модели.

**Формат:** код на Python.

## Задание для сравнения

В качестве тестовой задачи используется логическая задача, аналогичная тем, что применялись в предыдущих днях:

```
У фермера есть куры и кролики. Всего 15 голов и 42 ноги.
Сколько кур и сколько кроликов у фермера?
```

Эта задача подходит для сравнения, потому что:

- имеет однозначный правильный ответ;
- требует логических рассуждений;
- не слишком сложная, чтобы слабая модель не справилась совсем;
- не слишком простая, чтобы сильная модель не ответила тривиально.

## Что будет реализовано

- загрузка API-ключа из переменной окружения через `dotenv`;
- подключение к API через `requests`;
- **интерактивный режим** — без флагов запускается цикл ввода;
- выбор моделей через флаги CLI (`--weak`, `--medium`, `--strong`);
- **произвольная модель** — флаг `--model "идентификатор"` для любой модели из каталога;
- **запустить все модели** (`--all`) — слабая + средняя + сильная + сравнение;
- **финальное сравнение** — отдельный API-вызов, где модель оценивает все ответы (LLM-as-a-Judge);
- **замер времени** — точное время ответа каждой модели;
- **замер токенов** — количество потреблённых input и output токенов;
- **расчёт стоимости** — на основе прайса routerai.ru;
- **обработка TPM-лимита** — автоматический retry при HTTP 429 (повтор через 60 секунд);
- настройка температуры генерации (`--temperature`);
- настройка лимита токенов (`--max-tokens`).

## Как работает программа

### Режимы работы

**Интерактивный режим** — запускается без флагов, ожидает ввод пользователя:

```bash
python "005_День 5/Den_5_Kod.py"
```

**Однократный запуск** — с флагами CLI для конкретного запроса:

```bash
python "005_День 5/Den_5_Kod.py" --all "У фермера есть куры и кролики. Всего 15 голов и 42 ноги. Сколько кур и сколько кроликов?"
```

### Выбранные модели

Программа поддерживает три предустановленных уровня, переключаемые через флаги CLI:

**Слабая модель** (`--weak`) — `sao10k/l3-lunaris-8b` (Llama 3 8B, Dense, 8K контекст).
Быстрая и дешёвая, подходит для простых задач.

```bash
python "005_День 5/Den_5_Kod.py" --weak "У фермера есть куры и кролики..."
```

**Средняя модель** (`--medium`) — `openai/gpt-5-nano` (400K контекст).
Баланс скорости и качества, универсальное решение.

```bash
python "005_День 5/Den_5_Kod.py" --medium "У фермера есть куры и кролики..."
```

**Сильная модель** (`--strong`) — `deepseek/deepseek-v4-pro-0813` (MoE, 1M контекст).
Максимальное качество, подходит для сложных задач.

```bash
python "005_День 5/Den_5_Kod.py" --strong "У фермера есть куры и кролики..."
```

**Запустить все модели** (`--all`):

```bash
python "005_День 5/Den_5_Kod.py" --all "У фермера есть куры и кролики. Всего 15 голов и 42 ноги. Сколько кур и сколько кроликов?"
```

При `--all` автоматически запускаются все три модели **плюс финальное сравнение**.

**Произвольная модель** (`--model "идентификатор"`):

```bash
python "005_День 5/Den_5_Kod.py" --model "deepseek/deepseek-v4-pro-0813" "У фермера есть куры и кролики..."
```

### Финальное сравнение (LLM-as-a-Judge)

После получения ответов от всех моделей выполняется отдельный API-вызов: модель (`--strong`) - `deepseek/deepseek-v4-pro-0813` выступает в роли независимого эксперта и оценивает все ответы по критериям:

1. Точность и логическая корректность результата
2. Полнота и обоснованность рассуждений
3. Соотношение качества ответа и ресурсов модели
4. Вывод: какая модель лучше подходит для какого типа задач

```bash
python "005_День 5/Den_5_Kod.py" --all "У фермера есть куры и кролики. Всего 15 голов и 42 ноги. Сколько кур и сколько кроликов?"
```

### Системный промпт

Первым элементом истории создаётся сообщение с ролью `system`:

```python
messages = [
    {
        "role": "system",
        "content": "Ты полезный ассистент. Отвечай на русском языке.",
    }
]
```

### Замер метрик

Программа автоматически собирает три метрики для каждого ответа:

- **Время ответа** — `time.perf_counter()` до и после запроса, точность до миллисекунд;
- **Количество токенов** — из поля `usage` ответа API (`prompt_tokens`, `completion_tokens`);
- **Стоимость** — рассчитывается на основе прайса routerai.ru:
  ```
  стоимость = (input_tokens * price_per_1M_input / 1_000_000) +
              (output_tokens * price_per_1M_output / 1_000_000)
  ```

### Обработка TPM-лимита

При превышении лимита токенов в минуту (HTTP 429) программа автоматически повторяет запрос:

1. Анализирует тело ответа на наличие `rate_limit`, `too_many`, `limit`;
2. Выводит предупреждение и ждёт 60 секунд;
3. Повторяет запрос (до 2 попыток).

Если вторая попытка не удаётся — выбрасывается понятная ошибка.

### Температура генерации

Параметр `temperature` контролирует вариативность ответа (0.0–2.0, по умолчанию 0.7). Задается через флаг `--temperature`:

```bash
python "005_День 5/Den_5_Kod.py" --all --temperature 0.3 "У фермера есть куры и кролики..."
```

Для финального сравнения температура по умолчанию снижена до `0.2` для более стабильной оценки.

### Обработка ошибок

Если переменная `API_KEY` отсутствует, программа завершается с понятным сообщением.

Ошибки API перехватываются в блоке `try/except`:

- `requests.exceptions.HTTPError` — ошибки HTTP (неверный ключ, недоступность сервиса);
- `requests.exceptions.RequestException` — сетевые ошибки (нет соединения, таймаут);
- `KeyError`, `IndexError`, `ValueError` — ошибки разбора ответа.

## Итог пятого дня

Реализован скрипт с сравнением трёх моделей разного уровня мощности (слабая, средняя, сильная), интерактивным режимом и автоматическим финальным сравнением. Программа автоматически замеряет время ответа, количество токенов и рассчитывает стоимость вызова на основе прайса API. LLM-as-a-Judge подход позволяет модели самостоятельно оценить, какая модель дала наилучший результат для конкретного типа задачи. Обработка TPM-лимита обеспечивает стабильную работу при интенсивном использовании API. Эксперимент показывает, что выбор модели — это компромисс между качеством ответа, скоростью и стоимостью: для простых задач достаточно дешёвой слабой модели, а для сложных логических задач сильная модель даёт значительно более качественный и обоснованный результат.
