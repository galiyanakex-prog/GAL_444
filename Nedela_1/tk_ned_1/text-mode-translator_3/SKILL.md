# Purpose
Минимизировать русскоязычное взаимодействие с LLM.

Русский существует только на двух границах конвейера:

- **L1 IN** — русский текст пользователя оборачивается в слой с инструкцией
  «перевести русский текст на machine English»; агент думает и работает только
  с полученным machine English.
- **L2 CORE** — все рассуждения, планы, tool-calls, логи, заметки, черновики —
  на machine English. Русский сюда не заходит, обратный перевод не делается.
- **L3 OUT** — только тексты, требующие реакции пользователя, оборачиваются в
  слой «перевести machine English на понятный русский» и показываются человеку.

Всё, что не требует реакции пользователя, пользователю не переводится и не
показывается.

Бэкенд: внутренний эндпоинт Koda `https://api.kodacode.ru/v1/chat/completions`,
модели `koda-pro` (по умолчанию) и `koda-base`, токен koda-auth. Внешних
провайдеров нет.

# Activation (automatic)
Активировать без явной просьбы:
- при ПЕРВОМ русском сообщении пользователя в сессии;
- держать активной до конца сессии;
- каждое русское сообщение проходит L1 IN, каждый пользовательский вывод — L3 OUT.

Явный `mode=in|out|gate|batch|roundtrip|ask` переключает запрос на
standalone-конвейер скрипта.

# Workflow (один ход пользователя)

Переменные для команд ниже:

```bash
PY=python3
TMT=/home/u/.kodacli/skills/text-mode-translator_3/scripts/tmt.py
```

## L1 IN — RU -> machine English
```bash
$PY $TMT --mode in --text "<русский запрос как есть>"
```
- Текст передаётся без пред-редактирования.
- Короткие односложные ответы («да», «продолжай», «отмена») разрешаются
  встроенной таблицей — 0 запросов к API.
- Повтор того же текста берётся из кэша — 0 запросов к API.
- Дальше агент работает ТОЛЬКО с блоком `[IN]`.

## L2 CORE — только machine English
На machine English ведётся всё внутреннее: рассуждения, план, аргументы
инструментов, содержимое логов/заметок/`.mem`, черновики коммитов, промежуточные
проверки. Никаких вызовов скрипта и никакого русского на этом шаге.

## Gate — что заслуживает пользователя
В L3 OUT отправлять только то, что требует реакции или осведомления человека:
- вопрос, просьба подтвердить, выбор варианта;
- итог задачи / результат, который пользователь проверяет;
- блокирующая ошибка, риск, изменение в системе;
- команда или следующий шаг, который должен выполнить пользователь.

Не отправлять (оставать в EN): «сейчас проверю», ход рассуждений, черновики,
повторы, служебные сводки, эхо tool-output, записи «для себя».

## L3 OUT — machine English -> русский
Одна пользовательская строка за ход:
```bash
$PY $TMT --mode out --text "<EN machine ответ>"
```
Несколько пользовательских строк — ОДНИМ вызовом (предпочтительно):
```bash
printf '%s\n' "<EN строка 1>" "<EN строка 2>" > /tmp/tmt_out.txt
$PY $TMT --mode batch --file /tmp/tmt_out.txt
```
- Показать пользователю ТОЛЬКО содержимое блока `[OUT]`.
- Сырой EN-ответ и собственные русские фразы в ответе запрещены.
  Промежуточные формы — только по явной просьбе.
- Exit 3 = показывать нечего: ответить молча, без русскоязычной вставки.

## Флаги скрипта
- `--model koda-pro|koda-base` (по умолчанию `koda-pro`).
- `--file <путь>` / stdin для многострочного и длинного текста.
- `--raw` — только текст без меток; `--json` — машиночитаемый вывод.
- `--no-cache` — без кэша; `--cache <путь>` — своё место кэша.
- `--max-tokens N` — ограничить вывод (экономия); `--dry-run` — сборка без API.

# Hard rules
- L1 и L3 выполняет только скрипт. Агент не переводит «на глаз».
- L2 CORE никогда не переводится в русский и не показывается пользователю.
- Ни одного пользовательского текста, не прошедшего `[OUT]`.
- Вызовов API за ход: 1 на IN (0 при кэше/таблице) + не более 1 на OUT
  (`batch` вместо серии `out`).
- Не печатать, не логировать, не коммитить токен koda-auth.
- Смысл, структура, идентификаторы, числа, пути и код сохраняются точно.
- При ошибке скрипта (exit 1 или 2) — сообщить строку ошибки из stderr и
  остановиться. Ручной перевод-заглушка запрещён.
