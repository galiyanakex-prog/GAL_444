# День 4 — температура генерации

Четвёртое практическое задание курса AI Advent по исследованию влияния параметра `temperature` на ответы языковой модели через API.

## Задание

Отправить один и тот же запрос к модели с разными значениями температуры и сравнить результаты:

- `temperature = 0.3` — детерминированный ответ;
- `temperature = 0.7` — баланс между точностью и разнообразием;
- `temperature = 1.3` — высокая креативность.

Сравнить ответы по критериям:
- **точность** — насколько корректен и логичен результат;
- **креативность** — насколько оригинальны формулировки и подходы;
- **разнообразие** — насколько различаются ответы между запусками с одинаковой температурой.

Сформулировать выводы: **как с изменением температуры меняется точность, креативность и другие качества ответов, и для каких типов задач лучше подходит каждая настройка температуры**.

## Результат

Скрипт на Python с CLI-флагами и интерактивным режимом, который отправляет один и тот же запрос к модели с разными значениями температуры и выводит сравнение результатов с автоматической оценкой через LLM-as-a-Judge.

## Что будет реализовано

- загрузка API-ключа из переменной окружения через `dotenv`;
- подключение к API через `requests`;
- **интерактивный режим** — без флагов запускается цикл ввода;
- переключение значений температуры через флаги CLI (`--temp-0.3`, `--temp-0.7`, `--temp-1.3`);
- **произвольная температура** — флаг `--temperature VALUE` для любого значения от 0.0 до 2.0;
- отправка одного и того же запроса с разными температурами;
- **финальное сравнение** — отдельный API-вызов, где модель оценивает все ответы по критериям (LLM-as-a-Judge);
- вывод ответов для сравнения;
- **обработка TPM-лимита** — автоматический retry при HTTP 429 (повтор через 60 секунд);
- настройка лимита токенов (`--max-tokens`).

## Как работает программа

### Режимы работы

Программа поддерживает два режима работы:

**Интерактивный режим** — запускается без флагов, ожидает ввод пользователя:

```bash
python "004_День 4/Den_4_Kod.py"
```

**Однократный запуск** — с флагами CLI для конкретного запроса:

```bash
python "004_День 4/Den_4_Kod.py" --temp-0.3 "Как распространяются короткие радиоволны в пространстве?"
```

### Значения температуры

Программа поддерживает три предустановленных значения, переключаемые через флаги CLI:

**Температура 0.3** (`--temp-0.3`) — детерминированный ответ. Модель выбирает токены с высокой вероятностью. Результат предсказуем и одинаков при повторных запусках. Подходит для задач, где важна точность.

```bash
python "004_День 4/Den_4_Kod.py" --temp-0.3 "Как распространяются короткие радиоволны в пространстве?"
```

**Температура 0.7** (`--temp-0.7`) — баланс между точностью и разнообразием. Стандартное значение по умолчанию. Умеренная вариативность при сохранении логичности.

```bash
python "004_День 4/Den_4_Kod.py" --temp-0.7 "Как распространяются короткие радиоволны в пространстве?"
```

**Температура 1.3** (`--temp-1.3`) — высокая креативность. Модель чаще выбирает менее вероятные токены, ответ становится более вариативным и нестандартным. Подходит для творческих задач.

```bash
python "004_День 4/Den_4_Kod.py" --temp-1.3 "Как распространяются короткие радиоволны в пространстве?"
```

**Произвольная температура** (`--temperature VALUE`) — любое значение от 0.0 до 2.0:

```bash
python "004_День 4/Den_4_Kod.py" --temperature 1.5 "Как распространяются короткие радиоволны в пространстве?"
```

**Запустить все значения** (`--all`):

```bash
python "Nedela_1/den_04/Den_4_Kod.py" --all "Как распространяются короткие радиоволны в пространстве?"
```

При `--all` автоматически запускаются все три предустановленных значения **плюс финальное сравнение**.

### Финальное сравнение (LLM-as-a-Judge)

После получения ответов с разными температурами выполняется отдельный API-вызов: модель выступает в роли независимого эксперта и оценивает все решения по критериям:

1. Точность и логическая корректность результата
2. Креативность и оригинальность подхода
3. Разнообразие формулировок
4. Пригодность для данного типа задачи

```bash
python "Nedela_1/den_04/Den_4_Kod.py" --all "Как распространяются короткие радиоволны в пространстве?"
```

### Обработка TPM-лимита

При превышении лимита токенов в минуту (HTTP 429) программа автоматически повторяет запрос:

1. Анализирует тело ответа на наличие `rate_limit`, `too_many`, `limit`;
2. Выводит предупреждение и ждёт 60 секунд;
3. Повторяет запрос (до 2 попыток).

Если вторая попытка не удаётся — выбрасывается понятная ошибка.

### Температура генерации

Параметр `temperature` контролирует вариативность генерации. Стандартный диапазон OpenAI-совместимого API и OpenRouter: **0 ≤ temperature ≤ 2**. Задается через флаги CLI:

- `--temp-0.3` → temperature = 0.3 (детерминированный ответ)
- `--temp-0.7` → temperature = 0.7 (баланс точности и разнообразия)
- `--temp-1.3` → temperature = 1.3 (высокая креативность)
- `--temperature VALUE` → произвольное значение от 0.0 до 2.0

```bash
python "Nedela_1/den_04/Den_4_Kod.py" --all --temperature 1.5 "Как распространяются короткие радиоволны в пространстве?"
```

**Практические рекомендации:**

| Диапазон | Поведение | Лучше подходит для |
|---|---|---|
| **0** | Максимально детерминированные ответы | Код, инструкции, факты |
| **0.2–0.5** | Точные ответы | Расчёты, объяснения |
| **0.7–1.0** | Универсальный режим | Общие диалоги, баланс |
| **1.0–1.5** | Больше вариативности | Творчество, мозговые штурмы |
| **выше 1.5** | Ответы менее стабильны | Эксперименты, креатив |

**Важно:** температура влияет не на каждом шаге одинаково. Если токен-лидер имеет вероятность ~100%, температура не меняет результат. Реальный эффект виден там, где конкуренция между токенами близкая (49% vs 47%).

### Обработка ошибок

Если переменная `API_KEY` отсутствует, программа завершается с понятным сообщением.

Ошибки API перехватываются в блоке `try/except`:

- `requests.exceptions.HTTPError` — ошибки HTTP (неверный ключ, недоступность сервиса);
- `requests.exceptions.RequestException` — сетевые ошибки (нет соединения, таймаут);
- `KeyError`, `IndexError`, `ValueError` — ошибки разбора ответа.
