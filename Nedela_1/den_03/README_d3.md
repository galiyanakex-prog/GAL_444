# День 3 — способы рассуждения

Третье практическое задание курса AI Advent по сравнению различных способов управления рассуждениями языковой модели через API.

## Задание

Взять одну задачу (логическую, алгоритмическую или аналитическую) и решить её через API **четырьмя способами рассуждения**, затем сравнить результаты:

- отправить запрос **без дополнительных инструкций** — прямой ответ;
- добавить в промпт инструкцию: *«решай пошагово»* (chain-of-thought);
- попросить модель **сначала составить промпт** для решения задачи, а затем использовать его;
- создать в промпте **группу экспертов** (например: аналитик, инженер, критик) и получить решение от каждого.

Сравнить:
- отличаются ли ответы между собой;
- какой способ дал наиболее точный и качественный результат.

## Результат

Скрипт на Python с CLI-флагами и интерактивным режимом, который отправляет один и тот же запрос к модели через API четырьмя способами рассуждения, а затем автоматически сравнивает результаты с помощью LLM-as-a-Judge.

## Что будет реализовано

- загрузка API-ключа из переменной окружения через `dotenv`;
- подключение к API через `requests`;
- **интерактивный режим** — без флагов запускается цикл ввода;
- переключение способов рассуждения через флаги CLI (`--direct`, `--step-by-step`, `--generate-prompt`, `--experts`);
- **финальное сравнение** — отдельный API-вызов, где модель оценивает все четыре ответа по критериям (LLM-as-a-Judge); запускается автоматически при `--all` или отдельно через `--compare` (с указанием хотя бы одного способа);
- отправка одной и той же задачи четырьмя способами;
- вывод ответов для сравнения;
- **обработка TPM-лимита** — автоматический retry при HTTP 429 (повтор через 60 секунд);
- настройка температуры генерации (`--temperature`);
- настройка лимита токенов (`--max-tokens`);
- опциональная сверка с эталоном (`--expected-answer`).

## Как работает программа

### Режимы работы

Программа поддерживает два режима работы:

**Интерактивный режим** — запускается без флагов, ожидает ввод пользователя:

```bash
python "den_03/Den_3_Kod.py"
```

**Однократный запуск** — с флагами CLI для конкретного запроса:

```bash
python "den_03/Den_3_Kod.py" --direct "Решите задачу: у фермера есть куры и кролики. Всего 15 голов и 42 ноги. Сколько кур и сколько кроликов?"
```

### Способы рассуждения

Программа поддерживает четыре способа, переключаемые через флаги CLI:

**Прямой ответ** (`--direct`) — модель решает задачу без дополнительных инструкций по рассуждению.

```bash
python "den_03/Den_3_Kod.py" --direct "Решите задачу: у фермера есть куры и кролики. Всего 15 голов и 42 ноги. Сколько кур и сколько кроликов?"
```

**Пошаговое решение** (`--step-by-step`) — в промпт добавляется инструкция «решай пошагово», модель демонстрирует цепочку рассуждений (chain-of-thought).

```bash
python "den_03/Den_3_Kod.py" --step-by-step "Решите задачу: у фермера есть куры и кролики. Всего 15 голов и 42 ноги. Сколько кур и сколько кроликов?"
```

**Генерация промпта** (`--generate-prompt`) — сначала модель сама составляет оптимальный промпт для решения задачи, затем этот промпт используется для получения ответа. Состоит из двух API-вызовов.

```bash
python "den_03/Den_3_Kod.py" --generate-prompt "Решите задачу: у фермера есть куры и кролики. Всего 15 голов и 42 ноги. Сколько кур и сколько кроликов?"
```

**Группа экспертов** (`--experts`) — в системном промпте создаётся группа экспертов (аналитик, инженер, критик), каждый даёт своё решение задачи.

```bash
python "den_03/Den_3_Kod.py" --experts "Решите задачу: у фермера есть куры и кролики. Всего 15 голов и 42 ноги. Сколько кур и сколько кроликов?"
```

**Запустить все способы** (`--all`):

```bash
python "den_03/Den_3_Kod.py" --all "Решите задачу: у фермера есть куры и кролики. Всего 15 голов и 42 ноги. Сколько кур и сколько кроликов?"
```

При `--all` автоматически запускаются все четыре способа **плюс финальное сравнение**.

### Финальное сравнение (LLM-as-a-Judge)

После получения четырёх ответов выполняется отдельный API-вызов: модель выступает в роли независимого эксперта и оценивает все решения по критериям:

1. Точность и логическая корректность результата
2. Полнота и обоснованность рассуждений
3. Чёткость структуры и пошаговость объяснения
4. Способность проверить правильность ответа

Если передан флаг `--expected-answer`, модель также сверяет каждый результат с эталоном.

```bash
python "den_03/Den_3_Kod.py" --all "Решите задачу..." --expected-answer "9 кур, 6 кроликов"
```

### Системный промпт

Первым элементом истории создаётся сообщение с ролью `system`:

```python
messages = [
    {
        "role": "system",
        "content": "Ты полезный ассистент. Отвечай на русском языке.",
    }
]
```

В режиме группы экспертов в системный промпт добавляется описание ролей:

```python
{
    "role": "system",
    "content": (
        "Ты полезный ассистент. Отвечай на русском языке. "
        "Представь группу экспертов: аналитик, инженер, критик. "
        "Каждый эксперт даёт своё решение задачи. "
        "Оформи ответ в виде трёх блоков, каждый с заголовком роли."
    ),
}
```

### Обработка TPM-лимита

При превышении лимита токенов в минуту (HTTP 429) программа автоматически повторяет запрос:

1. Анализирует тело ответа на наличие `rate_limit`, `too_many`, `limit`;
2. Выводит предупреждение и ждёт 60 секунд;
3. Повторяет запрос (до 2 попыток).

Если вторая попытка не удаётся — выбрасывается понятная ошибка.

### Температура генерации

Параметр `temperature` контролирует вариативность ответа (0.0–2.0, по умолчанию 0.7). Задается через флаг `--temperature`:

```bash
python "den_03/Den_3_Kod.py" --all --temperature 0.3 "Решите задачу: ..."
```

Для финального сравнения температура по умолчанию снижена до `0.2` для более стабильной оценки.

### Обработка ошибок

Если переменная `API_KEY` отсутствует, программа завершается с понятным сообщением.

Ошибки API перехватываются в блоке `try/except`:

- `requests.exceptions.HTTPError` — ошибки HTTP (неверный ключ, недоступность сервиса);
- `requests.exceptions.RequestException` — сетевые ошибки (нет соединения, таймаут);
- `KeyError`, `IndexError`, `ValueError` — ошибки разбора ответа.

## Подготовка к запуску

Добавьте `API_KEY` в корневой файл `.env`:

```env
API_KEY=ваш_ключ_от_api
```

## Запуск

Из корня репозитория выполните:

```bash
# Интерактивный режим
python "den_03/Den_3_Kod.py"

# Однократный запуск — прямой ответ
python "den_03/Den_3_Kod.py" --direct "Решите задачу: у фермера есть куры и кролики. Всего 15 голов и 42 ноги."

# Однократный запуск — пошаговое решение
python "den_03/Den_3_Kod.py" --step-by-step "Решите задачу: у фермера есть куры и кролики. Всего 15 голов и 42 ноги."

# Однократный запуск — генерация промпта
python "den_03/Den_3_Kod.py" --generate-prompt "Решите задачу: у фермера есть куры и кролики. Всего 15 голов и 42 ноги."

# Однократный запуск — группа экспертов
python "den_03/Den_3_Kod.py" --experts "Решите задачу: у фермера есть куры и кролики. Всего 15 голов и 42 ноги."

# Запустить все способы + финальное сравнение
# Флаг --all автоматически включает все 4 способа и завершает сравнением
python "den_03/Den_3_Kod.py" --all "Решите задачу: у фермера есть куры и кролики. Всего 15 голов и 42 ноги."

# С эталоном для сверки
python "den_03/Den_3_Kod.py" --all "Решите задачу..." --expected-answer "9 кур, 6 кроликов"

# С настройкой температуры и лимита токенов
python "den_03/Den_3_Kod.py" --all --temperature 0.3 --max-tokens 1024 "Решите задачу: ..."

# Финальное сравнение отдельно
# Требует указания хотя бы одного способа (--direct, --step-by-step и т.д.),
# иначе сравнение выполнится с пустыми ответами
python "den_03/Den_3_Kod.py" --compare --direct --step-by-step "Решите задачу..."
```

## Итог третьего дня

Реализован скрипт с переключением способов рассуждения LLM, интерактивным режимом и автоматическим финальным сравнением. LLM-as-a-Judge подход позволяет модели самостоятельно оценить, какой способ рассуждения дал наиболее точный и убедительный результат. Обработка TPM-лимита обеспечивает стабильную работу при интенсивном использовании API. Сравнение показывает, как разные подходы к управлению рассуждениями модели (прямой ответ, пошаговое решение, генерация промпта, группа экспертов) влияют на точность, полноту и качество результата.
