## 1. Профиль пользователя и его предпочтения (задание п.3)

☐ **1.1** Пройти интервью (стиль / ограничения / контекст = предпочтения):
```
Ваше имя:            → Алексей
стиль ответов:       → краткий, по делу, без воды
ограничения:         → русский язык, не выдумывать факты
контекст задачи:     → учусь делать AI-агентов, неделя 3
```
Ожидание: `[Инициализация] Профиль и дерево users/demo12/ созданы.`

☐ **1.2** Проверить, что профиль существует и читается:
```
/profile
```
Ожидание: `[Профиль] активный: (default)` + словарь с `name`, `style`, `constraints`,
`context`. По этим полям видно, что предпочтения легли в **профиль**, а не только в чат.

## 2. Профиль подмешивается в каждый запрос

☐ **2.1** Задать реальный запрос, например `Объясни, что такое эмбеддинг`.
Ожидание: живой осмысленный ответ; в ответе заметен заданный **стиль** (кратко, по делу,
по-русски) — то есть профиль влияет на генерацию.

☐ **2.2** Убедиться, что профиль добавлялся в промт **каждого** обмена:
```bash
grep "активный профиль\|ответ получен" Den_log.md | tail -4
```
Ожидание: строки вида `[Агент] M1: ответ получен …`, `[Агент] M2: ответ получен …` и
`[Агент] активный профиль: default` — профиль привязан к сессии и повторяется на каждом ходе.

## 3. Несколько профилей-«призм» на одного пользователя

☐ **3.1** Создать второй профиль мини-интервью (он же пример из чата — «Химик»):
```
/profile new chemist
  Имя профиля:                    → Химик
  Домен (область запросов):       → химия
  Триггеры (через запятую):       → химия, реактив, реакция
  Стиль ответов:                  → строго по формулам, кратко
  Ограничения:                    → не выдумывать вещества
  Контекст:                       → пишу посты про химию
```
Ожидание: `[Профиль] Профиль «chemist» создан и активирован.`

☐ **3.2** Создать третий профиль (другая «призма», из чата — «Экономист»):
```
/profile new economist
  Имя профиля:              → Экономист
  Домен:                    → экономика
  Триггеры:                 → экономика, рынок, цена
  Стиль ответов:            → аналитически, с цифрами
  Ограничения:              → оговаривать допущения
  Контекст:                 → пишу про финансы
```

☐ **3.3** Проверить список профилей:
```
/profile list
```
Ожидание: три строки — `default` с пометкой `*` (дефолтный) и активный с `>`; подпись
`(* — default, > — активный)`.

## 4. Ответы для разных профилей (задание: «проверьте ответы для разных профилей»)

☐ **4.1** Один и тот же вопрос под разными профилями:
```
/profile use chemist
Расскажи про воду
/profile use economist
Расскажи про воду
```
Ожидание: два **разных по подаче** ответа на один вопрос — у `chemist` формульный/химический
(под призмой химика), у `economist` аналитический с цифрами. Это ключевое доказательство
персонализации.

☐ **4.2** Посмотреть полный JSON профиля:
```
/profile show chemist
```
Ожидание: `[Профиль chemist]` + JSON с ключами `id, profile_id, name, domain, triggers,
style, constraints, context, skills`.

## 5. Автоматический учёт профиля (роутер — «что ассистент учитывает автоматически»)

☐ **5.1** Сначала сухой разбор (НЕ переключает):
```
/profile route Химия: какой реактив взять
```
Ожидание: `[Роутер] разбор запроса: «…»`, счёты по профилям, `решение → профиль «chemist»`.

☐ **5.2** Включить авто-роутинг и проверить переключение по запросу:
```
/profile auto on
Химия: какой реактив взять
/profile list
```
Ожидание: `[Роутер] Авто-роутинг включён …`; ответ дан под профилем `chemist`; в
`Den_log.md` появились `[Роутер] запрос → профиль chemist (счёт N)` и
`[Агент] активный профиль: chemist`; в `/profile list` пометка `>` стоит у `chemist`.

☐ **5.3** Проверить ничью/неоднозначность:
```
/profile route Реактив закончился
```
Ожидание: `решение → без переключения (ничья или ноль; остаёмся на текущем/дефолтном)`.

## 6. Согласованность с моделью памяти (задание п.3) и учёт стоимости

☐ **6.1** Убедиться, что профиль — отдельный слой, а не часть истории:
```

```
Ожидание: блоки `[profile]`, `[long_term]`, `[working]`, `[short_term]`; в `[profile]` —
активный профиль, в `[short_term]` — только реплики диалога.

☐ **6.2** Проверить, что живой прогон учтён в журналах:
```
/tokens
/cost
/exit
```
Ожидание: `[Токены] Обменов: N …`, `[Стоимость] Оценка сессии (вход): …`;
в `tokens.csv` добавились строки; в `users/demo12/` есть
`profile.json`, `profiles/chemist.json`, `profiles/economist.json`, `long_term_memory.json`,
`tasks/Основная_задача/…`.
