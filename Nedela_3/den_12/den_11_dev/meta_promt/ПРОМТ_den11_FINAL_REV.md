# ПРОМТ_FINAL_REV — универсальный: файл-каталог-резюме проекта (пошагово, блоками)

> **Назначение.** Промт заставляет агента создать ОДИН файл-каталог-резюме, дающий
> исчерпывающее представление обо всём содержимом проекта — независимо от его размера,
> языка и специфики. Рабочий принцип: **прочитал → сразу записал → забыл**. Никакого
> «сначала изучу весь проект, потом напишу». Контекст не переполняется, потому что в
> памяти никогда не живёт больше одного файла.

> **Как пользоваться.** Заполнить **только раздел 1** (одно поле обязательно) и отправить
> агенту целиком. Всё остальное — инструкции, их не редактировать.

## 2. РОЛЬ И ЦЕЛЬ

Ты — составитель инвентарного описания проекта. Твой единственный результат — файл `ИТОГ`.

Ты **не** анализируешь проект ради советов, **не** рефакторишь, **не** запускаешь код,
**не** ставишь зависимости. Ты последовательно и полно **описываешь**: сначала содержимое
одной директории, затем каждой входящей — рекурсивно, и в конце делаешь общий вывод.

Приоритет: **полнота охвата** (ни один файл не пропущен) важнее красоты формулировок.

## 3. КОРНЕВЫЕ ПРАВИЛА (нарушать нельзя)

### 3.1 Про файлы
1. **Создаётся ровно один файл — `ИТОГ`.** Никаких временных, служебных, черновых, отчётных файлов.
2. **Только чтение проекта.** Ни один существующий файл проекта не создаётся, не изменяется, не перемещается, не удаляется. Команды записи — только в `ИТОГ`.
3. **Append-only.** Уже записанные блоки не переписываются и не «улучшаются». Исправление задним числом — только по прямой фразе пользователя.
4. Если `ИТОГ` уже существует и непустой — **не затирай**: определи по нему последний завершённый блок (раздел 9) и продолжай с следующего.

### 3.2 Про охват
5. Описываются **все** файлы и все директории `КОРЕНЬ`, кроме попавших под `ИГНОР`.
6. `ИГНОР` по умолчанию: `.git/`, `.venv/`, `venv/`, `env/`, `node_modules/`, `__pycache__/`, `*.pyc`, `.pytest_cache/`, `build/`, `dist/`, `.mypy_cache/`, `.idea/`, `.vscode/`, `*.log`, `*.swp`, `.DS_Store`. Пропущенные по `ИГНОР` перечисляются **одной строкой** в БЛОКЕ 00 — и больше не упоминаются.
7. Файл **нельзя пропустить**. Неприменимые случаи фиксируются явно, а не опускаются:
   - пустой файл → `пустой (0 байт)`;
   - бинарный/медиа/не читается → `не читается: <тип/расширение>, назначение предполагаемое: <…>`;
   - доступ запрещён → `недоступен: <причина>`;
   - симлинк/дубликат → `ссылка на <цель>` / `дубликат <пути>`.
8. Символические ссылки на директории **не обходятся** повторно (чтобы не зациклиться) — помечаются ссылкой на уже описанный блок.

### 3.3 Про порядок и запись
9. **Строгая последовательность внутри блока (стержень промта):**
   `описал структуру директории → записал → описал файл №1 → записал → описал файл №2 → записал → … → описал поддиректории (рекурсивно, каждая своим блоком)`.
   Запись выполняется **сразу** после описания, а не в конце блока и не в конце работы.
10. **Один шаг = один файл** (или одна структура директории). Читаешь файл → тут же дописываешь его подблок → переходишь к следующему. Ранее описанные файлы **больше не перечитываются**.
11. Порядок обхода: **сначала все файлы текущей директории (по алфавиту), затем поддиректории (по алфавиту), рекурсивно в глубину.** Нумерация блоков сквозная: `01, 02, 03, …`, затем финальный блок.
12. Запрещено: «сначала прочитать всё, потом написать», «написать блок целиком одним действием», «сделать резюме по памяти, не открыв файл».

### 3.4 Про автономность
13. В `РЕЖИМ = автономный` работай без вопросов и подтверждений: создавай, дописывай, переходи к следующему блоку. Остановка — только при блокирующей ошибке или исчерпании контекста (раздел 9.3).
14. Ничего не коммитить. Критические команды не выполнять — они не нужны: задача полностью сводится к чтению и записи одного файла.

## 4. ШАГ 0. ИНВЕНТАРИЗАЦИЯ (только чтение, до первой строки резюме)

1. Получи полное дерево `КОРЕНЬ` (например `find <КОРЕНЬ> -not -path '*/.git/*' | sort` или эквивалентный обход файловыми инструментами).
2. Примени `ИГНОР`. Посчитай: `D` — число директорий (= число блоков описания), `F` — число файлов.
3. Создай `ИТОГ` и запиши в него **БЛОК 00** (шапка + план обхода) — см. раздел 5.
4. После БЛОКА 00 сразу начинай БЛОК 01 по протоколу раздела 6. Не запрашивай одобрение плана.

**Ограничение Шага 0:** дерево используется только для плана обхода и подсчёта. По нему
**не** составляются резюме файлов — каждое резюме пишется только по фактическому чтению файла.

## 5. БЛОК 00 — шапка и план обхода (формат)

````markdown
# КАТАЛОГ-РЕЗЮМЕ ПРОЕКТА «<имя проекта/каталога>»

- Дата составления: <ГГГГ-ММ-ДД>
- Корень описания: `<КОРЕНЬ>`
- Детальность: <нормальная|краткая|максимальная> | Режим: <автономный|шаговый>
- Охват: директорий — <D>, файлов — <F>, блоков описания — <D>, финальный блок — <D+1>
- Исключено по ИГНОР: <перечислить маски/каталоги одной строкой>

## План обхода (карта блоков)

| Блок | Директория | Файлов | Статус |
|---|---|---|---|
| 01 | `<путь>` | <n> | ⬜ |
| 02 | `<путь>` | <n> | ⬜ |
| … | | | |
| <D+1> | **ИТОГОВЫЙ ВЫВОД ПО ПРОЕКТУ** | — | ⬜ |
<!-- ПРОГРЕСС: блок=00/…; записано файлов=0/…; очередь=01,02,… -->
````

Строка `<!-- ПРОГРЕСС: … -->` — служебный маркер в конце **каждого** записанного блока
(раздел 9). Он не виден при чтении markdown и служит точкой восстановления.

## 6. ПРОТОКОЛ БЛОКА (строгая последовательность, повторять для каждой директории)

Для блока с номером `NN` и директорией `P`:

1. **6.1 Структура.** Получи содержимое `P` (только верхний уровень, без рекурсии). Запиши в `ИТОГ` заголовок блока и дерево `P` (файлы + поддиректории, с пометкой `[файл]`/`[каталог]`, размером в строках для текстовых). **Запись → сразу далее.**
2. **6.2 Назначение директории.** 2–5 строк: для чего этот каталог в проекте, какое место занимает (по именам файлов и содержимому, без домыслов — домыслы помечай `предположительно`).
3. **6.3 Файлы — по одному, по алфавиту.** Для каждого файла: прочитать → составить резюме по формату раздела 7 → **дописать подблок в `ИТОГ`** → следующий файл. Мелкие файлы (< 30 строк) допускается объединять в группу до 5 штук, но резюме пишется для каждого отдельно и запись идёт сразу после группы.
4. **6.4 Итог блока.** 2–4 строки: что этот каталог даёт проекту, его ключевые файлы, его связи с другими каталогами (со ссылками `→ БЛОК NN`).
5. **6.5 Маркер прогресса.** Дописать `<!-- ПРОГРЕСС: … -->`. Обновить статус блока в таблице плана (допустимо точечной правкой одной ячейки — это единственное разрешённое изменение уже записанного текста).
6. **6.6 Переход.** Взять первую ещё не описанную поддиректорию `P` → она становится блоком `NN+1` → вернуться в п. 6.1. Если поддиректорий нет — подняться на уровень вверх и взять следующую там. Когда очередь пуста → финальный блок (раздел 8).

**Пустая директория** (или состоящая только из исключённого по `ИГНОР`) — блок минимальный: заголовок, дерево, строка «содержимое вне области описания (<причина>)», маркер прогресса.

## 7. ФОРМАТ ПОДБЛОКА ФАЙЛА (резюме)

Заголовок подблока — полный относительный путь. Поля обязательны; если поле неприменимо —
пиши `—`.

```markdown
### `<путь/к/файлу>`
- Роль: <назначение в одной фразе> | Объём: <N строк, M КБ> | Статус: <рабочий / черновик / заглушка / архив / конфиг / данные / артефакт сборки>
- Назначение: <1–4 строки: зачем файл нужен проекту>
- Содержимое:
  - <код: классы/функции/методы — по одной строке на каждую ключевую сущность>
  - <markdown/текст: перечень заголовков разделов + 1 строка сути каждого>
  - <данные/JSON/CSV: схема, ключевые поля, объём записей>
  - <конфиг: ключевые параметры и их значения>
  - <скрипт/sh/desktop: что запускает, какими аргументами>
- Связи: зависит от <пути/БЛОК NN>; используется в <пути/БЛОК NN>
- Замечания: <TODO, заглушки, дубли, противоречия, устаревшее; если чисто — «нет»>
```

Ограничения объёма (режим `нормальная`): **4–15 строк** на файл, жёсткий потолок 20.
Режим `краткая` — 2–6 строк (поля «Содержимое» сжато, «Замечания» только при наличии проблем).
Режим `максимальная` — до 25 строк, с разбором каждой функции/раздела.

Правила содержания:
- Пиши **что файл делает и зачем**, а не пересказ строк. Цитаты — не длиннее 3 строк, только если без цитаты смысл не передаётся.
- Имена сущностей (классы, функции, разделы, поля) приводи **точно** как в файле — это опора для навигации.
- «Связи» заполняются по фактическим упоминаниям (импорты, пути, имена файлов в тексте). Нет данных — `—`, не додумывать.
- Если файл больше ~400 строк: читай частями, резюме дописывай последовательно в один подблок; не пытайся удержать весь файл в памяти.

## 9. КОНТЕКСТ, ПРОГРЕСС И ВОССТАНОВЛЕНИЕ

### 9.1 Защита контекста (главный механизм)
- В памяти одновременно: **один** читаемый файл + последние 1–2 записанных подблока. Всё остальное — на диске в `ИТОГ`.
- Не перечитывай описанные файлы; при необходимости ссылки бери из `ИТОГ`.
- Не держи «мысленного плана» — план обхода лежит в БЛОКЕ 00 файла.
- Не выводи резюме файлов в чат: содержательный текст идёт **только** в `ИТОГ`. В чат — лишь служебные строки прогресса (раздел 10).

### 9.2 Маркер прогресса
После каждого блока (и при необходимости после каждого файла крупного блока) дописывай:
`<!-- ПРОГРЕСС: блок=NN/D; записано файлов=X/F; очередь=… -->`

### 9.3 Восстановление после разрыва сессии / исчерпания контекста
1. Прочитай **хвост** `ИТОГ` (последние ~80 строк) → найди последний `ПРОГРЕСС`.
2. Прочитай БЛОК 00 (таблицу плана) → определи первый блок со статусом ⬜.
3. Продолжи с него по протоколу раздела 6. Ничего не переписывай, заново не сканируй.
4. В чат — одна строка: `Продолжение: блок NN из D, файлов X/F`.

Если `ИТОГ` обрывается на середине подблока — допиши недостающее в этот подблок и иди дальше.

## 10. ФОРМАТ ОТВЕТА АГЕНТА

- В чате — **только** короткие служебные строки: `БЛОК 03/12 — <путь> — файлов 7 — записано`.
- Никаких пересказов содержимого `ИТОГ` в чате, никаких сводок «что я сделал», вопросов «продолжать?».
- При `РЕЖИМ = шаговый`: один блок за ответ + строка прогресса + следующая строка плана.
- Полное завершение: одна сводка (файлов описано, блоков, путь к `ИТОГ`) + предложение коммита. **Не коммитить** без прямого запроса.

## 11. КРИТЕРИИ ПРИЁМКИ (агент проверяет сам перед финальным ответом)

1. `ИТОГ` существует, непустой, содержит БЛОК 00, все блоки `01…D` и финальный блок `<D+1>`.
2. Число файлов в подблоках = `F` из БЛОКА 00; расхождений нет (проверка: `grep -c '^### ' <ИТОГ>` = `F`).
3. Каждый блок содержит: дерево директории, назначение, резюме всех файлов, итог блока, маркер прогресса.
4. В каждом подблоке файла заполнены поля «Роль», «Назначение», «Содержимое»; «Связи»/«Замечания» — либо значение, либо `—`.
5. Финальный блок содержит все подразделы 8.1–8.7 и ссылки на блоки, а не общие слова.
6. Ни один файл проекта, кроме `ИТОГ`, не создан и не изменён (`git status` — только `ИТОГ`).
7. В `ИТОГ` нет пропусков вида «и далее аналогично», «остальные файлы похожи», «см. код».

Нарушение любого пункта — дописать/исправить в `ИТОГ`, затем сдавать.

## 12. ЗАПРЕТЫ

- Создавать любые файлы, кроме `ИТОГ`; писать временные файлы в `/tmp` для «промежуточного анализа».
- Изменять, перемещать, удалять, переименовывать файлы проекта; менять права.
- Устанавливать зависимости, запускать тесты/сборку/приложение, обращаться в сеть.
- Пропускать файлы «как незначимые» или описывать группу файлов одним общим абзацем.
