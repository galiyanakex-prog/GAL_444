### `Nedela_3/den_11/core/agent.py`
- Роль: stateful-оркестратор агентного цикла | Объём: 232 строки, 12 КБ | Статус: рабочий
- Назначение: владеет идентификацией пользователя, интервью, текущей задачей и сессией; обеспечивает явную маршрутизацию каждой записи в память и полный цикл обработки одного сообщения.
- Содержимое:
  - `PromptContext.__init__(query, memory_blocks, summary, short_term_messages)` — владелец контекста промта (импортируется `prompt_builder.py`)
  - `Agent.__init__(llm, memory, prompts, store, user_id, default_task, log)` — поля `deliver` (default все 4 слоя), `session_id` (`%Y%m%d_%H%M%S`), `message_counter`, `initialized`
  - `Agent.identify(requested_user)` — решение «новый/известный» по `store.profile_repo.exists()`
  - `Agent.interview_questions()` — три вопроса персонализации: style, constraints, context
  - `Agent.initialize_user(user_id, name, answers)` — `store.ensure_user()`, профиль через `memory.remember("profile")`, первая задача через `remember("working")`, ссылка на задачи через `remember("long_term")`
  - `Agent.load_state(user_id)` — чтение `long_term`, выбор первой задачи, `initialized = True`
  - `Agent.build_context(query)` — `memory.build_blocks(deliver)` + окно последних 10 сообщений краткосрочной + `store.read_sessions_resume()`
  - `Agent.respond(user_message)` — цикл: `remember_message("user", …, "M<N>")` → `build_context` → `prompts.build` → `llm.complete` → при `None` возврат без записи → `remember_message("assistant", …, "M<N>a")`
  - `Agent.remember_message(role, content, message_id)` — `MemoryItem(source="user"|"model", scope="session", role=…)` → `layers["short_term"].write()`
  - `Agent.switch_task(new_task, reason)` — отметка перехода в рабочей памяти старой задачи, новая задача в `working` и `long_term` со `source_session`, новый `session_id`
  - `Agent.save_state()` — `working.lifecycle_summary` + `store.write_sessions_resume()`
- Связи: зависит от `memory/base.py`, `memory/manager.py` (БЛОК 13), `core/prompt_builder.py`, `core/llm_client.py` (БЛОК 02); создаётся в `den_11_Kod.py:build_agent()` (БЛОК 01); тестируется `den_11_dev/tests_debug/unit/test_agent.py` (БЛОК 12); spec — `den_11_dev/meta_promt/ПРОМТ_den11_agent.md` (БЛОК 07)
- Замечания: класс `Agent.ROLES` объявлен, но в методах не используется — фактическая роль берётся из аргумента `remember_message()`

  - load_profile(user_id) — SELECT profile_json; None если нет записи или JSON битый (JSONDecodeError/TypeError)

- Роль: фасад файловой иерархии — единственный модуль, знающий пути | Объём: 194 строки, ~7 КБ | Статус: рабочий

## 8.3 Как проект устроен и работает

1. Запуск: `den_11_run.sh` (БЛОК 01) активирует venv и стартует `den_11_Kod.py` (БЛОК 01).
2. DI-сборка: `build_agent()` создаёт `ProfileRepository` и `Store` (БЛОК 14) → `MemoryManager(default_layers)` (БЛОК 13) → `PromptBuilder` и `RouterAIClient`/`MockClient` (БЛОК 02) → `Agent` (БЛОК 02).
3. Идентификация ДО загрузки памяти: флаг --user или ввод; `profile_repo.exists()` решает «известный → load_state()» или «новый → интервью из 3 вопросов → initialize_user() создаёт дерево users/<id>/…» (БЛОК 02 → данные БЛОКИ 15–27).
4. Цикл обмена: `respond()` → сообщение пользователя в short_term (идентификатор M<N>, parent_id) → `build_context()` (блоки build_blocks(deliver) плюс окно 10 сообщений плюс resume) → `PromptBuilder.build()` в каноническом порядке блоков → `llm.complete()` → ответ в short_term (M<N>a) (БЛОК 02 → БЛОК 13 → БЛОК 02).
5. Каждая запись логируется строкой «[Память] слой ← ключи → путь» в `Den_11_log.md`; каждый обмен — в `den_11_tokens.csv` (БЛОК 01).
6. Выход: `save_state()` обновляет lifecycle_summary и sessions_resume.md — resume «с того же места» при следующем запуске (БЛОК 02 → БЛОКИ 18, 25).
7. Проверка: `unit_runner.py` (L2, 31 тест) → `smoke.py` (L3) → `scenario.py` (L4, 5 сценариев) → `check_acceptance.sh` (гейт 9/9) — всё без живого ключа (БЛОКИ 08, 12).
