   `working`, а не отдельным блоком.

### Подшаг 3.1 — Этап/шаг/действие в блоке промта
- Цель: `as_prompt_block()` дополняется строками состояния (§2.7): «Этап: execution
  (шаг 2/3): Собрать информацию», «Ожидаемое действие: …», при paused — «Пауза (вернуться
  к: execution)», при failed — «Ошибка: …». Источник — `task_state.json` через
  `store.read_task_state`; строка «Стадия задачи: {current_state}» сохраняется
  (обратная совместимость).
- Прочитать: `memory/working.py` (весь), `$ARCH` §2.7.
- Изменить/создать: `memory/working.py` — `as_prompt_block()` (+ чтение состояния;
  `read()`/`write()` не меняются — контракт слоя прежний).
- Проверка: `py_compile`; smoke: блок содержит «Этап:» при существующем `task_state.json`
  и не падает при его отсутствии.
- Запись в журнал: 3.1.
- Объём: ~60 строк чтения, ~30 строк правки.
- Кандидат на батч: да (с 2.1 Этапа 2).

### Подшаг 3.2 — Зеркало `current_state`
- Цель: при каждом переходе автомата `working_memory.json.current_state` обновляется

- Прочитать: `memory/working.py` (`write`).
- Изменить/создать: (ожидаемо — ничего; при необходимости минимальная правка).
- Проверка: запись в журнале «решение: зеркало пишется из `Agent._persist_task_state()`».
- Запись в журнал: 3.2.
- Объём: ~40 строк чтения, ~0–5 строк правки.
