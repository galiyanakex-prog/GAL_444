## 2. Шаги этапа (исполняемый алгоритм)

### Шаг 4.1 — Новые команды
1. `/approve` → `agent.approve_plan()` (печать результата; из неподходящих стадий —
   отказ с объяснением).
2. `/goto <этап>` → `agent.attempt_transition(этап)` (демо контроля: допустимый —
   выполняется, недопустимый — отказ с правилом, состояние не меняется); без
   аргумента — подсказка со списком стадий.
3. `/transitions` → `agent.transitions_report()` (карта + журнал + счётчик отказов).
4. **Ожидаемый результат:** 3 новые формы команд работают в REPL.

### Шаг 4.2 — Адаптация унаследованных команд автомата
1. `/plan <цель>`: `new → planning`, печать «план построен, ожидает утверждения
   (/approve)» (не «переход в execution»).
2. `/step`, `/run`: печать по новому флоу (из `planning` — подсказка про `/approve`).
3. `/pause`, `/resume`, `/task retry`: согласованы с M3 (сообщения о стадиях —
   новые имена).
4. `/state`: + разрешённые переходы из текущей стадии + счётчик отказов в
   `transition_log` (расширение снимка).
5. `/help`: + `/approve`, `/goto`, `/transitions`; обновлённые описания.
6. **Ожидаемый результат:** команды согласованы с новым автоматом.

### Шаг 4.3 — REPL-смоук (subprocess, `.tmp/`, `--mock`)
Полный сценарий канона «Проверьте» из задания:
```text
/plan Сделать REST API        → план построен, стадия planning
/goto implementation          → ОТКАЗАНО (нельзя реализацию до утверждённого плана);
                                /state — стадия НЕ изменилась
/approve                      → plan_approved
/goto done                    → ОТКАЗАНО (нельзя финал без валидации)
/run                          → implementation → validation → done
/goto new                     → ОТКАЗАНО (терминальная)
/transitions                  → журнал: 3 отказа + успехи
```
Вторая ветка (пауза): `/plan` → `/approve` → `/step` → `/pause` → `/exit` →
перезапуск процесса → `/resume` → `/run` → done (шаг не повторён).
**Ожидаемый результат:** все шаги дают ожидаемые ответы; exit 0; временные файлы в
`.tmp/m4_<ts>/`.

### Шаг 4.4 — Регрессия наследия
1. Смоук унаследованных команд: `/memory`, `/profile list`, `/deliver`,
   `/invariants`, `/invariant add`, `/check`, `/compare`, `/summary`, `/tokens`,
   `/cost` — работают как в дне 14.
2. L1 → ok; L2/L4 — отклонения только зафиксированные (M1/M3); гейт — без новых
   красных.
**Ожидаемый результат:** наследие не регрессирует.

## 4. Автоматический гейт M4→M5

Гейт считается **зелёным**, если одновременно:
- [ ] REPL-смоук 4.3 проходит полностью (3 отказа с правилами, состояние не
      меняется, `/transitions` показывает журнал);
- [ ] ветка паузы: перезапуск → `/resume` → та же стадия/шаг → `/run` → done;
- [ ] унаследованные команды дней 11–14 работают (смоук 4.4);
- [ ] L1 зелёный; отклонения L2/L4 — только зафиксированные на M1/M3;
- [ ] флаги не менялись (12).

**Зелёный** → запись M4 в `migr_log.md` (✅) → **перечитать `migr_plan.md`** →
создать `migr_plan_5.md`.
**Красный** → карточка ошибки, этап M4 открыт.
