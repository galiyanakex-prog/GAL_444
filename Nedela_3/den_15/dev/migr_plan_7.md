## 2. Шаги этапа (исполняемый алгоритм)

### Шаг 7.1 — Раздел «Инварианты и ограничения состояния» в `README.md`
Описать:
- **модель**: `Invariant` / `ConstraintSet` / `ProposedAction`; инвариант ≠ обычное сообщение;
- **хранение**: `invariants.json` отдельно от диалога (скоуп — по задаче);
- **проверка**: `InvariantChecker.check` — только кодом, до изменения состояния/инструмента;
  «код запрещает, промт рекомендует»;
- **отказ**: называет действие, нарушенный `id`, причину и альтернативу;
- **изменение**: отдельная авторизованная операция `update_invariant(authorized=True)`;
- **CLI-команды**: `/invariants`, `/invariant add|set|on|off`, `/check`.
**Ожидаемый результат:** раздел README соответствует коду.

### Шаг 7.2 — Строки 26–30 в `dev/Проверка.md`
| Пункт | Что проверяем | Как |
|---|---|---|
| 26 | Инварианты хранятся отдельно от диалога | `invariants.json` существует; очистка `session.json` не удаляет набор (`test_invariants.py`) |
| 27 | Ассистент явно учитывает инварианты в рассуждениях | блок `[system: invariants]` в промте (виден в `Den_log.md`/`/deliver`); правило роли |
| 28 | Ассистент отказывается предлагать решения, нарушающие инварианты | `InvariantChecker.check` → нарушения → действие не выполняется, инструмент не вызван |
| 29 | Конфликт запроса и инварианта + объяснение отказа | `scenario_invariant_conflict`: отказ называет `id`, причину и альтернативу |
| 30 | Изменение инварианта требует отдельного подтверждения | `update_invariant(authorized=False)` → `PermissionError`; `/invariant set ... --yes` меняет правило |
**Ожидаемый результат:** `dev/Проверка.md` содержит 30 пунктов (25 прежних + 26–30).

### Шаг 7.3 — Сверка формулировок с кодом
Пройти по README/Проверке и убедиться, что **каждое** утверждение воспроизводимо фактическим
поведением (имена команд, полей, файлов, тексты отказа). Расхождения устранить в пользу кода.
**Ожидаемый результат:** документы описывают фактическое поведение без расхождений.

## 4. Автоматический гейт M7→M8

Гейт **зелёный**, если:
- [ ] `README.md` содержит раздел «Инварианты» и он **соответствует коду**;
- [ ] `dev/Проверка.md` содержит критерии 26–30;
- [ ] критерии 26–30 **воспроизводимы по тексту** (команды/ожидания совпадают с реализацией);
- [ ] нет расхождений между документами и кодом.

**Зелёный** → запись M7 в `migr_log.md` (✅) → **перечитать `migr_plan.md`** → открыть
`migr_plan_8.md`.
**Красный** → карточка ошибки `dev/logs_reports/errors/error_<ts>.md`, этап M7 остаётся открыт.
