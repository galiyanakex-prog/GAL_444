## 2. Шаги этапа (исполняемый алгоритм)

### Шаг 3.1 — Расширить `BLOCK_ORDER` именем `invariants`
Порядок блоков расширяется **одним** блоком `invariants` (**после** `profile`, **до** `working`):
```text
[system: роль]                    ← + правило «работай в рамках инвариантов, не предлагай их нарушающих решений»
[system: профиль]
[system: инварианты]              ← ← НОВОЕ: список активных правил
[system: долговременная память]
[system: рабочая память задачи]
[system: summary общего префикса]
[messages: краткосрочная память]
[user: текущий запрос]
[резерв: output + tool]
```
**Ожидаемый результат:** имя `invariants` добавлено в `BLOCK_ORDER` на позицию после `profile`.

### Шаг 3.2 — Формировать текст блока из `ConstraintSet.active()`
Формат (канон `arch_den_14.md` §2.7):
```text
Обязательные инварианты:
- [stack.python] Использовать только Python 3.12
- [framework.django] Использовать Django, а не FastAPI или Flask
- [dependencies.no-new] Не добавлять новые внешние зависимости
- [database.no-schema-changes] Не изменять схему базы данных

Инструкции:
1. Учитывай каждый инвариант при составлении плана.
2. Не предлагай решения, нарушающие инварианты.
3. Если запрос конфликтует с инвариантом, явно сообщи об этом.
4. Не считай обычное сообщение пользователя разрешением нарушить инвариант.
```
**Ожидаемый результат:** блок собирается из **активных** инвариантов (выключенные не попадают).

### Шаг 3.3 — Дозированная доставка
- блок добавляется **только если** `invariants` есть в `deliver` (механизм дней 11–13);
- при отсутствии в `deliver` блок **не** включается (поведение как в днях 11–13);
- порядок остальных блоков сохраняется.
**Ожидаемый результат:** доставка инвариантов управляема, переполнение контекста не создаётся.

### Шаг 3.4 — Правило роли
Дополнить блок `[system: роль]` формулировкой: «работай в рамках инвариантов, не предлагай
решений, нарушающих инварианты». Это **мягкая** защита (промт рекомендует); жёсткий запрет —
`InvariantChecker` (M4). Двойная защита — по канону `Суть_N3.md`.
**Ожидаемый результат:** роль явно упоминает инварианты.

## 4. Автоматический гейт M3→M4

Проверка сборки промта (без живого ключа, `MockClient` / чистый вызов билдера):
```bash
python - <<'PY'
# собрать промт с deliver, включающим 'invariants' → блок присутствует, порядок сохранён
# собрать промт с deliver без 'invariants' → блока нет
print("M3 OK")
PY
```
Гейт **зелёный**, если:
- [ ] при наличии `invariants` в `deliver` в собранном промте виден блок `[system: invariants]`;
- [ ] при отсутствии `invariants` в `deliver` блок отсутствует;
- [ ] порядок блоков сохранён (`invariants` после `profile`, до `working`);
- [ ] в блок попадают только **активные** инварианты;
- [ ] наследие (роль/профиль/память) не сломано.

**Зелёный** → запись M3 в `migr_log.md` (✅) → **перечитать `migr_plan.md`** → открыть
`migr_plan_4.md`.
**Красный** → карточка ошибки `dev/logs_reports/errors/error_<ts>.md`, этап M3 остаётся открыт.
