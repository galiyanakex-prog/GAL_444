## 2. Шаги этапа (исполняемый алгоритм)

### Шаг 4.1 — Инициализация в `__init__`
```python
# core/agent.py
self.constraints: ConstraintSet
self.checker: InvariantChecker      # инжектится (RuleBasedChecker по умолчанию)
```
**Ожидаемый результат:** агент хранит набор правил и чекер (полиморфизм/инъекция).

### Шаг 4.2 — `load_constraints()`
Загрузка набора задачи через фасад:
- при `load_state(user_id)` — подтянуть набор активной задачи;
- при `switch_task()` — подтянуть набор **этой** задачи (`invariants.json`);
- `--fresh` → не восстанавливать набор.
**Ожидаемый результат:** переключение задачи меняет действующий набор.

### Шаг 4.3 — `check_invariants(action)`
```python
def check_invariants(self, action) -> list[str]:
    return self.checker.check(action, self.constraints)
```
**Ожидаемый результат:** делегирование чекеру, единая точка проверки.

### Шаг 4.4 — `_propose_action(user_message)`
Формирует `ProposedAction` (в бою — из ответа LLM; в тестах — заглушка). Поля: `description`,
`technology`, `adds_dependency`, `changes_database_schema`.
**Ожидаемый результат:** действие представлено структурой `ProposedAction`.

### Шаг 4.5 — `propose_and_check(user_message)`
```python
action = self._propose_action(user_message)
violations = self.check_invariants(action)
if violations:
    self._log(f"[Инварианты] действие запрещено: {action.description}")
    for v in violations:
        self._log(f"[Инварианты] - {v}")
    return self._refusal_message(action, violations)
return self._execute(action)
```
**Ожидаемый результат:** единый рабочий цикл «план → проверка → выполнить/отказать».

### Шаг 4.6 — `_execute(action)` — единственное место вызова инструмента
Вызов инструмента выполняется **только** при `violations == []`. Запрещённое действие
**не вызывает** инструмент и **не меняет** состояние.
**Ожидаемый результат:** инструмент недостижим в обход проверки.

### Шаг 4.7 — `_refusal_message(action, violations)` (канон §2.9)
Отказ обязан объяснять: (1) какое действие хотел выполнить пользователь, (2) какой инвариант
нарушен, (3) почему инвариант обязателен, (4) допустимую альтернативу. Пример:
```text
Я не могу выполнить этот запрос в текущей конфигурации.

Причина: запрос нарушает инвариант framework.django:
проект должен использовать Django, а переход на FastAPI запрещён.

Могу предложить альтернативу:
реализовать нужную функциональность средствами Django.
Если вы хотите изменить это правило, сначала нужно явно обновить
инвариант framework.django.
```
Плохие реакции: молчаливое выполнение и сухое «Нельзя».
**Ожидаемый результат:** отказ называет `id`, причину и альтернативу.

### Шаг 4.8 — Логи и `severity`
- писать строки `[Инварианты] …` в `Den_log.md`;
- `severity="error"` — действие блокируется; `severity="warning"` — действие выполняется,
  в лог пишется ворнинг.
**Ожидаемый результат:** поведение различается по `severity`, аудит в логе.

### Шаг 4.9 — Операции изменения набора
```python
def add_invariant(self, inv: Invariant) -> None            # добавить
def update_invariant(self, id, text, authorized) -> None   # требует подтверждения (PermissionError без него)
def toggle_invariant(self, id, active) -> None             # on|off
```
Изменение инварианта — **отдельная авторизованная операция**; обычная фраза в диалоге —
конфликт/предложение, но не автоматическое изменение.
**Ожидаемый результат:** изменение набора возможно только через явные операции.

### Шаг 4.10 — Проверка до действия
Подтвердить, что `check_invariants` вызывается **перед**: вызовом инструмента, изменением
файлов, установкой пакетов, изменением состояния задачи, применением технического решения,
отправкой результата пользователю.
**Ожидаемый результат:** проверка строго предшествует любому побочному эффекту.

## 4. Автоматический гейт M4→M5

Проверка на заглушке-инструменте (счётчик вызовов), без живого ключа:
```bash
python - <<'PY'
# 1) запрещённое действие (technology="fastapi" при framework.django) → отказ; счётчик инструмента == 0
# 2) отказ содержит id инварианта и альтернативу
# 3) разрешённое действие → _execute вызван; счётчик == 1
# 4) в логе есть строки "[Инварианты] ..."
print("M4 OK")
PY
```
Гейт **зелёный**, если:
- [ ] запрещённое действие **не** вызывает инструмент (счётчик вызовов == 0);
- [ ] отказ содержит `id` инварианта **и** альтернативу;
- [ ] разрешённое действие выполняется (инструмент вызван);
- [ ] логи `[Инварианты] …` присутствуют;
- [ ] `severity="warning"` → выполнение + ворнинг; `severity="error"` → блокировка;
- [ ] память/профили/автомат (наследие) не сломаны.

**Зелёный** → запись M4 в `migr_log.md` (✅) → **перечитать `migr_plan.md`** → открыть
`migr_plan_5.md`.
**Красный** → карточка ошибки `dev/logs_reports/errors/error_<ts>.md`, этап M4 остаётся открыт.
