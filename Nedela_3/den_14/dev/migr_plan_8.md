## 2. Шаги этапа (исполняемый алгоритм)

### Шаг 8.1 — Полный прогон тестового контура (L2 → L3 → L4 → гейт)
```bash
export API_KEY=test-key
python dev/tests_debug/unit_runner.py            # L2
python dev/tests_debug/scenario.py               # L4 (8 сценариев)
python dev/tests_debug/smoke.py                  # L3
bash dev/tests_debug/check_acceptance.sh         # гейт (11/11)
```
**Ожидаемый результат:** все уровни зелёные, без живого ключа; временные файлы — только в `.tmp/`.

### Шаг 8.2 — Проверка критериев приёмки инвариантов (26–30)
Пройти по `dev/Проверка.md` (строки 26–30) и подтвердить каждый пункт (`arch_den_14.md` §4.3):
- [ ] **26** Инварианты хранятся отдельно от диалога — `invariants.json` есть; очистка
      `session.json` не удаляет набор;
- [ ] **27** Явный учёт в рассуждениях — блок `[system: invariants]` в промте;
- [ ] **28** Отказ от нарушающих решений — `InvariantChecker.check` блокирует; инструмент не вызван;
- [ ] **29** Конфликт запроса и инварианта + объяснение — `scenario_invariant_conflict` называет
      `id`, причину, альтернативу;
- [ ] **30** Изменение инварианта требует подтверждения — `PermissionError` без `--yes`;
      `/invariant set ... --yes` меняет правило.
**Ожидаемый результат:** 26–30 зелёные.

### Шаг 8.3 — Подтверждение нерегрессии прежних 25 критериев
Прогнать прежние проверки (память + персонализация + состояние задачи) и убедиться, что все
25 зелёные (`arch_den_14.md` §2.13, §4.3).
**Ожидаемый результат:** регрессии нет.

### Шаг 8.4 — Проверка наличия целевых артефактов (`arch_den_14.md` §4.1)
```bash
ls -1 core/invariants.py README.md run.sh run.desktop
find users -name invariants.json | head
grep -n "Инварианты" README.md
```
Подтвердить: `core/invariants.py`; `users/<id>/tasks/<task>/invariants.json` (создаётся при
работе); `run.sh` исполняемый; `run.desktop` с абсолютным путём; раздел «Инварианты» в `README.md`.
**Ожидаемый результат:** артефакты на месте.

### Шаг 8.5 — Запись итога в `dev/migr_log.md`
Отразить: дерево проекта, «что сделано / что проверено / что спорно»; статус каждого этапа M0–M8.
**Ожидаемый результат:** журнал полон, открытых ошибок нет.

### Шаг 8.6 — Предложение коммита
Сформировать предложение коммита (сообщение + список файлов). **Коммит выполняется только по
явной команде пользователя** — самостоятельно не коммитить.
**Ожидаемый результат:** предложение коммита выдано пользователю.

- [ ] целевые артефакты `arch_den_14.md` §4.1 созданы (вкл. `core/invariants.py`,

- [ ] гейт: `unit_runner.py` → `scenario.py` (8) → `check_acceptance.sh` (11/11) — всё без
      живого ключа;
- [ ] все этапы M0–M8 отражены в `migr_log.md` со статусом ✅; открытых ошибок нет;
- [ ] рабочие планы `migr_plan_0.md … migr_plan_8.md` созданы и исполнены;
