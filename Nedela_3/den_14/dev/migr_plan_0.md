## 2. Шаги этапа (исполняемый алгоритм)

### Шаг 0.1 — Активировать окружение и зафиксировать точку старта
1. Перейти в каталог проекта и активировать `.venv`:
   ```bash
   cd Nedela_3/den_14
   source ../.venv/bin/activate
   ```
2. Зафиксировать версию Python и `git status` (что изменено до старта).
3. **Ожидаемый результат:** окружение активно, исходное состояние зафиксировано в журнале.

### Шаг 0.2 — Сверить фактическое дерево модулей с `arch_den_14.md` §2.1
1. Вывести фактическую структуру:
   ```bash
   find core memory storage -maxdepth 1 -type f | sort
   ls -1 Kod.py run.sh run.desktop README.md
   ```
2. Сопоставить построчно с деревом из `arch_den_14.md` §2.1.
3. Составить таблицу: **есть / нет / отличается**. Ожидаемо **нет**: `core/invariants.py`,
   `invariants.json` в иерархии `users/`, блок `invariants` в промт-билдере, CLI-команды
   инвариантов, `unit/test_invariants.py`, `scenario_invariant_conflict`, раздел «Инварианты»
   в `README.md`, строки 26–30 в `dev/Проверка.md`.
4. **Ожидаемый результат:** таблица расхождений «текущее → целевое» заполнена.

### Шаг 0.3 — Зафиксировать точки внедрения (не менять)
Перечислить и **пометить как неизменяемые контракты дней 11–13** (по `arch_den_14.md` §2.13):
- `core/llm_client.py` (`LLMClient` / `RouterAIClient` / `MockClient`),
- `memory/*` (`MemoryLayer`, `MemoryManager`, 4 слоя памяти),
- `storage/db.py` (`ProfileRepository`),
- `core/state_machine.py` (`TaskStage` / `TaskState` / переходы / pause/resume),
- `core/profile_router.py` (`ProfileRouter`).
**Ожидаемый результат:** список точек внедрения зафиксирован (в M1–M7 править их контракты
запрещено).

### Шаг 0.4 — Регрессионный baseline (без живого ключа)
Прогнать существующий контур на `MockClient` / `API_KEY=test-key`:
```bash
export API_KEY=test-key
python dev/tests_debug/unit_runner.py            # L2 — юнит-тесты
python dev/tests_debug/smoke.py                  # L3 — смоук (in-process + CLI)
python dev/tests_debug/scenario.py               # L4 — сценарии
bash dev/tests_debug/check_acceptance.sh         # гейт приёмки (11 проверок)
```
> Точные имена/параметры запуска уточнить по содержимому `dev/tests_debug/*` (не менять их).
1. Зафиксировать результаты: число тестов, число сценариев, гейт `N из 11`, exit-коды.
2. **Ожидаемый результат:** baseline зелёный — «25 прежних критериев зелёные».

### Шаг 0.5 — Проверить работоспособность запуска
```bash
bash run.sh --help        # или иной безопасный неинтерактивный вызов
```
Проверить, что `run.sh` исполняемый (`-x`) и корректно активирует окружение.
**Ожидаемый результат:** скрипт запускается без ошибок импорта.

### Шаг 0.6 — Составить перечень расхождений для M1–M7
Оформить список «что отсутствует → каким этапом закрывается» (трассировка по `migr_plan.md` §9):
- `core/invariants.py` → **M1**;
- `storage/store.py` (invariants_path/read/write) → **M2**;
- блок `invariants` в `prompt_builder.py` → **M3**;
- проверка/отказ в `agent.py` → **M4**;
- CLI-команды в `Kod.py` → **M5**;
- `test_invariants.py`, `scenario_invariant_conflict` → **M6**;
- `README.md` + `dev/Проверка.md` (26–30) → **M7**;
- финальный прогон + приёмка → **M8**.

## 4. Автоматический гейт M0→M1

Гейт считается **зелёным**, если одновременно:
- [ ] baseline зелёный (L2/L3/L4/гейт пройдены без живого ключа);
- [ ] расхождения с `arch_den_14.md` §2.1 перечислены;
- [ ] точки внедрения (неизменяемые контракты) зафиксированы;
- [ ] регрессия до изменений подтверждена;
- [ ] `run.sh` работает; окружение активируется.

**Зелёный** → запись M0 в `migr_log.md` (✅) → **перечитать `migr_plan.md`** → открыть
`migr_plan_1.md`.
**Красный** → карточка ошибки `dev/logs_reports/errors/error_<ts>.md`, этап M0 остаётся открыт.
