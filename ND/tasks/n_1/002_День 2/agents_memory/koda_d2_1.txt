  День 2. Задание 2 — Формат ответа 🔥

  Руководитель проекта: Алексей Гладков (нужно следовать его указаниям).

  Задача: Отправить один и тот же запрос к LLM в разных режимах контроля ответа и сравнить
  результаты.

  Что нужно реализовать:

   1. Явное описание формата ответа — модель должна возвращать ответ в строгом формате (например,
      JSON, Markdown, YAML). Идеальный вариант — JSON, где структура одинакова независимо от
      количества запросов.

   2. Ограничение на длину ответа — задать максимальный объём ответа.

   3. Условие завершения ответа — использовать stop sequence или явную инструкцию в промпте, чтобы
      модель знала, когда закончить.

  Сравнить два режима:
   - 👉 Ответ без ограничений — свободная форма.
   - 👉 Ответ с ограничениями — детерминированный формат.

  Результат (код): Один и тот же запрос с разным уровнем контроля ответа через API.

  ---

  Дополнительные требования из чата проекта:

   - Переключалки режимов — нужно сделать переключение между режимами (без ограничений / с
     ограничениями), например через флаги CLI (--answer-length, --json-format и т.п.).
   - Детерминированный формат — в идеале получать одинаковый JSON-структуру ответа независимо от
     количества запросов. Значения могут отличаться (это нейросеть), но формат должен быть
     фиксированным.

    Пример: если модель выдаёт рецепты, она должна всегда возвращать массив с полями имя, вес,
  порядок в блюде.

   - Через параметры API или промпт — можно задавать через response_format (Structured Output) в
     самом запросе API, либо через инструкции в промпте. Оба варианта допустимы.

   - Обработка некорректных ответов — если модель вернула ответ не в том формате, можно добавить
     валидацию кодом (проверка по JSON Schema) и вернуть ошибку.

   - Один запрос — одинаковый формат, но не обязательно одинаковый контент — например, на вопрос
     «Титаник» структура ответа (название, жанр, актёры, описание) всегда одинаковая, но само
     описание может немного отличаться от запроса к запросу.

   - Обработка вопросов вне тематики — в системном промпте можно задать ограничение темы. Если вопрос
      не по теме — отфутболить стандартной фразой.

  ---

  Проще говоря: Написать скрипт на Python с CLI-флагами, который отправляет один и тот же запрос к
  LLM в двух режимах — свободном и с жёстким контролем формата (JSON + длина + stop sequence).
  Сравнить результаты. Цель — показать, как настройки API влияют на предсказуемость и
  структурированность ответа модели.

❯ Описание образца (day-02-response-control)

  Это интерактивная CLI-программа на Python, которая отправляет один и тот же запрос к модели
  openai/gpt-oss-20b через Groq API (клиент groq.Groq) дважды — без ограничений и с ограничениями —
   и выводит оба ответа для сравнения.

  Ключевые особенности:

   - Библиотека: groq (официальный клиент Groq), а не requests напрямую
   - Модель: openai/gpt-oss-20b через Groq
   - Интерактивность: бесконечный цикл while True с вводом пользователя (input()), команда выход для
     завершения
   - Два вызова на каждый ввод: with_limits=False и with_limits=True
   - Контроль формата: через текстовые инструкции в системном промпте (CONTROL_INSTRUCTIONS) —
     «Краткий ответ:», ровно 3 пункта, не более 70 слов, завершить после третьего пункта
   - Ограничение длины: смысловое (70 слов в промпте) + техническое (max_completion_tokens=500)
   - Условие завершения: явная инструкция в промпте (не stop sequence)
   - Температура: temperature=0.8
   - Обработка ошибок: общий except Exception — без разделения по типам
