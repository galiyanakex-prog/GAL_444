  ⚠ Проблемы безопасности:

  1. Нет ограничения длины истории диалога
  История messages растёт бесконечно. Это может привести к:
   - Переполнению контекста модели
   - Резкому росту расходов по API
   - Возможности DoS через бесконечный диалог

  2. Нет rate limiting
  Пользователь может бесконечно слать запросы без пауз. Нет защиты от случайного или намеренного
  расходования лимитов API.

  3. Нет валидации ввода пользователя
  Ввод напрямую передаётся в API. Хотя это не критично для безопасности (ключ в .env), это
  открывает возможность для prompt injection.

  4. Несоответствие README и кода
  В README описаны вещи, которых нет в коде:
   - Упоминается GROQ_API_KEY, а в коде API_KEY
   - Описан системный промпт про «продавца Алекса/Боба», а в коде — «полезный ассистент»
   - Упоминается client.chat.completions.create() (OpenAI SDK), а в коде requests.post()
   - Упоминаются параметры temperature и reasoning_effort, которых нет в запросе

  Это не проблема безопасности, но вводит в заблуждение.
