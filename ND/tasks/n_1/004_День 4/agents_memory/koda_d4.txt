❯ День 4 — Температура генерации

  📄 Задание_Д4.txt

  Это техническое задание на четвёртое практическое задание курса. Основные элементы:

  Цель: Исследовать, как параметр temperature влияет на ответы LLM — на точность, креативность и
  разнообразие.

  Основное задание: Отправить один и тот же запрос с тремя значениями температуры:
   - 0.3 — детерминированный ответ, предсказуемый и одинаковый
   - 0.7 — баланс между точностью и разнообразием
   - 1.3 — высокая креативность, вариативные ответы

  Что сравнивать: точность, креативность, разнообразие ответов.

  Ключевые дополнительные моменты из чата проекта:
   - Можно использовать LM как судью (LLM-as-a-Judge) для оценки
   - Температуру можно экспериментировать шире — до 2.0
   - Потолок температуры зависит от модели: DeepSeek ~1.5–2.0, Anthropic 0–1.0, Mistral ~1.5
   - Температура влияет не на каждом шаге — реальный эффект виден только при конкуренции токенов
   - Режим reasoning автоматически фиксирует низкую температуру
   - Можно реализовать двухступенчатый автоподбор температуры

      Подчёркивается, что низкой температуры недостаточно — результат всегда нужно проверять

  ---

  main.py — образец

  Общее описание: Скрипт на Python, который выполняет эксперимент с тремя значениями температуры и
  формирует сравнительный вывод через LLM-as-a-Judge.

  Архитектура (4 функции + main):

   1. `get_response(user_prompt, temperature)` — отправляет запрос к Groq API с retry-логикой при
      превышении лимита (статусы 413/429, повтор через 60 секунд, максимум 2 попытки). Возвращает
      текст ответа.

   2. `print_section(title, content)` — вспомогательная функция для красивого вывода разделов с
      разделителями =.

   3. `build_comparison_prompt(responses)` — формирует промпт для модели-оценщика. Объединяет три
      ответа с подписями температур, задаёт критерии оценки (точность, креативность, разнообразие),
      просит вывести таблицу и выводы.

   4. `main()` — главная функция:
      - Выводит исходный запрос
      - Циклом по TEMPERATURES = (0.0, 0.7, 1.2) отправляет три запроса, сохраняет ответы в словарь,
        выводит каждый в отдельном разделе
      - Запускает четвёртый запрос (temperature=0) для сравнения через build_comparison_prompt
      - Выводит итоговое сравнение

  Особенности:
   - Использует официальный клиент groq (не requests)
   - Системный промпт с ролевой игрой (бот "Бублик", пользователь "Чебуратор")
   - MAX_COMPLETION_TOKENS = 1200
   - Обработка ошибок через try/except в main() с выводом понятного сообщения
   - Все строки закомментированы — каждая строка имеет поясняющий комментарий
