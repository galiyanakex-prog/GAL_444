❯ Суть задания (День 3)

  Цель: Взять одну задачу (логическую, алгоритмическую или аналитическую) и решить её через API
  четырьмя разными способами рассуждения, затем сравнить результаты.

  Четыре способа:

   1. Прямой ответ — отправляешь промпт с задачей без каких-либо дополнительных инструкций по
      рассуждению.

   2. Пошаговое решение — в промпт добавляешь инструкцию: «решай пошагово» (chain-of-thought).

   3. Генерация промпта — сначала просишь модель саму составить оптимальный промпт для решения задачи,
       а затем используешь этот сгенерированный промпт для получения ответа.

   4. Группа экспертов — в системном промпте создаёшь роль группы экспертов (например: аналитик,
      инженер, критик) и получаешь решение от каждого эксперта отдельно.

  Что сравнить:
   - Отличаются ли ответы между собой?
   - Какой способ дал наиболее точный и качественный результат?

  Формат результата:
  Код на Python (через API), где реализованы все 4 варианта + вывод сравнения.

  ---

  Дополнительные моменты из чата:
   - Рекомендуется влиять на результат через системный промпт (например, указывать актуальную дату).
   - Модель не имеет автоматического доступа к интернету — для этого нужен инструмент web_search
     через Responses API.
   - К задаче нет жёстких требований — можно захардкодить одну задачу или предложить несколько на
     выбор.

  Общая структура

  Образец — это статичный скрипт без CLI и интерактивного режима. Он запускается один раз, последовательно
  выполняет 6 API-вызовов и завершается.

  Ключевые особенности:

   1. Библиотека: Использует groq (официальный Python-клиент), а не requests.
   2. Модель: openai/gpt-oss-20b через Groq API.
   3. Задача: Классическая задача о переходе моста (1, 2, 7, 10 минут), правильный ответ — 17 минут.
   4. Параметры: temperature=0.2, reasoning_effort="low", max_completion_tokens=2048.
   5. Системный промпт: Фиксированный — «Бортовой помощник Бублик для космического путешественника
      Чебуратора».
   6. Обработка TPM-лимита: При ошибке 413/429 ждёт 60 секунд и повторяет запрос.

  1. Финальный блок сравнения
  Проблема: В образце задача захардкожена и известен эталон (17 минут). В Den_3_Kod.py задачу вводит
  пользователь, поэтому универсального правильного ответа нет.

  Решение: Использовать подход LLM-as-a-Judge с опциональной сверкой по эталону.
   - Добавляем флаг --expected-answer (необязательный). Если пользователь знает правильный ответ, он
     передаёт его.
   - Оценщик получает все 4 ответа + критерии + (опционально) эталон.
   - Промпт оценщика:

   1 Сравни четыре решения одной задачи. Оцени каждый способ по критериям:
   2 1. Точность и логическая корректность
   3 2. Полнота рассуждений
   4 3. Чёткость структуры и пошаговость
   5 [Опционально: Эталонный ответ: {expected_answer}. Сверь результаты.]
   6 Укажи, какой способ дал наиболее точный и убедительный результат, и кратко объясни почему.
  Это добавит 1 API-вызов в конец цепочки. Запускать его можно автоматически при --all или по флагу
  --compare.

  2. Обработка TPM-лимита
  RouterAI (как и большинство провайдеров) возвращает HTTP 429 при превышении лимита токенов в минуту.

  Решение: Добавить retry-логику внутрь send_request:
   - Цикл for attempt in range(2):
   - При response.status_code == 429 проверяем тело ответа на rate_limit_exceeded или too_many_requests
   - Ждём 60 секунд (time.sleep(60)) и повторяем запрос
   - Если вторая попытка тоже падает — выбрасываем ошибку

  Схема интеграции:

    2
    3 def send_request(messages, max_tokens=500, temperature=0.7):
    4     for attempt in range(2):
    5         try:
    6             response = requests.post(URL, headers=HEADERS, json=data, timeout=60)
    7             if response.status_code == 429:
    8                 body = response.json()
    9                 if "rate_limit" in str(body).lower():
   10                     if attempt == 1:
   11                         raise RuntimeError("Превышен лимит API после повторной попытки")
   12                     print("  ⏳ Превышен минутный лимит. Повтор через 60 сек..." )
   13                     time.sleep(60)
   14                     continue
   15             response.raise_for_status()
   16             # ... парсинг ответа ...
   17         except requests.exceptions.RequestException as e:
   18             # ... обработка ...

   4. main() → вызов сравнения после 4 способов, вывод итогового вердикта
